# 开发约定

> 本页由 `AGENTS.md` §10 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

- **统一响应格式** `{"code","msg","data"}`，`code === 0` 为成功，错误时 `code` 取 `ERROR_CODE`（默认 -1）。
- **错误处理**：上游非 2xx 抛 `base.UpstreamError`（透传状态码，Message 附响应体前 256 字节摘要）；`app.handleError` 统一映射（超时→504；读/解析失败等 `StatusCode=0`→502；不安全 base_url 与参数缺失→400；DNS/连接拒绝→502）。**对下游的错误文案必须脱敏**：网络错误的 `err.Error()` 可能含完整签名 URL，详细信息只进服务端日志。
  **对下游的出口有两条**，两条都要过 `sanitizeUpstreamMsg`：handler 返回 error 走 `handleError`；
  handler 不报错但正文是错误形态（`ContentType=="error"` 的带内错误，Legado 书源的传统写法）走响应写回处，
  由 `app.scrubInBandMsg` 收口（待办清单 P23①）——它原来只挂在 `handleError` 上，带内那条把整条约定绕过了。
  只扫错误文案的 `message`，**正文一律不动**（合法正文里本来就可能含 URL）。
  落地上收口在 `handleError`：① 所有出口文案过 `sanitizeUpstreamMsg`（含 `://` 一律换「上游请求失败，请稍后重试」）；② `*url.Error`/`net.Error` 判为传输层失败（`isTransportError`）走 502，不再落进「400 + 原文」的参数错误兜底——DNS 分支在前，保留「上游地址不可达/连接被拒绝」这类更具体的友好文案；③ 不含 URL 的本地错误（如参数缺失提示）原样给下游，排障要看得到。回归用例 `test/upstream_error_mask_test.go`。
- **上游字段兼容**：解析上游响应禁止写死单一字段名，必须多字段兼容读取（`utils.FirstNonEmpty` / `utils.ToString`，数值 ID 一律用 `utils.ToString` 避免科学计数法），拼进 URL 的 ID 必须 `url.QueryEscape`。
- 日志与界面文案用中文，代码标识符用英文。
- **手写 SQL 的别名/列名必须避开 MySQL 8.0 保留字**（`EMPTY`/`RANK`/`GROUPS` 这类，SQLite 容忍而 MySQL 报 1064；
  测试全在 SQLite 上跑，这类错误不会有用例信号，只有生产暴露）。聚合别名统一加 `_count`/`_sum` 后缀：
  `AS empty_count`、`AS latency_sum`、`AS max_latency`（`handlers/admin/monitor_subjects.go` 即此教训）。
  **这条已固化为机器拦截**：`make vet` 跑 `scripts/check-sql-reserved.sh`——别名表是在本地 MySQL 8.0.43 上
  逐词实测（`SELECT 1 AS w` 与 `FROM (SELECT 1 a) w` 两个位置）得到的 241 个词，不是抄文档，
  所以 `TEXT`/`DATE`/`MAX` 实测可用、不在表内。它扫三样：`AS x`、子查询的 `) x`、以及反引号标识符；
  明知故犯的对照组（如 `test/dialect_quoting_test.go`）在行尾标 `dialect-allow` 放行。
  已知盲区：跨行拆开写的 SQL，续行没有关键字就不在扫描范围内。
- **不要在 SQL 里写死反引号**：反引号是 MySQL/SQLite 方言，PostgreSQL 只认双引号；而设置读取的出错路径是
  「报错被吞、返回空串」，所以 `DB_TYPE=postgres` 的部署会**所有系统设置都读成空**且毫无症状
  （待办清单 P1）。条件一律用 map 形式（`Where(map[string]interface{}{"key": k})`）让 GORM 按 dialector 加引号；
  `ORDER BY 保留字` 两种引号都做不到跨方言，改成取回后在内存里排。守卫用例 `test/dialect_quoting_test.go`：
  一份全库反引号扫描 + 一份 postgres 方言 DryRun 的直接证据（不连库也能跑）。
- **审计类写入不许吞错**：`redemption_logs` 这种「只为留档而写」的表，插入失败必须打一行服务端日志
  （改了结果就错了、吞了就更没人知道）。列宽按**用户输入原文的最坏形态**定，不按我们自己生成的形态定：
  卡码明文 20 位以内，但用户可能粘贴 64 位历史哈希，`code` 就得是 64。
  生产是 MySQL（`STRICT_TRANS_TABLES`），超长不是截断而是整条 insert 报错——而 SQLite 根本不检查列宽，
  所以这类问题同样不会有用例信号（上面「保留字」那条的同一盲区），改完要在真 MySQL 上过一遍。
- **下发位置是部署事实，不做设置项**：书源 JSON 由静态托管在 `data/shuyuan/bookSource.json`，
  对外就是 `GET /data/shuyuan/bookSource.json`（免鉴权、原样直出，阅读 App 才能自己拉）。
  `GET /user/import-config` 只回 `{book_source_path, ready}`，**绝对地址由前端用 `window.location.origin` 拼**——
  浏览器地址栏才是用户真实到达的域，服务端拿 `X-Forwarded-Host` 拼链接等于让伪造的请求头决定用户去哪。
  `ready` 的判据是 `json.Valid` 而不是「文件存在」：半截文件会让 App 导入失败而面板一切正常，宁可不给按钮。
  换书源＝替换文件，不动设置、不重编译；旧的 `legado_import_url` 设置键已进 seed 的废弃清单（启动硬删）。
- **可信代理**：`CreateApp` 中 `SetTrustedProxies(["127.0.0.1","::1"])`——只有本机 nginx 的 `X-Forwarded-For` 参与真实 IP 还原。套 CDN 部署时需同步配置 nginx real_ip（`set_real_ip_from` + `real_ip_header`），否则记录与限流/黑名单口径都会是边缘节点 IP。
- **前端**（规范见 `.trae/skills/minimalist-ui`）：暖单色配色、衬线标题（Newsreader）+ 几何无衬线（Geist）、1px `#EAEAEA` 边框、Bento 网格、淡彩标签；**禁止** emoji、渐变、重阴影、Inter/Roboto/Lucide。分层：`api/client.js`（fetch 封装：token 注入、401 跳登录、`code!==0` 抛 ApiError）+ `api/index.js`（按域端点方法，页面不拼路径）+ `store.js`（reactive 会话态，路由守卫用 `meta.public`/`meta.admin`）+ `components/`（UiTag/UiModal/UiPagination/UiSpinner/UiEmpty/UiField/UiSwitch/UiTrendChart/VerifyCodeField/PageHeader，标签一律 UiTag）+ `styles.css` 的 `@layer components` 基样类（btn/input/card/tag/table）。新页面复用这些组件，不要再写一次性样式。
- **一份事实只许一处写；看到两处写同一份值就合并**。最新一次是数据源的授权与限额：
  `quota_limits(scope=source, target=数据源码)` 的**存在**即「该套餐能用这个源」，`limit=-1` = 能用且不限，
  **删这行 = 回收该源**（判定口只有一个：`gate/grant.go`）。曾经的第二张表 `quota_plan_data_sources`
  停读停写，存量由 `db/seed.go` 的 `alignPlanGrants` 一次性搬进限额表（补 `-1`，搬迁不改额度口径）。
  由此带出一条硬约束：**播种不得按行无限回填**——授权只在「套餐建出来那一次」铺默认档，
  新接入的源由 `attachSourceToBuiltinPlans` 补授权，默认档单点定义在 `db.DefaultPerSourceLimit`；
  否则管理员删掉的授权会在下一次重启复活（待办清单 P34；同类的两处入口收口见 P17、P28）。
  配套两条：`scope=source` 的限额行**目标必须是真实数据源码**（写错名字不报错、只会静默不发源），
  且限额行的增删要 `InvalidateDatasourcesCache()`（它现在会改变套餐能看到哪些源）。

- **设置项的 `type` 是行为声明，不是展示标签**：`string`·`bool`·`number`·`json`。
  `json` 型在面板里用多行编辑器 + 「校验 / 格式化」，后端 `PUT`/`POST /admin/settings/:key` 保存前用
  `json.Compact` 校验并压成单行（只吃 token 间空白，字符串内容与转义原样保留），非法即 400——
  坏值在写入时拒绝，比在运行时（如发码静默失败）发现便宜。type 由 `db/seed.go` 声明并在启动时对账，
  面板不提供改类型入口，所以老库的 `string` 行会跟着声明走。
- **`reveal` 动画依赖观察时机**：`.reveal` 默认 `opacity:0`，由 `utils.revealObserve()` 给元素加 `.in` 才显现，
  而它只观察**调用那一刻已存在**的 `.reveal:not(.in)`。所以异步页面必须先把 `loading` 置回 false、
  再 `nextTick(revealObserve)`——反过来写会让数据取回来了却整块不可见（`Ranking.vue` 初版即如此）。
  同一条坑在折叠组件上会再长一遍：`v-show` 收起的段里的 `.reveal` 元素拿不到观察，展开后停在 `opacity:0`——
  所以 `UiCollapse` 自己在展开后补一次 `nextTick(revealObserve)`，别指望每个页面记得（待办清单 P29）。
- **管理后台的导航是路由的索引，不是精选**：`web/src/main.js` 里每个 `/admin/*` 路由都必须在
  `pages/Admin.vue` 的 `shortcuts` 里有入口——**已由 `make vet` 扫**（`nav-check`：routes 与 shortcuts 求差集，非空即红）。
  起因是号池那一页就是这样漏的：管理员从面板里进不去，只能背 URL。
- **自定义类必须已定义**：`btn-*`/`card`/`table-*`/`input*`/`tag`/`kbd`/`label`/`checkbox`/`reveal` 这些
  本仓自定义类，写了就必须能在 `styles.css` 或**本文件自己的 `<style>`** 里找到定义——
  Tailwind 对不存在的类**静默跳过**，构建、用例、肉眼都不会报，只有对照产物 CSS 才发现（`btn-secondary` 被写
  了 7 处、`label` 17 处、`checkbox` 5 处，全是这种）。**已由 `make vet` 扫**：`scripts/check-css-classes.sh`（待办清单 P31）。
- **移动端只走共享件，不逐页补丁**：表格一律 `.table-wrap`（现在自带 `overflow-x-auto`，窄屏是**滚**不是裁）；
  6 列以上的表必须声明移动端裁剪列（`hidden md:table-cell`，先例 `admin/Users.vue`、`admin/Monitor.vue` 三张表）；
  小屏点击区下限靠 `styles.css` 末尾那条 `@media (max-width: 767px)` 统一抬，不在页面里各写各的（待办清单 P30）。
- **跨进程测试不抢端口**：`test/python/conftest.py` 以 `SERVER_PORT=0` 起 `cmd/fakegateway`，端口从服务的
  `LoomProxy starting on <host:port>` 日志行读回（`app.Run` 因此显式 `net.Listen` 再 `srv.Serve(lis)`，
  日志报的是内核实际地址）。老写法是测试自己 bind-then-close 挑一个空闲端口，那是 TOCTOU——
  两个并发构建会撞 `bind: address already in use`（待办清单 P9）。
- **排行榜页**（`web/src/pages/Ranking.vue`，路由 `/ranking`，登录即可见）：顶部导航在「概览」与「接入指南」之间。
  数据来自**公开榜端点 `/rank/boards`**（`handlers/rank`，固定两张榜 keyword/book、各 top20、窗口只允许 1/7/30 天、
  字段只有 `name` + `total`），并支持 `?source=<数据源>` 按源筛选（候选随响应在 `sources` 里下发，取启用中的
  数据源；未知/已停用的源返回 400，避免把"筛错了"看起来像"没数据"）——同一关键词跨多个源时热度是分开统计的，
  不给筛选就没法判断该用哪个源检索。另有 `?media=<novel|audio|comic|video>` 按媒介筛（待办清单 P3）：
  一站多形态的源在按源统计时是同一条，媒介本来就是明细列，所以这里只是加筛选、不引入新维度；
  候选随响应在 `medias` 里下发，白名单取 `base.MediaValues()`——注意别用 `base.IsValidMedia` 校验入参，
  它认空串（「源未声明媒介」是合法状态）。管理端 `/admin/monitor/subjects` 收同一个参数，两处共用引擎。
  **与管理端的 `/admin/monitor/subjects` 物理错开**——
  后者仍带 success_rate/latency/sources/last_called_at 等运维字段，不该整包交给普通用户。
  卡片头部只标条目数，不显示「合计次数」——合计随窗口与筛选摆动、且容易被读成"独立用户数"。
  放行范围由管理员按**数据源**指定（系统设置 `rank_public_sources`，逗号分隔，留空=谁都不开放）：
  名单外的源既不能单独筛（403），也不会被"全部数据源"那次合并统计算进去（`subjectrank.Query` 的
  `allowSources` 在 SQL 与内存两条路径上都收口），候选列表也只剩名单内的源——
  只校验传入参数而不收窄合并统计，等于名单形同虚设。管理员不受名单限制。
  **编辑入口只有一处**：数据源管理页每行的「榜单可见」开关（`PATCH /admin/data-sources/:id` 带
  `rank_public: true|false`）——它读出现名单、增删这一个源码、整体写回同一个设置项，
  **不新增第二份真相**，`GET /admin/data-sources` 的行因此多带派生字段 `rank_public`（源行本身没有这列）。
  设置页那份 `widget: 'sources'` 复选组已换成 `sources_ro`（只读摘要「已放行 N 个源」+ 跳转按钮，
  `rank_public_sources` 在 `Settings.vue` 里不再可编辑）：两处入口一份真相在**存储层**成立、在**编辑语义**上
  不成立——「整份名单一次提交」与「逐源增量」并存时，拿旧快照在设置页点保存会静默冲掉别处刚改的源，
  而设置页的候选只在打开那一刻取一次 `/datasources`，新源不刷新就不出现（待办清单 P17）。
  全量入口仍在后端（`PUT /admin/settings/rank_public_sources`），供脚本与部署使用。
  删除数据源时后端会把它的源码从名单里摘掉——留着不会放行任何东西，但名单会越积越脏。
- **监控页的数据源筛选用 `datalist` 而非 `select`**（`Monitor.vue` 的维度榜与历史调用两处共用一份候选）：
  候选来自 `/datasources`（启用中的源，带展示名），但**已下线的源在 `data_sources` 里是硬删的**、下拉里不会出现。
  它们在 `api_call_logs` 里是否还有历史明细**不是平台保证，是运维决定的事**（清理是惯例而非机制）——
  只要库里还留着旧源码的行，管理员就得能手打它筛历史，所以做成"可选 + 可手输"。
  公开榜 `/rank/boards` 相反：候选由后端校验，未知源 400（普通用户不该靠猜 code）。
- **两个权限档位共用一份聚合**：`handlers/subjectrank` 是榜单引擎（维度白名单 + 窗口 + 明细与内存缓冲合并），
  管理端与公开端都只调它——口径分叉比多一个包危险。
- **系统设置页**（`web/src/pages/admin/Settings.vue`）是卡片聚合而非平铺列表：受管 key 按功能分 5 张卡，卡级 diff 保存（逐 key `PUT /admin/settings/:key`）；不在清单内的 key 落入「自定义配置」兜底卡。**seed 新增设置 key 时要同步把字段加进前端 GROUPS 的对应分组**（或确认走兜底卡）。
- `web/vite.config.js` 已配 dev 代理（`/auth`·`/admin`·`/quota`·`/rank`·`/datasources`·`/data`·`/verify` → `localhost:8081`）。
- **中间件**：新增一条 = 新建 `middleware/<职责>` 包（或进 `gate` 的对应轴文件）+ `init()` 里一次 `middleware.Register(Def{Scope, Order, Applies, Build})` + `middleware/all/all.go` 加一行空白导入；`app.go` 免改。顺序只改 `middleware/middleware.go` 的 Order 常量，`test/middleware_chain_test.go` 会失败以逼一次审查；同作用域内 Order 撞车或重名在 `Register` 期 `log.Fatalf`（宁启动失败不带病装配）。`middleware` 根包是叶子包，不要给它加子包或 gate 的导入（成环），装载清单只在 `middleware/all`。
- **测试**：黑盒测试一律放 `test/`（包名 test，只测公开 API，不与源码混放）。单元级用 `httptest` + 直接构造 `conf.Config` 全局指针；HTTP 集成用 `testserver_test.go` 的 `newTestServer(t)`（临时 SQLite + `app.CreateApp()` + `httptest.NewServer`，自动 AutoMigrate + seed，admin/admin1234）。全局态（`conf.Config`·`db.DB`·`utils.DefaultCache`·限流器·号池注册表）跨用例共享，**集成用例禁止 `t.Parallel()`**；`newTestServer` 已清缓存，直接改库后按需 `delCostCache`。
- **断言写完要做一次变异验证**：把被测的那个改动**反转**再跑用例，确认它真的失败——绿灯只证明用例没挡住现状，
  不证明它能挡住错误。改名、挪参数、加声明位这类「行为等价」的改动最容易写出永远绿的用例。
  本轮两例：回填扫描方向 `DESC`↔`ASC` 一换即失败（证明这条钉住了）；把假源的必填声明撤掉，
  用例立刻拿到另一种 400 文案（证明断言测的是声明位，不是碰巧的报错）。
- **踩到的机制性坑记在 [`踩坑判据.md`](踩坑判据.md)**：一句可自查的判据 + 它的固化去处。
  那条约定里最重要的一条是**退出机制**：坑一旦被固化成用例/门禁/校验位，本页那一行就该删掉——
  「文档写过」不等于「防住了」（保留字那条写了多年，仍然在同一个仓库里第二次踩，
  直到它变成 `make vet` 里的一个脚本）。
- **质量门禁**：每次修改完成后 `make build`（含 vet + gofmt + `go test -race`），并**必须 `git commit`**（含 AGENTS.md 同步更新），不留未提交的工作区改动。
- **AGENTS.md 同步规则**：改动涉及数据源、接口、中间件、配置项、架构模式时，同步更新本文件对应章节并一起提交。不确定时优先更新，避免文档与代码脱节。
