## 3. P104：spike 两步的实测

### 3.1 基线（第一步之前，仓库现状）


### 3.3 第二步：切两包后的墙钟（`/tmp/p104_probe_repo` 一次性副本，不进仓库）

切法：按耗时均衡移动 11 个文件到新包 `test/probeb/`，跨边界引用到的声明由脚本整份借入（7 个 borrow 文件）。
两条对照 + 一条合跑，全部当场计时：

```
两包合跑（go test ./test/... 跨包并行）  WALL=257.2s   EXIT=1（原因见 §3.4，不影响这条读数的有效性）
单包对照 A（./test/，91 文件）            WALL=244.6s   EXIT=0
单包对照 B（./test/probeb，11 文件）      WALL=205.3s   EXIT=1（32 条 FAIL，同一原因，见 §3.4）
串行合计 244.6 + 205.3 = 449.9s  →  并行 257.2s  =  **省 42.8%**（对基线 456.9s 是 43.7%）
```

**判据通过**：条目写的是「降不到 300s 以下就不做」，实测 257.2s。
两条单包对照不是多余的动作——只量合跑那一条，分不清省下的时间是并行给的还是机器今天快；
而合跑那次里跑完的那包是 253.3s（单独跑 244.6s），**争用代价 +3.5%**，这就是"16 核只用 1 核"能换到的折扣。

### 3.4 失败归因：不是并行撞坏了用例

`probeb` 里 32 条 FAIL 全是**要打假源路由**的那些（聚合搜索 / 计费 / 限流 / 访问控制 / 隐私留存 / 额度转移），
症状统一是 `404 {"code":404,"msg":"not found"}`。根因既不是并行也不是夹具：

**`fakesource.Register()` 挂在 `test/fakesource_test.go:17` 的包级 `init()` 上**，
新包没带这个 init，三个假源就没登记，路由不存在、seed 里也没有那些数据源。

排除的过程靠两条对照：同一批用例在**单包**跑里同样红（所以与并行无关），
而留下的那包在并行跑里 253.3s 全绿（所以并行也没撞坏任何东西）。
**这条是拆包必须带走的第二件东西**：正式拆分时每个新包都要自带一行
`func init() { fakesource.Register() }`，否则得到的不是"并行提速"而是"32 条红"。

### 5.1 它第一次跑就教了我两件事（判据是它给的，不是我设计的）

1. **`/admin/users` 在 1280 视口被报成溢出**：`table.table-base` 右沿 1395 > 1280，而整页 `scrollWidth=1280`。
   真因是表体在自己的横向滚动容器里——**用户滚得到就不是缺陷**。第一版判据把"出界"当成"到不了"，误报。
2. **但加上"祖先能滚"之后，违例反而报不出来了**：种一个 2400px 的 div，`offenders` 列表居然是空的。
   真因是 CSS 的一条规则——**一个轴 `overflow-y:auto` 会让 `overflow-x` 的计算值也变成 `auto`**，
   于是"页面根能横滚"恒成立，任何溢出都能被它豁免。
   修法是两个信号各管一段：**整页 `scrollWidth` 超了就直接列出出界元素**（此时"祖先能滚"不能作为豁免），
   **整页没超时才用"局部滚动容器且它自己装得进视口"当豁免**。

### 5.2 两个信号都注入违例证明过会红（不然它就是一个新的绿灯装饰品）

| 违例 | 结果 |
|---|---|
| 种 2400px 的 div 进 `/panel/ranking`，重建前端与二进制 | `溢出 scrollWidth=2416 视口=390  div(右沿2416,宽2400)`，退出码 1 ✓ |
| 改用**普通用户**的会话去开管理页 | `403 /rank/boards` 被抓到 ✓，同时页面身份守卫报 `❌ 没停在本页：location=/panel/dashboard` ✓ |
| 路由表解析第一版切错边界（`createRouter` 在 import 行就出现，切出空块） | 守卫直接报"路由表读出来是空的——探针会空转"并退出 2 ✓ |

撤违例的方式是先 `git diff` 看清只丢本轮种的 2 行，再 `git checkout --` 那一个文件（本轮自己种的，不是别人的活）。
