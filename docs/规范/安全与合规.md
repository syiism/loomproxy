# 安全与合规

> 本页由 `AGENTS.md` §11 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

- 不要把真实密钥写入仓库或文档：`.env` 的 `API_KEYS`·`ADMIN_PASSWORD`·`JWT_SECRET` 均属敏感信息；生产必须改默认 `JWT_SECRET`。
- CORS 当前为 `*`（面向阅读 App 的开放 API），收紧前需评估对书源客户端的影响。
- `baseURLCheckMiddleware` 对所有注册路由校验 `base_url`（`utils.IsSafeURL`：仅 http/https，DNS 解析后拒绝回环/私有/保留 IP，含 IPv6）。**按来源区别对待**：请求参数与用户个人配置严格校验；**平台默认配置视为管理员可信来源**，允许指向本机/内网（用于同机部署数据源项目）。声明 `FixedBaseURL` 的源整体跳过。
- 密码 bcrypt 哈希；用户软删除，其用户名/邮箱进入黑名单（注册、建用户、管理侧改邮箱三处查重都走 `Unscoped()`
  且改邮箱排除自身 id，冲突返回 409 提示「已被注销账号占用」；少一处预检，约束冲突就一路撞到驱动变成没头没尾的 500。
  占用者用户号只在 `/admin/users/:id` 的文案里给出——注册端是匿名可达的，不能泄漏他人 id）。
  `users.email` 声明 `not null`：历史 NULL 行只读，管理端提交空邮箱一律 400 而不是写 NULL。
- **免鉴权的静态托管路径把每个路径段都当不可信输入**（待办清单 P74）：`GET /data/<分类>/<文件>.json` 不走鉴权，
  而 handler 里是 `filepath.Join(DATA_DIR, source, name+".json")`。修复前的实测形态是
  `GET /data/../<文件>.json`——gin 把路径参数原样交出来，`source=".."` 就把基准目录抬到 DATA_DIR 的父目录，
  于是**父目录里任何 `.json` 都能被原样读出**（`GET /data/..` 还会把那份文件名列表念出来）。
  判据：**路径穿越的守卫要站在两处**——入口（段里不许有 `.`/`..`/分隔符/前导点）与落盘点
  （算出来的绝对路径仍在这个根目录之内）。只留入口是"信任下一次没人改坏它"，只留地板会得到一个含糊的
  "200 且什么都没读到"；两处各自单独验过（见用例的三种摘除组合）。
  响应形状沿用本页既有的 `ErrorResponse`（`{"error":"非法的字典路径"}`），**没有改状态码**——
  缺文件回 200 还是 404 仍是待办清单 P51② 那一问，不由这条顺带拍掉。
- 号池与设备凭证（`pool_devices.attrs`）属上游签名凭证：接口响应与日志只出脱敏值（保留前 8 后 4），管理面板不展示原值。
- **设置项里的对外通道凭证只写不回显**（待办清单 P62，与号池那一条同口径、另一个面）：
  `verify_http_headers` 里躺着发码平台的真实访问令牌，而 `GET /admin/settings` 过去是 `Find` 之后整份原样返回——
  于是这个值的可见面是**所有管理员会话的读响应 + 面板 DOM + 任何记录响应体的地方**。
  现在判据只有一处：`db.SensitiveSettingKeys` 名单（**现只一键，刻意不做通用"凭证类设置"框架**——
  一例就建框架，那份名单会长成第二事实来源）。读的一侧命中即出**空串**（不是 `••••` 掩码：
  掩码会被当成值保存回去），名单随响应一起下发（`{items, sensitive_keys}`），面板据此渲染密钥控件，
  所以前端没有第二份名单可漂。写的一侧必须有配套的那一半：**留空 = 保持原值**，
  否则「打开面板 → 什么都没改 → 点保存」就是管理员自己把通道配死。
  **这一条不撤销历史**：已经进过面板的那个令牌要**轮换**，那是通道侧的独立动作，不在代码里。
- **参数绑定错误的原文不外发**（待办清单 P90②）：gin 的绑定错误带着**结构体名、字段名、期望类型**
  （`json: cannot unmarshal array into Go value of type auth.loginRequest`、
  `Key: 'loginRequest.Password' Error:Field validation …`），而它过去被 `"参数错误: "+err.Error()`
  原样发进**用户面**六个端点的响应（`/auth/login`·`/auth/me`·`/auth/privacy`·`/auth/display-alias`·
  `/auth/password`·`/user/source-configs`）。现在对外一律固定句「参数错误」，真因进服务端 ERROR（带路径，不带输入值）。
  **管理面那 33 处不改**：它们都在 `AdminRequired()` 之后，而本页早已把「明细只经 `/admin/*`」写成设计——
  管理员看到 SQL 文本属于这套设计，不是泄露。判据是**按读者与来源两条轴审**，不是"凡 `err.Error()` 皆删"。
- **登录防爆破的锁定读数只经 `/admin/*`，且不新增留存**（待办清单 P40）：`GET /admin/security/attempts` 出的是
  当前进程内存里的「IP + 窗口计数 + 是否锁着」，`POST /admin/security/attempts/reset` 按 IP 清锁——两者都不写库、
  不进 `api_call_logs`（那张表只覆盖数据源路由）。选择「不落库」是有意的：把每次登录尝试（IP + 用户名）长期驻库
  是一份新的敏感行为留存，需要单独的保留期与出明细口径，不该顺带塞进一个运维按钮。
- **阅读数据的留存同意位**（待办清单 P37）：`users.content_consent`，NULL = 从未表态 = **同意**（默认档写在读的一侧，不靠回填数据）。
  用户在个人中心（`/panel` → 个人资料 → 阅读数据留存）可关闭；关闭后 `monitor` 在写入明细之前抹掉
  搜索词、书名、章节名、**书目标识与章节标识**、媒介、结果数七个字段——标识必须一起清，
  否则名称回填循环会按标识把书名补回来，开关形同虚设。请求本身照常成功、调用计数不受影响。
  承诺的边界要说全：**留存的内容只用于排行榜展示，公开端点只出书名与搜索词**（维度白名单
  `keyword`/`book`，章节与媒介不出公开榜，身份字段更不给）；关闭**不追溯删除**已落库的历史明细，
  「删除我的全部记录」是另一个决策（涉及审计口径与既有备份）。
  同意位只有 `POST /auth/privacy` 一个写入口，且**只认会话**：长期 API Key 能改它，
  就等于密钥泄露时攻击者可以替受害者重新打开留存，而这件事在会话列表里看不见。
- **许可与合规**：代码按 AGPL-3.0 发布（`LICENSE`），使用条件见 `DISCLAIMER.md`。引入新依赖前确认许可证与 AGPL 兼容（`go.mod` 是唯一的依赖清单，别绕过）；不要把凭证、上游签名参数或真实 `.env` 内容写进仓库、文档与测试夹具。`api_call_logs` 的内容维度是用户阅读/调用行为数据，默认永久保留（`MONITOR_RETENTION_DAYS=0`），对外部署前必须按合规要求设定保留期。
- **调用明细含用户阅读内容**（搜索词/书名/章节名/媒介）：属敏感行为数据，**明细**只经 `/admin/*`（后端 `AdminRequired()`）暴露给管理员，不出网关；**"不进访问日志"这半句过去只对了一半，见下条**；
- **留存要按面清点：响应、库、进程日志、指标、缓存是五面**（待办清单 P92）：`users.content_consent`（P37）关掉的是写库前的捕获，
  `MONITOR_RETENTION_DAYS` 轮转的是库表，**两者都碰不到 journald**——而 Go 的 http 错误原文必带完整请求 URL，
  Legado 一族的查询串里就是搜索词与书/章标识（现网 14 天实测 260 行带查询串、121 行带搜索词）。
  日志侧的口径是**隐去内容、保留拓扑**（`app.scrubQueryForLog` 洗掉查询串、留协议+域名+路径），
  与对外文案的"出现 `://` 就整句换掉"（`sanitizeUpstreamMsg`）是**两个判据**，不许合并成一份。
  **第五面是 `FetchShared` 的响应缓存（2026-10-08 拍板走 Redis）**，它是这一族里最新长出来的一格，
  而且**是那条判据自己应验的一次**：清单页写着"按面清点"，实现缓存时数的仍是四面——
  缓存键里带着「哪本哪章」、条目按自己的 TTL 驻留，`content_consent` 与 `MONITOR_RETENTION_DAYS` 一样碰不到它
  （关掉留存的读者，那一格照样在）。它不在明细表里、也没有保留期设置可管，**要它不存在只有把 TTL 给成 0**。
  所以架构页那三条约束（键含会话、只缓存 2xx、TTL 由源侧显式给）是这一面的**留存边界**，不是风格；
  取舍是「少打上游」换「多一处按内容命名的短期驻留」，值本身只是上游原样的密文信封，我们不解开它。
  管理员可按**数据源**把**聚合榜**（`/rank/boards`：两个维度、top20、只有名称与次数）放开给登录用户
  （`rank_public_sources`）——
  聚合不等于明细，但窗口越短稀有词越容易反推到个人，所以公开端的窗口取值被代码钉死为 1/7/30 天且不接受更细的筛选；默认永久保留（`MONITOR_RETENTION_DAYS=0`）意味着这些记录长期驻库——对外部署前按合规要求设定保留天数。
- 面板路由守卫在前端，真正可信的权限校验是后端 `AdminRequired()`——后端是唯一信任边界。
