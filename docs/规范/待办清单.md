## P109 `make build` 的退出码会被管道吞掉：`make build \| tail` 报的是 tail 的 0【在册：待固化】

- **现象**：本轮两次把「红掉的构建」读成「绿的构建」——命令写作 `make build 2>&1 | tail -25`，
  通知给出 exit 0，而输出末尾明写着 `make: *** [Makefile:58：vet] 错误 2`。
- **影响**：这不是观感问题。换装流程里"全量门禁 EXIT=0"是发布前置的**唯一读数**（AGENTS §3、S69 口径），
  一个会被吞掉的退出码等于那条前置可以假绿；而假绿的那一次恰好也是我最容易不再回头看输出的一次。
- **建议**：把"构建结果"的判法改成**先落文件再判**——`make build > /tmp/build.log 2>&1; echo $?` 之后读日志，
  或在 Makefile 里加一个自带 `SHELL := /bin/bash` + `.SHELLFLAGS := -o pipefail -c` 的目标；
  更彻底的是给运维脚本一条判据：**任何承担"通过与否"读数的外层管道都要 pipefail**（与换装三查同族：
  读数要来自被测对象本身，不能来自它后面那一截管道）。
- **发现处**：2026-10-08 携带形态并发冒烟那一轮，我自己踩的两次。

## P111 方案页的豁免遮住了三处不存在的仓库路径【在册：待处置】

- **暴露经过**：携带分支把 `docs/数据源/方案-xxx.md` 搬进 `docs/数据源/方案/` 并去掉前缀，
  而 `check-doc-refs.sh` 的"将来时页不核对"是按**文件名含「方案」**判的——改名一失效，三处路径立刻报红。
  豁免规则先修了（目录段也认），**但被遮住的东西不会因为这个修复就变对**：
- **三处计划路径**（都在方案页里，本树不存在；**这一条自己不用反引号写它们**——反引号在这套判据里是"本树存在"的断言，
  在册的待办页是**被核对的现状页**，用引号点名不存在的东西会让这条判据自己变红，携带树上那条 `sources/...` 更是两棵树都躲不掉）：
  「sources/fq/protocol/session.go」（会话池方案里"计划新建"的文件，三次被点名）、
  「test/fq_hg_integration_test.go」（拆分方案的迁移清单里写的用例，实际落地用的是别的名字）、
  「docs/本次案例总结报告.md」（纸间方案页引的仓外/历史材料）。
- **为什么要处置**：这条判据的全部价值在于"`docs` 里点名的路径还在不在"。方案页整类豁免是对的（它们陈述打算），
  但**豁免是遮蔽不是判定**——写"计划新建 `x/y.go`"没问题（占位形状不被判），写成与现存文件无差别的路径形，
  半年后没有人分得清哪个是打算、哪个是已经不存在了（「admin.GetStats」那一族的形状：一个看起来比真的更像真的名字）。
- **三个出路**：① 方案页里凡"计划新建"的路径统一写成 `x/y.go`（新）或"文件名未定"，让形状自带将来时；
  ② 把豁免从"整页"收窄成"只豁免带 `（新）`/`（计划）` 标注的那一条"（要动脚本，且需要那三条先补标注）；
  ③ 维持现状，接受"方案页里的路径不作仓库事实"这一条写进页首（现在这句其实没写）。
- **建议**：① + ③ 各一半——改三处措辞很便宜，同时在脚本头部与豁免注释里写明"方案页的路径不作仓库事实"。
- **发现处**：2026-10-08 携带分支归拢 `docs/数据源/方案/` 那一次，改名让豁免失效才露出来。
