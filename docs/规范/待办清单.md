## P1 `db.GetSetting` 的列引号只兼容 MySQL/SQLite

- **现象/证据**：`db/setting.go` 读设置用 `Where("`key` = ?", key)`（反引号硬编码，注释写的就是「MySQL 保留字」）。
  PostgreSQL 的标识引用是双引号，反引号是语法错误 → `First` 报错被吞掉，函数返回空串。
- **影响**：`DB_TYPE=postgres` 的部署上**所有系统设置都读成空**（榜单放行名单、代理开启名单、验证码开关、自动拉黑阈值…），
  且不会报错，只会表现成「设置没生效」。和 `api_keys.key` 那次是同一类坑（那次的教训是「条件用 map 形式让 GORM 按方言加引号」）。
- **建议修法**：条件改 `Where(map[string]interface{}{"key": key})`；顺带全库扫一遍同类硬引号。
- **发现处**：2026-10-01 修 `api_keys.key`（`92d608e`）时同源比对出来的。

## P2 命名缓存写 Redis 的队列会丢

- **现象/证据**：生产关停日志 `命名缓存写 Redis 累计丢弃 5104 条（队列满；内存缓存期间仍正常）`。队列 4096、
  写侧每 200ms 提交 128 条（约 640 条/秒），高峰写入需求压不过就丢。
- **影响**：跨重启的「标识→名称」完整度打折——排行榜与监控明细里会出现空白名，需要 `POST /admin/monitor/backfill-subjects` 事后补。
- **建议修法**：加大队列或批量/缩短提交间隔；更根本的是丢弃计数非零时发出告警（现在只在关停时打一行）。
- **发现处**：2026-10-01 部署后的 journalctl 复核。

## P3 公开榜缺 `media` 筛选参数

- **现象/证据**：`/rank/boards` 只能按 `source` 筛；引擎 `handlers/subjectrank` 已有 media 维度，缺的只是筛选入参。
- **影响**：一站多媒介的源（如 `fq_hg` 小说/听书/漫画/短剧/漫剧）在榜上算同一个源，用户无法按媒介看榜。
- **建议修法**：给公开端点加 `media` 参数（白名单取 `base/media.go` 的枚举），并把候选随响应下发。
- **发现处**：2026-10-01 做榜单页时的遗留项（已记在 AGENTS 拆分前的原文里）。

## P4 号池没有「总号数上限」声明位

- **现象/证据**：`pool.Config` 只有 `ColdSpares`/`MaxHot`/`MaxDead`，都是水位而非上限；uxx 池的账号上限是在**源内**
  用 `Create` 前查 `pool_devices` 计数实现的，属于绕路。
- **影响**：任何「建号会对上游产生不可逆增长」的源都得自己再写一遍闸；`xmly` 目前没有上限。
- **建议修法**：给 `Config` 加 `MaxDevices`（0=不限），框架在 `createColdLocked` 前统一判一次。
- **发现处**：2026-10-01 uxx 会员号池落地（`77b48a6`）。

## P5 号池只支持墙钟燃烧型，用量摊薄型未支持

- **现象/证据**：`Acquire` 只在 `hot` 里轮询，而 `hot` 刻意只有 1 个；对「不因墙钟过期、只在被风控时临时不可用、
  理想是把请求摊到多台」的资源形态（`fq_hg` 会话池）不适配。
- **影响**：`fq_hg` 的会话池仍走文件形态，看不到面板、不能自建号（`device_register` 未移植）。
- **建议修法**：方案已写（`docs` 分支侧的融入方案 + 本仓库 P5），核心是给 `Config` 补形态声明位与 `cooldown` 状态；
  **用户已明确：设备池方案先待定，不动代码**。
- **发现处**：2026-10-01 评审 `fq_hg` 会话池。

## P6 面板「号池」页需要池形态标签

- **现象/证据**：`Pools.vue` 按 hot/cold/spent/dead 展示。若将来出现 `spread` 型池（P5），一堆 `cold` 会被管理员读成「池没工作」。
- **建议修法**：`pool.Status` 带 `kind`，前端加一个标签列/角标。
- **发现处**：2026-10-01 `fq_hg` 融入方案讨论。

## P7 uxx 广告冷却的自适应值需上线后复核是否收敛

- **现象/证据**：站点只回 `zt:yes`「请稍后再观看」，间隔未知，现按「成功减 7 分钟 / 失败加 1 分钟 / 上下界收到 1 分钟内钉住」标定。

- **发现处**：2026-10-01 上线当天（`77b48a6`）。

## P8 `/datasources` 的鉴权口径与文档不符

- **现象/证据**：文档写「`/datasources`·`/data` 免鉴权」，但 `AUTH_ENABLED=true` 且白名单为默认值时，
  匿名请求 `/datasources` 实测 401「缺少鉴权凭证」，只有 `/data` 匿名可达。
- **影响**：书源客户端能不能匿名拉清单，文档说的和实际不一致；本轮只做文档，不动代码也不改口径。
- **建议**：要么把 `/datasources` 加进 `AUTH_WHITELIST`（产品决策），要么把文档改成「`/data` 免鉴权、`/datasources` 需鉴权」。
- **发现处**：2026-10-01 生产升级实测（分支侧文档 §11 已记）。

## P9 构建纪律：同一时刻只能跑一个测试二进制

- **现象/证据**：`go test ./test/` 里的 Python 用例子进程会起 `cmd/fakegateway` 并监听 **固定端口 8081**；
  两个构建并发跑（或上一个被 kill 后残留进程未退）就会 `bind: address already in use` 而失败。
- **影响**：不是产品缺陷，但会让人误判「代码改坏了」。
- **建议**：要么串行跑构建，要么让 fakegateway 在测试里用 `:0` 随机端口并回写实际地址。
- **发现处**：2026-10-01 并发跑 base 与分支两个 `make build` 时踩到。
