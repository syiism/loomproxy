# 门禁台账

> 18 道 `make vet` 门禁（15 个 `scripts/check-*.sh` + Makefile 内联的 nav-check + gofmt + go vet）
> 只进不出的问题在 2026-10-05 被点出名：
> 「§5b 的门禁闸能防边跑边加，存量没有退役机制」。本页是退役机制的家：**每道门禁必须登记「拦住过什么」**，
> 连续 3 轮零命中且没有分支侧命中的，降级为用例或删（删门禁与删判据同规矩：先删后加、回链经验）。
> 「拦住过什么」一栏填不出来又不属于自指类的，本身就是降级候选。

## 退役与体量规则（本页的牙齿）

1. **零命中退役**：一道门禁连续 3 轮长任务零命中（骨架与携带分支的预检都没红过），且有等价用例可接住的，
   降级为用例；接不住的（跨方言/跨仓形状）在「拦住过什么」里写明为什么必须留在构建里，否则删。
2. **体量阈值**：`docs/规范/待办清单.md` 在册未收口 > 20 条或页长 > 800 行、
   `docs/规范/已收口索引.md` 页长 > 400 行（2026-10-07 从清单页分出来的一页；触发之后的动作写死：
   **按轮次分片，不在这里做压缩**——把行改短就是往第二份事实来源里塞内容，那一族刚治过）、
   `docs/规范/踩坑判据.md` > 40 条、
   **`AGENTS.md` > 30KB** → 触发一次强制归档/瘦身轮（只归档或下沉、不新增）。
   **这条线按树分档**（维护者 2026-10-08 拍，分支侧登记为 S80 的 A 案）：
   骨架树上核绝对体量（全文 ≤ `AGENTS_LIMIT` = 30KB）；携带树上核的是**「分支往共用章节添了多少」**——
   `delta = (全文 − §0 那一节) − 基线 tag 上的 AGENTS 全文`，预算 `CARRY_EXTRA_BUDGET` = 512 字节。
   **为什么携带树不核绝对数**：第一版那么写，落地当场就红，而超的那 268 字节不是"分支留了一段骨架长文本"，
   是分支在 §11/§12/头部补的三句许可与推送边界——那些本来就该在携带树上。
   一条会把正当补充判成违规的门禁，第二次就被人无视（本台账反复记的那条）。
   §0 不计入是因为它是分支自有的那一节；基线 tag 从 §0 里那条 `git diff skeleton-vNN...HEAD` 现取，
   所以这条检查同时要求那句话维持形状——它变了就出声，不静默跳过。
   量法、阈值、预算三样的唯一落点都在 `scripts/check-doc-numbers.sh` 里，不在这里抄数。
   **最新时点读数（2026-10-10 收口轮，P113/P114/P117 三条整条搬出之后；`wc -l` / `wc -c` 现测）**：
   清单页 **317 行 / 在册正文 7 条**（P110 那轮搬出压到 51，登记 P109/P111、P109 的追记与缓存这一族的 P112~P114 涨到 122；**这条读数每登记/收口一次就得复算一次**，本轮被 `doc-numbers-check` 连着逮到两次——**上一条的错也不是数错，是把"复算过"当成"改过了"：那次 `check-doc-numbers` 的红被 `| tail` 咽掉了，见待办清单 P109**。2026-10-09 复测：P115 登记与落地记录涨到 148 行 / 7 条，P116 入册到 160、两条更新到 162、测试迁入到 164、CI 接线到 165；同日 P115 线上收口整条搬出后回落到 154 行 / 7 条，P117 滑窗续期入册到 167 行 / 8 条，P118 榜单慢查询（现网实测）入册到 215 行 / 9 条（同日复测把 `:508`/`:209` 的成因改判后追加 ⑤ 那一格），P118 ① 落地后回写涨到 232 行、补 tag 指路到 234、与 deploy 对齐（指向四处 + 复采读数）到 239、P118 ② 生产实测否决回写到 244；**2026-10-10 收口轮：P113/P114/P117 三条「代码早已在 v110 里、状态行还在册」整条搬出 → 201 行 / 6 条；同日维护者点名四格面板调整登记 P119 → 243 行 / 7 条**），已收口索引 **153 行 / 索引 112 条**（这两数与下面两条由 `doc-numbers-check` 规则④ 当场核对，不再靠手改。P104 之前的两次加行是第四十四遍登记 P103、第四十八九遍落地 P102/P103 各一截——**这一条线今天第一次落到阈值之内**（登记至今它一直在 800 行之上，
   最少时是 P35~P95 那 22 条整条搬出之后的 1422 行）。做法是把占全页三分之二的巡检日志（P49，1199 行）整条搬进
   `docs/归档/2026-10-瘦身轮/`，再搬出两条"其实已收口"的（P23 ②已拍归分支、P75 两半做完），1783 → 524 行（现 585）。
   **同批删掉三份"谁还在清单页"的副本名单**（页顶那句已收口枚举漏列 P69/P72 而表里有行；归档 README 与
   清单页的指针块各有一份早已搬走的名单）——判据：**索引表才是正本，名单都是副本**。
   见那一页顶部与报告 §21、§22。**规则被兑现一次，比新加一条规则有用**：
   从没读到的阈值等于没有阈值，它给下一轮的信号是"超线也不要紧"），
   判据页 1636 行（**条数不在这里抄**——`judgment-count-check` 直接在判据页上核，两处都写就会长出第二个正本。档位定义在第四十三遍补的，当时重判为 **2 已 / 39 部分 / 14 未**，
   原先那句写的是 10 已——**档位从来没有定义，所以宽松的方向一直是默认方向**。
   那一格当时留下的是「能删的只有 `已`，只剩 2 条」；**本次真把它删了**：两条整节移出本页，
   删之前先把判据里**机器检不了的那两半**升进 `开发约定`（元判据"文档要求人记住的步骤，脚本没做到就等于没做"、

   **删页面不等于丢教训，先确认去处再删，否则这一轮又变成"白踩一次"**。

   剩下的体量因此只能靠**合并同族**降——不能靠改档位（那是替自己打分），也不能靠新加自指门禁（那是给下一页添复述））、
   `AGENTS.md` **32003 字节**（骨架树现测，2026-10-09 与 deploy 对齐：§1/§4/§12 三处把"接入一个源"的携带清单改指装配仓 `loomproxy-deploy`，31209 → 31635，仍在那条线之内；2026-10-10 又 +368：§9 那条公开榜补了缓存那三句（P118 ③），**这一条线仍然超、瘦身仍排在下一个整轮**——本轮不假装它在线之内；
   S73 瘦身后第一次落到阈值之内；**分支那一格不抄在这里**——携带分支每次 merge 都要改 §0 锚点，
   那个数是「写下即过期」的形状，而这一页两棵树共用（接缝判据不许分支单方面改它），
   于是分支树上要么每颗合并提交顺带改一次正本、要么让它常红——两个都不要。
   分支侧只留量法 `wc -c AGENTS.md` 与 S61；规则④ 在分支树上**出声说明这一项不核**，不静默跳过）
   ——**这两条线仍超**（判据页条数在阈值之上——那一数只在判据页的分布行里写，
   AGENTS 那一轮整文件重写把它从 32780 压到 30888，但之后每一版收口都在往里加，今天又回到 31KB 之上（本轮 P104 收口在 §3 加了三行并行事实，**+643 字节**——超线这件事仍然挂着，见下面那句"瘦身仍排在下一个整轮"），

   这一版第一次回到阈值之内）；判据页的瘦身仍排在下一个整轮（那两轮搬的都是"日志"和"已收口的条目"——那些不需要判断去处；
   而把一段细节从索引页沉到哪一页，是要先答去处再动手的，**没有去处的瘦身只是换个地方堆**）；
   AGENTS.md 的 30KB 上限同日登记（分支版曾涨到 62KB：§0 的逐版 prose 内联是主因，已随 §0 瘦身收口；
   分支版今天实测也在 30KB 之上，而它那一格原本写的是"本文件 ≤ 30KB"——**索引页在替自己说假话**，
   第四十二遍改成"目标 + 现测超限 + 量法"并登成分支侧 S61）。
3. **自指占比**：守规范页自身数字的门禁（judgment-count、doc-numbers）是「过程治理吃掉产品工作」的
   领先指标，新增自指类门禁要过「为什么不进用例」这一问。
