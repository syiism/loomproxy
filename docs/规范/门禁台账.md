# 门禁台账

> 14 道 `make vet` 门禁（12 个脚本 + go vet + gofmt）只进不出的问题在 2026-10-05 被点出名：
> 「§5b 的门禁闸能防边跑边加，存量没有退役机制」。本页是退役机制的家：**每道门禁必须登记「拦住过什么」**，
> 连续 3 轮零命中且没有分支侧命中的，降级为用例或删（删门禁与删判据同规矩：先删后加、回链经验）。
> 「拦住过什么」一栏填不出来又不属于自指类的，本身就是降级候选。

## 退役与体量规则（本页的牙齿）

1. **零命中退役**：一道门禁连续 3 轮长任务零命中（骨架与携带分支的预检都没红过），且有等价用例可接住的，
   降级为用例；接不住的（跨方言/跨仓形状）在「拦住过什么」里写明为什么必须留在构建里，否则删。
2. **体量阈值**：`docs/规范/待办清单.md` 在册未收口 > 20 条或页长 > 800 行、`docs/规范/踩坑判据.md` > 40 条
   → **触发一次强制归档轮**（只归档、不新增）。2026-10-05 时点：清单页 2017 行、判据页 1155 行——
   **阈值已双双触发**，归档轮排在下一个整轮（本轮先落规则，不动存量）。
3. **自指占比**：守规范页自身数字的门禁（judgment-count、doc-numbers）是「过程治理吃掉产品工作」的
   领先指标，新增自指类门禁要过「为什么不进用例」这一问。
