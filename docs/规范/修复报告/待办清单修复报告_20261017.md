## 2. 取证

- **时区那条的取证不引用"现在几点"**：本机时区读数就是 **UTC+0000**（不是 +8），而平台偏移由 testkit 钉在 +8，
  于是「进程日」与「平台日」在 UTC 16:00–23:59 那八小时不同日——**这台开发机自己就在窗口里**。
  所以最初把这条记成"本地不会红、换台机器才红"是记错了，本轮改成实情：它是"任何非 +8 主机都会红，本机正是非 +8 主机"。
  变异验证（§10 那条：把改动反转跑一次）的红把两个钟并列印了出来：FAIL 行给
  `map[day:2026-10-17 source:fake_c …]`（服务端按平台时区标的那个），
  同一刻 `date -u` 与 `TZ=Etc/GMT-8` 的读数分别是 2026-10-16 与 2026-10-17；
  换回 `utils.DayStart(1)`（日界唯一处，当日传 1）后 `ok loomproxy/test 7.372s`。
  **这条是 CI 接线直接钓出来的第一个坑**，属于判据页「CI 会红、线上不会红」那族的镜像方向。
- `--frozen-lockfile` 先钉一次是有对象的：本轮把 `web/package.json` 的 8 个 specifier 与 `web/pnpm-lock.yaml` 的 importers 逐个对过，一致；
  将来漂了就是当场红，而不是换一棵依赖树继续往下跑。
- **全门禁**：本轮按 P109 要求的形状跑（`make build > /tmp/gate.log 2>&1; echo "BUILD_EXIT=$?" >> /tmp/gate.log`），
  退出码与失败段落在提交说明与 `/tmp/gate.log` 里，不在这页抄第二份。
