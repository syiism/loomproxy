## 2. 取证

## 4. 三跑的定位链与真因（本轮最后落的那一节）

| 跑次 | sha | 步骤结论 | 由此得到 |
|---|---|---|---|
| 首跑 | `daf8fdb` | 单步 `make build` 红（62 s），annotation 只有 `exit code 2` | 合成一步没有可归因性；日志下载要管理员权限（未认证 403） |
| 第二跑 | `c8a0401` | `make web` 3 s 绿 → **`make vet` 62 s 红** → `make test` skipped | 拆步生效：红在静态段，且**测试从没跑到**（所以任何"测试挂了"的说法都不成立） |
| 第三跑 | `e4e9afb` | 同上，handler 把日志末尾送进 annotations | **真因**：`/bin/sh: 3: Syntax error: "(" unexpected` → `Makefile:198 nav-check` |

- **本地排除的三种组合**（都绿，写下来是为了让下一次别重复跑）：工作树 + `GOTOOLCHAIN=go1.26.5` 的 `make vet`；
  HEAD 干净克隆 + 本机 1.27.2 的**完整** `make build`；HEAD 干净克隆 + `GOTOOLCHAIN=go1.26.5` 的 `make vet`。
  第一与第三之间原本缺一个交叉组合（`GOTOOLCHAIN` 不改 `gofmt` 这类独立二进制，
  所以第一次探针其实没在 1.26.5 的 gofmt 上跑过——补测了两版 gofmt 的 `gofmt -l`，输出都是 0 个文件）。
- **根因的形状**：Makefile **没声明 `SHELL`** → make 用 `/bin/sh` 跑 recipe →
  Ubuntu 的 `/bin/sh` 是 dash，`nav-check` 的 `comm -23 <(...) <(...)` 解析不过；
  开发机 Arch 的 `/bin/sh` 指向 bash，于是**这段静态门禁在本地"绿"了一年多，在任何 dash 机器上直接缺席**。
  代价不是"少一条红"，而是**一半机器上 `make vet` 那 21 项根本没跑过而退出码看着像失败**。
- **改的三样**：Makefile 写死 `SHELL := /bin/bash`（与 `scripts/` 下 26 支脚本的 shebang 同口径）；
  `check-script-syntax.sh` 扩两半（断言 `SHELL := ` 声明位在 + 抽 recipe 行 `bash -n`，抽不到行就**出声**不静默绿）；
  判据页新增一行（档位 `部分`——**声明位与语法拦得住，方言拦不住**，`<(...)` 在 bash 下合法，
  方言那一半靠 CI 这台非 bash-sh 的机器实跑）+ 开发约定一条 + AGENTS §10 一条。
- **两个坑的共同形状**（这条是本轮真正的产出）：时区那条与 shell 那条都是
  **开发机的属性被当成通用事实**（本机 `/bin/sh` 是 bash、本机时区是 UTC+0000）。
  所以"本地 `make build` 绿"从来不等于"门禁跑过了"，只等于"在这台机器上没报错"——
  这正是接 CI 的理由，也是 CI 在两天内交出的两条回报。
