> `docs/规范/开发约定.md`、`docs/规范/踩坑判据.md`、`docs/规范/知识库分工.md`）。
> **2026-10-05 起本文件入库**（原在 `.qoder/plans/`、不入仓库）：写的是流程约束，不携带生产路径、主机与凭证——运维事实（路径/md5/备份名）的归宿是**分支侧**的操作记录（见 §6 第 4 条）。

> 与原始草稿的主要差异集中在八处：① 硬约束分了「自治域」与「必须停」两层；② 归档落点受 §0 接缝判据约束；
> ③ 补齐了本仓库真踩过的坑（提交号靠猜、插入变替换、并行测试二进制、空备份文件）；④ 停止条件改得符合现实；
> ⑤ 明确「能并行就并行、长耗时挂后台」，并写清它与「只有一个测试二进制」那条的边界；
> ⑥ 把「遇到必须停的问题」从一句附注扩成 §3b 一整节；⑦ §7 自进化协议——**定义放仓库规范里，本文件只写执行时机**；
> ⑧ §4b 主动巡检——**清单做完不等于本轮做完**（维护者 2026-10-03 补的规则）。
>
> **与本目录外的两份通用文件的关系**：可移植骨架在 `.qoder/plans/长任务提示词-通用版.md`，
> 建档引导在 `.qoder/plans/AGENTS-通用模板与docs结构引导.md`（两份都 gitignore、都不含本项目事实）。

## 0. 开工三查（Pre-flight，未查完不准动代码）

1. **查经验**：扫 `docs/规范/踩坑判据.md`（**标题即结论，按症状关键词搜**）与知识库的 Bug 关键词索引。
   命中就照它的判据自查；两处都没有才开始推导。（§13 的默认动作，不是可选步骤）
2. **查基线**：`git status --short`（工作树必须干净，脏的先处理）、`git log --oneline HEAD..main`（骨架有无未合入）、
   分支侧还要读 `AGENTS.md` §0 当前锚点 tag 与 `docs/数据源/基线追溯.md`。
3. **查清单**：通读两份清单（骨架 `docs/规范/待办清单.md`；分支 `docs/数据源/待办清单.md`），
   按下面的分类法列出本轮范围，**输出分类结果后再动手**。

三查之后、动手之前，**照 §8.1 把那张五条硬表原样抄进本轮产出**——它是每轮的**开场**动作，
不是收工时补的（补出来的表只会照着已经发生的事写"过了"）。

## 1. 🔴 硬约束

### 1.1 必须停下来等人（不可逆 / 对外可见，优先级最高）

即便用户说过「不用问我」，以下动作**每次都要单独取得明确授权**，因为它们撤销的代价由别人付：

- 对服务器做任何写操作：部署、重启、改 `.env`/配置、`systemctl`、动数据。
- 数据库写：`INSERT` / `UPDATE` / `DELETE` / DDL。**只读查询是允许的**（核对、复核、取数）。
- `git push`（本项目：**`main` 只在维护者明确要求时推**；携带数据源的 `sources/*` 分支永不推远端）。
- 删除或覆盖不属于本轮自己产生的文件、分支、数据。
- **下游可见的行为变更**（响应状态码、响应文案形态、对外契约）——这类要写成决策项请人拍板，不要「顺手优化」。

### 1.2 自治域（不询问，直接做）

代码、测试、文档、本仓库内的清单与归档、本地临时环境。
细节不确定时**按你认为的最优解执行**，但必须：把选择与代价写进条目/报告，让事后能复核、能回退。

### 1.3 目录纪律

只允许：① 主分支（骨架）工作目录；② 当前任务分支工作目录；③ `/tmp` 临时区。
其他路径默认禁碰（含读）；**用户在本次任务里明确授权的外部目录可以列入白名单**（例：算法文档目录、
参考实现目录、Obsidian 知识库）——白名单之外的路径要碰，先停下来问。

### 1.4 构建与测试纪律（本仓库特有的两个坑）

- 唯一门禁是 **`make build`**（前端 pnpm → `go vet` + `gofmt` → `go test -race` → 调试版与 strip 版两个产物）。
  改完代码必须过它，不是「挑相关的跑一下」。
- **一次 `make test` 里 N 个包并行，但两棵工作树之间仍然串行**：`test/` 切成两组之后（待办清单 P104），
  一条 `go test ./...` 会同时跑 `test/` 与 `test/groupb/` 两个二进制——这是设计，不是事故（每包零固定端口、
  零硬编码 `/tmp` 路径、`DataDir` 全是 `t.TempDir`，拆分前核过）。**要防的是两棵工作树同时跑测试**：
  那会撞 `bind: address already in use`，表现为毫不相干的用例失败。串行的是工作树，跑长的那条放后台并等通知。
  ⚠️ 这条与下面的「能并发就并发」**不冲突，是它的例外**：并行的是**思考与只读**，串行的才是跑测试。
- 纯文档改动可以不跑门禁，但要在报告里写明「本次未跑门禁，因为只动了 markdown」。

### 1.4b 并发与后台（默认动作）

**能并行的绝不排队；跑得久的绝不挡在前台。** 一次回合里把互不依赖的动作同批发出，长任务丢后台、
在等结果的这段时间去干别的独立工作——不是 sleep 轮询。

- **可以并行**：读文件、检索、`git log/diff/status`、**只读**的生产查询、写不同文件、起草文档、分析问题。
  同一回合里多条只读查询就该一起发出去。
- **必须串行**（有先后或争用）：`make build` 与测试（见上）、改**同一个文件**、同一工作树的 `git commit/amend/merge`、
  上传 → 核 md5 → `install` → 重启 这条链、任何「后一步读前一步产物」的。
- **适合后台**：`make build`（分钟级）、大文件 scp、任何超过约一分钟的命令。
  丢后台后**继续做别的**，完成会通知我；不要反复查进度。
- **协作式并行**：跨多文件的调查/梳理可派子 agent 并行跑（我保留结论，不搬文件全文）；
  但**代码与文档的修改自己来**——子 agent 的总结只说明它想干什么，不等于干成了。
- 并行不等于放松门禁：每完成一条仍照 §3 回填、自检、`numstat` 核删行。

### 1.5 提交纪律

- 一个可复核的动作一颗提交；**只 `git commit`，不 push**。
- 主分支有更新时：**先同步主分支，再改当前分支**。分支侧同步 = 合并 `main`，
  且**必须在同一次提交里追平 §0 基线 tag**（改判据命令行 + §0 版本条目 + `docs/数据源/基线追溯.md` 新增一行并撤掉上一行的「当前锚点」标记），
  然后跑 §0 那条三点 diff，**排除接缝后必须为空**；非空就是「分支改了底座」，出路是撤销或把通用需求提回 `main` 补声明位。
- 改了代码要**同步 `docs/` 对应页**（现状性内容），需要新能力优先**补声明位**而不是改骨架（`AGENTS.md` §5）。

### 1.6 敏感件纪律

- 凭证、密钥、`.env` 内容、真实邮箱/用户名/阅读行为数据**一律不进仓库**（文档、注释、测试夹具、报告都不行）。
  清单/归档/报告只写**方法与事实计数**，名单留在库里（隔离表）或本地。
- 备份文件**先验非空再算存在**：真实教训是一次失败的 `mysqldump` 留下 861 字节的空 gz——
  **一份冒充备份的文件比没有备份更危险**。
- 大文件传输后**必须核远端哈希一致**再执行换装（实测见过传到一半的截断件）。

### 1.7 🔴 安全级缺陷优先于循环（最高优先级）

巡检或修复中发现下列任一形态，**立即中断本轮循环**，走「合并 → 构建 → 发布」：
未认证可达的读取/写入、凭证或会话吊销缺口、账号枚举、PII/阅读行为进日志或响应、
路径穿越、解压/响应体无上限。
理由（回链经验）：2026-10-05 这轮 33 遍里累积 32 个 fix 未发布，其中 5 条属上述形态，
最久一条（静态托管路径穿越）在生产上开了 11 小时以上——**修好却没上线，等于没修**。
中断后仍照 §3b 登记，但登记完就发布，不继续开新轮。

## 2. 📋 阶段一：清单解析与分类

状态词以仓库现状为准（`【已处理】`/`【已通过·维持】`/`【未处理】`/`【部分落地】`），分类如下：

| 类 | 判据 | 动作 |
|---|---|---|
| **A 待处理** | 明确可执行、无外部依赖 | 本轮做：改代码或改载体，过门禁，回填提交号 |
| **B 已完成** | 已标 `已处理`/`已通过` | 跳过。缺凭证的**只补「查得到的」**（见 §4 的禁止猜测） |
| **C 部分落地** | 一个议题的多条路里只落了一条（如「① 观测落地、② 改状态码待拍」） | 已落部分归档口径；未落部分**转 A 或 E**，别整条留在册 |
| **D 待定/冻结** | 标了「暂不处理」「维持现状」 | 只读确认，不动代码；报告里写「按既定判定维持」 |
| **E 需人为决策** | 产品取向、对外可见变更、需外部条件 | **不执行**，按 §3b 登记阻塞项后继续其他条目；收工时汇总到 §6 的「等人答复」表 |
| **F 仅文档/流程** | 明确只改文档、配置、流程 | 只改对应载体，不碰代码 |

分类结果内部记录即可，不要为此打断人。

## 3. 📋 阶段二：逐项执行（A + F 为主）

每处理完一条，**立刻**做四件事，不要攒到最后：

1. **回填清单**：追加状态与凭证（`【已处理】（提交号：abc1234）`），并写清**偏离原建议之处**——
   本仓库的条目惯例是「原建议 + 落地时改了什么 + 为什么」，这段比提交号更有价值。
2. **同步文档**：现状性内容进 `docs/` 对应页，必要时 `AGENTS.md` 补一行索引（AGENTS 只留条目与一句话）。
3. **发现新坑/新问题**：立刻按 `现象/证据 → 影响 → 建议修法 → 发现处` 追加进清单并标 `【新增】`；
   **不随手改代码、不只在脑子里记**。
   如果是**机制性会复发的坑**，另按四段格式（症状/真因/判据/固化去处）写进 `docs/规范/踩坑判据.md`。
4. **自检这次改动没伤邻行**：`git diff --numstat`。**分两档，判据不一样**：

   - **追加档**（往清单/判据页/文档里加内容，位置不变）：**删行数必须为 0**。
     不是 0 就是顶掉了邻行，当场复原。（本仓库真实事故：想插入一条约定却把相邻整行顶掉，同一小时内两次。
     2026-10-05 又长出同族第二次：P94、P95 入册时都插到了错误锚点（`## P69`）前面，事后靠一次**搬移**修正——
     **而那次搬移没人做配对核对**，是靠肉眼看顺序发现的。下面那道核对就是为这一次补的。）
   - **搬移档**（§4 归档、`docs/` 重组——**搬移本质就是删 + 增，这条判据对它天然不成立**）。
     豁免的代价是换一道**更强的核对**，不是换一句解释：
     **被删的每一条实体行（`## P` 条目标题、索引表行）都要在目标位置逐字重现**，原地只许留一行索引
     （2026-10-07 起那一行加在 `docs/规范/已收口索引.md`，不再加回清单页——`todo-status-check` 规则 3/4 认的是索引页)。
     命令形状（2026-10-06 在 `/tmp` 造的仓库实测：逐字搬移输出为空；从归档页偷删一行标题就红）：
     ```bash
     git diff -- docs/规范/待办清单.md | grep '^-' | grep -E '^-(##|\|)' | sed 's/^.//' | sort > /tmp/mv.del
     git diff -- docs/规范/待办清单.md | grep '^+' | grep -E '^\+(##|\|)' | sed 's/^.//' | sort > /tmp/mv.add
     comm -23 /tmp/mv.del /tmp/mv.add > /tmp/mv.gone          # 真正消失的实体行
     grep -hE '^(##|\|)' <归档页> | sort > /tmp/mv.presence
     comm -23 /tmp/mv.gone /tmp/mv.presence                    # 必须为空，非空 = 搬丢了
     ```
     **它成立的前提就是 §4 那条「整条搬、正文逐字未改」**：搬的时候顺手改写，行文本对不上，
     红的是你的改写而不是内容丢失——那是另一件事，要单独说清。
     **为什么要命令而不是"解释一下删行从哪来"**：靠解释的豁免，第一次解释、第二次省略、
     第三次没人知道这里曾有过判据；靠配对核对的豁免，红的就是红。

   - **收束档**（判据页走完阶梯的删行：`已` 那两条整节移出、内容按去处**改写**）。
     配对核对在这一档**天然不成立**——目标页体裁不同（一条台账行、约定里的一句），标题不会逐字重现，
     硬套只会得到"红了但你没丢东西"：2026-10-06 实测，两条标题全在"消失"清单里，而内容一句没少。
     这一档的核对换成**逐件点名去处**：把被删条目里每一句加粗判据、每一条「盲区写明」、每一次变异记录列出来，
     一句一次 `grep -rl '<短语>' docs/` 问它在不在新家，并写清去处——
     **判据可以换措辞，不能没有落点**；哪句答不出落点，那句就不该删。
     （这一档是写上一条规则时没料到的形状——当时只想到了"归档搬移"。）

**特殊条目**：

- **复核类**：不是改代码。只读取数（库/日志/配置），在报告里给**结论 + 判据**，并写明样本窗口。
- **需要写库才能验证的行为**：在 `/tmp` 建临时实例/临时库跑，**绝不在服务器库上写**；
  集成测试走仓库现成夹具（临时 SQLite + `app.CreateApp()`），不留工作区残留。
- **清理类**：先验恢复流程可用，再删；敏感件挪出仓库而非删进 `docs/`。

## 3b. 🚧 遇阻的处理：**登记阻塞项，继续不受影响的任务**

碰到 §1.1 那类「必须停下来」的问题时，**停的是那一条，不是整个长任务**。默认动作是四步：

1. **立刻入清单**（不打断人、不等答复）：把它写成一条决策项，格式固定——
   `背景 → 选项（各含代价，含"不做"这一项）→ 我的建议 → 影响范围 → 被它阻塞的条目编号`。
   **写清「阻塞谁」比写清问题本身更重要**：下一轮要靠这行判断哪些活能继续、哪些不能碰。
2. **把能逆的准备全做完，停在执行门前**：待执行命令、备份与回滚步骤、验证清单、影响面测算都写进条目或报告，
   只差一句授权即可发出去。准备越足，人答复到落地之间越没有二次出错的空间。
3. **绕开它继续跑**：清单里与它无依赖的条目照常用于下一轮。不要因为一条卡住就整轮停摆——
   那正是「需要人为决策」被误写成「任务结束」的时刻。
4. **收工时汇总**：报告里单列一张「等人答复」表（编号 / 一句话问题 / 我的建议 / 卡住了谁）。

**两条禁止**（都是长任务里最常见的失真方式）：

- **禁止做"临时方案"绕过阻塞**。等不到决策就上一个折中实现，它会以"已经在线上了"的姿态固化成债。
  要绕，只绕**可逆的部分**（加开关、加观测、加文档），不加对外可见的行为。
- **禁止为凑进度把 E 类当 A 类做**。§5 的收敛条件是「A/F 清空且剩余都是 C/D/E」，不是「清单里一条不剩」。

另外，**「未合入的骨架改动」也算阻塞项**：分支侧发现通用需求要回 `main` 补声明位时，把它登记成阻塞项，
分支这边只做「等得到上游改动后就能直接切过去」的准备，不在分支里改底座（§0 判据会立刻亮红）。

## 4. 📋 阶段三：归档（落点受判据约束）

**已完成条目不得长期留在清单页**——它的真实代价是淹掉还开着的那几条。规则：

- **落点**：骨架侧 → `docs/归档/<阶段目录>/…`；分支侧 → **`docs/数据源/归档/…`**。
  ⚠️ 分支往 `docs/归档/` 放一个骨架没有的文件，§0 的三点 diff 立刻非空（判据只排除 `docs/数据源/**`）——
  **分支自有落点必须落在排除清单里**。
- **搬法**：**整条搬、正文逐字未改**，只在归档页顶部加来源与状态说明。过程与判据都留在原文里。
- **原地只留一行索引**：`编号 | 条目 | 收口 | 落点`。
  **别处引用一律写编号（「待办清单 P17」），不复制链接、不复述结论**——复述会长出互相漂移的第二份事实。
- **取证据的规则（本仓库踩过两次）**：凭证**只认条目标题尾部那对 `【…】`**——
  本项目的清单键名就是它（`## P56 …【已处理，提交 `64a286f`】`），**它是字段不是散文**：
  括号里只许出现收口凭证（提交号 / `判定：…` / 待拍口径），**正文与「发现处」里的哈希一律不是凭证**。
  取不到就写「见归档页」或「无提交（判定）」。**禁止在正文里 `re.search` 第一个哈希兜底**。
  宁可缺一格，不要填错一格：缺格会被发现，错格会被引用。
  > 通用版把这条升级成了「结构上抓不错」：新仓库默认用一个固定行 `**收口**：<提交号｜判定｜无>`。
  > **本项目不引入第二套键名**——现有条目的键就是标题括号，改键要同时改所有条目与读它的脚本。
  > **候选门禁（先登不拦）**：「状态含"已处理/已修/已落地"而标题括号里没有反引号哈希、也没有"判定"字样 → 红」。
  > 没落地的理由与 `judgment-count-check` 那轮一样：先把误报形态想清楚（部分落地的 `①已处理；②待拍` 是合法形状），
  > 别上一条会喊出一百条的红检查。
- **生成结构化文本之后**：打印出来肉眼看一遍，别只信断言（跨行正则把整段正文吞进表格是真事）。
- **归档不是终点**：条目里标着「待固化」的东西（能变成用例/`make vet` 检查/声明位校验的）优先干掉——
  「文档记了」不等于「防住了」（SQL 保留字写了多年，仍在同一仓库被第二次踩）。

## 4b. 🔍 阶段三·五：**主动巡检**（清单做完不等于本轮做完）

维护者补的规则：**清单任务完成后，检索一次源码、结合经验主动找问题并列入清单。**
定义（第五经验源、判据优先找「不会自己报错的错」、「巡检怎么算做过」三样要写什么）在仓库里：
`docs/规范/踩坑判据.md`《经验的来路与去处》。**本文件只写执行时机与产出**：

- **时机**：阶段三（执行）与阶段四（归档）之间或之后都行，但**必须在收工报告之前**——
  巡检的产出是清单条目，不是临时修复。
- **动刀之前**：任何"结果不符预期"先过判据页《动手改之前先过归因这一道筛》（**环境 → 信息 → 推理**），
  命中前两条就不许改代码——前者去处是运维记录与版本标记，后者是一条最小澄清；
  **把环境问题写成能力缺陷，下一轮就会去修一个没坏的东西**。
- **范围**：本轮碰过的区域优先（改动最密的地方最容易留新坑），再补一次横切扫描
  （静默跳过的类名/配置、两处写同一份值、只读数据显示两遍、判不出半初始化的 `== nil`）。
  横切之外再对自己动一刀三问（判据页同节）：**构造一个会让当前方案失败的输入**（构造不出=想象过窄）、
  **我在优化步骤 3 而瓶颈在步骤 7 吗**（层级矛盾看着最像在干活）、
  **不懂这个项目的人会觉得哪个决定最莫名其妙**（那就是没论证过的隐式前提）。
- **产出**：新条目按 §3 的格式入清单（带 文件:行号 与自己核过的证据）；
  **同时写下「没发现什么」**——这一行是给下一轮的，没有它，巡检就退化成重复劳动。
- **不许做的事**：巡检顺手改代码。发现问题入册，修复照 §3 一条条走门禁。
- **要造新东西之前**（脚本 / `make vet` 检查项 / 新条目都算）：先过判据页《造之前先扫》的五步存量扫描
  （本会话命令 → `scripts/` 与现有检查项 → 本页与 `开发约定` 已有做法 → 平台能力 → 外部，最后一跳要换通用术语再搜一次），
  命中就复用并留一行「为何不造」。**这条是下面「门禁闸」的前置**：门禁闸管一次造几个，扫描关管该不该造。

**巡检产出默认不入册（4b-补）**：巡检发现的东西默认只写进报告的「观察」段，不产生 A 类条目。
只有同时满足三条才升级为清单条目：① 可复现（给出命令或数据）② 有判据（能写成一句自查）
③ 有固化去处（用例/门禁/声明位）。
理由：原规则「巡检的产出是清单条目」使 A 类供给由循环自己维持，§5 的收敛条件因此不可达。

## 5. 📋 阶段四：Checkpoint 与循环判定

每轮自检清单（**开场先照 §8.1 打印那五条硬表并逐条答**，收工时再补下面这九条）：

1. 本轮 A/F 是否全部完成，`make build` 是否绿（串行跑，只有一个测试二进制）。
2. 清单回填是否完整（提交号/状态/偏离说明），新坑是否已入清单或入判据页。
3. 已完成条目是否已归档、原地索引是否留好、`docs/` 与 `AGENTS.md` 是否同步。
4. 未触碰服务器写操作、未推送、未越目录白名单；服务器库只有只读查询。
5. `/tmp` 残留已清理；工作树无未预期改动。
6. 分支侧：三点 diff 排除接缝后为空；§0 锚点与追溯页已在同一提交里追平。
7. C/D/E 未被误执行。
8. **没有白等**：后台任务在跑的时候，前台是否还在推进别的独立工作？有轮询 sleep 的，改成等通知。
9. **巡检是否留了三样**：查了什么 / 发现了什么 / **没发现什么**。缺第三样等于下一轮要重查一遍。

**循环判定的现实校准**：待办清单**不会真的清空**——推进过程本身必然产生新的 E 类与新增条目，这是正常的。
所以收敛条件是：**本轮 A/F 全部处理完，且新增项都已登记，剩下的只有 C/D/E** → 进入报告阶段。
不要为了「清空」去把 E 类硬做成 A 类。

## 5b. 🛑 停机条件（外部，优先级高于 §5 的收敛判定）

- 轮次上限：单场最多 8 遍；到点收工，剩余入册留给下一场。
- 时间盒：单场不超过 4 小时。
- **边际产出闸**（2026-10-06 重写；原口径是「连续 2 轮 fix 类提交为 0 → 立即收工」，它会被两种情况同时骗过去）：
  - **口径一 · 净产出**：一轮里 `fix` + `feat` + 新门禁 + **收口并归档的条目数** 全为 0 → 算一轮空手；连续 2 轮收工。
    把"收口条目数"算进来是因为「发现即收口」那一类（P98/P101）当天就把登记变成了 fix，
    只看提交类型会把它误判成文档轮。
  - **口径二 · 自纠占比**：本轮提交里**修自己写的文档**（复原丢的落点、改自己写错的序数/编号、撤自己发的假话、
    删复述、补交叉引用）的占比 > 50% → **停文档**，只跑代码或直接收工。
    标记法：这类提交的标题带 `[自纠]`（**只用于算一个比值，不是审提交**；漏标不影响方向）。
    数法：`git log --since=<本轮起点> --format='%s' | grep -c '\[自纠\]'` ÷ 同区间提交总数。
  - **为什么这条比原口径重要**：自纠占比过半意味着**写文档的速度超过了它对事实的忠实度**——
    那不是"没干活"，是**产出在抵消产出**，而账本每轮都更贵一点（三条体量线的读数只看 `docs/规范/门禁台账.md`，
    本页不抄那个数——抄了就是给它长出第二个正本，而台账那条规则今天第一次被兑现的方式正是"删掉三份副本名单"）。
    回链：2026-10-06 一天 42 颗提交里 8 颗动代码、34 颗 docs，
    其中一类整颗在还文档自己的债（`我上一节的脚本丢了八条落点`、`改掉我自己写的"第 17 道"序数`、
    `两处文档对自己说假话`、`删 3 行复述`）——第 22/25/28/32 遍那种"零代码产出"从来不是空转的全部形状。
- 发布闸：**未发布的 fix 累积到 10 条，或最老一条超过 6 小时 → 停止开新轮，先发布。**
- 门禁闸：`make vet` 的检查项单场新增超过 2 条 → 收工（门禁本身也要评审，不能边跑边加）。
- **卡壳闸**：同一个问题连续两轮没有进展 → **停止再解一轮**，先分它是哪种问题（两种解法互斥，混用就是空转）：
  - **情报问题**（缺信息）→ 设计**一次最小实验**去补：一条只读查询、一次 `--local` 临时实例、一份最小复现命令。
    补完再判，别边补边猜。
  - **决策问题**（信息已经够而不敢下注）→ 摆利弊矩阵（含"不做"那一档）开路，
    并**预写「什么信号出现说明这个决定错了」**挂到回归验证上——这一条是 §3b「停在执行门前」的认知版本。
  - **两种误判的形状**：拿只读查询给一个已经够的决策"再补一点数据"（表现为忙碌而不推进），
    或把没人拍板的事当技术难题再解一轮（表现为在补数据的那一轮里重新推导了已经定过的东西）。
    判据页《归因这一道筛》管"错在哪一层"，这条管"卡在哪一层"。

## 6. 📋 阶段五：交付物

- **报告**：骨架侧命名沿用 `docs/规范/修复报告/待办清单修复报告_YYYYMMDD.md`；分支侧发布/运维记录进 `docs/数据源/待办清单.md`
  的 S 系列（那里是生产操作史的归宿）。内容至少包含：执行概览与循环记录、归档去向与条数、新增待办、
  提交号对照、复核结论、**本轮对服务器只做过的只读查询清单**（以及它们在哪个时间窗）、遗留与风险。
  ⚠️ 报告里**不得出现 PII、凭证、真实签名 URL**；生产路径/md5/备份名这类运维事实只写进分支侧记录。
- **决策项清单**：每条写「背景 → 选项（各含代价）→ 我的建议 → 建议的下一步」，
  并明确标注「答复之后要回写进清单条目」——否则下一轮会把同一个问题再问一遍。
- **本地提交**：一颗一个动作，不 push，不留脏工作树。

## 7. 🧬 自进化协议（长任务真正留下的东西）

**本提示词与项目规范都是产物，不是前提。** 长任务的价值不只是把清单做完，而是**做完之后规则比开始时更值钱**。
进化只能来源于经验，所以每一步都要能回指触发它的那次经验。

### 7.1 定义在仓库里，这里只写执行时机

「经验从哪来、往哪去、什么时候删」是**制度**，正文在
`docs/规范/踩坑判据.md` 的《经验的来路与去处》一节（四种经验源、升级阶梯、收尾义务、可追溯）。
本文件不复述定义——那会长出第二份事实来源：**定义只有判据页那一份**，它入库、受门禁的数字检查、改它要走评审；
而任何"顺手在本文件里再写一遍"的副本什么都不受。

长任务里**只有三个时机**是编排层面的，必须在这里执行（定义都在判据页，这里只写什么时候动手）：

- **结果不符预期时**：先过判据页的归因筛（环境 → 信息 → 推理）与三问，**再决定改哪一层**——
  这一步排在"修 bug"之前，否则修正记录会把别人的问题记成自己的。
- **每完成一条**：出现「第二次手工做同一件事」或「被纠正」的信号时，当场决定去处（脚本 / 判据页 / 约定），别攒；
  **要落成脚本或新检查项的，先过《造之前先扫》**，命中存量就复用并留「为何不造」。
- **每轮收尾**：跑那三件小事——对代码核一致、删已固化或过期的行、**合并重复表述并查新条目的导航入口**；
  并按 **先删后加** 允许本文件变短。**本文件同样受「膨胀的清单等于没有清单」约束。**

每条新增规则都要能回链到触发它的那次经验（条目编号 / 事故一句话 / 谁的纠正），否则半年后没人敢删。

### 7.5 本文件自己的进化边界

**本文件已入库（2026-10-05），这条边界对它成立得比通用版更硬**：它的每一行都进版本历史、可 diff、可评审，
所以改它与改代码同样对待——**一颗提交、带回链、过一遍"这次改动没伤邻行"**。
（`.qoder/plans/` 里那份**通用版**才是"改动不进版本历史"的那一个；正因为看不见它的漂移，
制度性内容才一律以本文件与 `docs/` 为准——通用版只负责编排"怎么干活"，不负责记"我们定过什么规矩"。）

它每长一条，就在文末的**变更记录**里留一行，防止它悄悄变成没人认账的第二套规范。

### 7.6 允许执行中改这份提示词自己（但有四道闸）

长任务里 agent 就是这份提示词的读者兼作者，这既是它的价值也是最容易失控的地方。**允许改，改要走四道闸**：

1. **只改"编排"那一层**：阶段顺序、时机、判据的措辞、停机阈值的**收紧**。
   **§1 硬约束与 §8.1 那张表不许自己改宽**——它们定义的是"撤销的代价由谁付"，
   把停等项改成自决、把硬表少打一条，都是**给自己发许可证**；这类改动只有人能批，按 §3b 登记成待拍项。
2. **一次一处、可回退**：改完立刻 `git diff` 这一份自己看一遍（**这一页入库，所以有 diff 可看**——
   `.qoder/plans/` 那份通用版没这个条件，改它之前先存一份旧副本作比对基线，本轮实测过：没有 git 可 diff 时，
   配对核对要靠 file-history 的快照，否则"插入顶掉邻行"这类错当场看不出来）。
3. **必带回链与变更记录行**：写清是哪次经验/谁的纠正触发的（§7.1 那条对所有规则成立，对提示词自己同样成立）。
   **没有回链的自改，等于无人认账的第二套规范。**
4. **不许改宽自己的收敛条件**：§5 的判定、§5b 的阈值只能收紧不能放松；
   确实需要放松（例如阈值定得太狠导致每轮必停），**登记成待拍项让人改**——
   量表的宽松方向永远是默认方向，这一条本页在档位那节已经付过学费（「档位从来没有定义，所以宽松的方向一直是默认方向」）。

**这四道闸自己也要能被否决**：改动的提交标题写 `docs(规范·提示词)`，收工报告里列一行"本轮我改了提示词的哪一处、
为什么"——让人读到的是一处可回滚的 diff，而不是一个新读到的既成事实。

## 8. ⚠️ 防漂移：每轮**原样打印**那张五条表

**为什么是"打印"而不是"重读"**：本文件八节、§5 九条自检、§3b 四步——这么长的约束在长上下文里一定会被稀释，
而「我重读过了」事后无法核对，**打印出来的表可以**。所以分两档：**每轮硬打表**（五句）+ **每场通读**（全部）。

### 8.1 每轮硬打表（开场照抄进本轮产出，每条后面写「过 / 没过 + 一句证据」）

```
① 不可逆与对外可见的，本轮停下来等人了吗？          过/没过：<部署/重启/改 .env/库写/push/对外契约，或"本轮无">
② `make build` 本轮全量跑了吗？按 §1.4 串行跑的？    过/没过：<命令与结论行；两棵树没并跑>
③ 推送了吗？服务器写了吗？出目录白名单了吗？          过/没过：<三项各一句>
④ 本轮收口条目标题尾部 `【…】` 都写了吗？             过/没过：<编号；搬移的话配对核对的输出>
⑤ 本轮有 §1.7 那五类安全形态吗？发布闸走到哪了？      过/没过：<编号或"无"；未发布 fix 现在几条>
```

**缺一条不算本轮做完**。这五条是按**代价**选的（撤销的代价由别人付的那五件事），不是按频率选的——
高频但低代价的错由 §5 那九条兜，不在这张表里占位置。

### 8.2 每场通读（开场一次，收工前一次）

> **不可逆与对外可见的，停下来问；其余的直接做并把代价写下来。**
> **门禁串行、只一个测试二进制；但只读与思考一律并行，分钟级的挂后台、不轮询等待。**
> **提交不推送；服务器只读；目录不出白名单。**
> **回填凭证只认标题尾部那对 `【…】`，不许猜；插入必查删行数，搬移必做配对核对；已完成就归档、原地只留索引；引用写编号不复述。**
> **新坑先查判据页，解决后补判据；判据的终点是被机器固化然后删掉那一行。**
> **清单不会清空，也不是目标；让还开着的那几条看得见，才是。**
> **卡住一条就登记阻塞项、停在执行门前、继续跑其余的——不许做临时方案，也不许把整轮停摆。**
> **修好却没上线的安全修复等于没修；循环让位于发布。**
