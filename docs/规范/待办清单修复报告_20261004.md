### P48② 上限类设置里的 `0` 到底是什么意思

- **背景**：`max_active_sessions` / `device_watch_window_days` / `suspect_distinct_ips` 三条走同一个整数读取口
  （`db.SettingInt`，P61 起三条并一）。
  ① 已落地：填了不生效的值会**出一条日志**（同一种替换只喊一次），但**语义照旧**——0 仍被当"没配"、按默认 5/7/8 走。
- **选项**：
  A **0 = 不适用（维持现状）**：代价是"管理员填 0、系统按 5"这件事仍然要靠日志才知道，面板不回显生效值。
  B **0 = 关掉该项容忍（会话上限 0 → 每次登录收口到 1）**：代价是**踢人开关的上限填错就能一次登出所有人**，
  把一次配置失误变成一次现网事故；而且它与已有的 `device_watch_enabled` 开关**语义重复**（要关就该有个开关，而不是把数值压成 0）。
  C 不做：维持 A 的行为 + ① 的日志。
  **P63 给这一问补了一个实例，方向与 A 相反**：携带形态里 uxx 的标定边界用 **0 当哨兵**
  （`hi == 0` 意思是"还没有上界证据"），而冷却值也可以被管理员设成 0 表示"不设冷却"——
  也就是说"0 算什么"不是全局可拍的，它**按键不同**。所以这一问的落法应当是"读的那条函数名"而不是"一个全局口径"

### P64 `/endpoints` 在默认配置下必然 401：网关开关与逐端点的归属要求撞在一起

- **背景**：`app/app.go:484` 把 `/endpoints` 挂在 `apiauth` 上，处理函数自己再要求 context 里有 `user_id`

  而那句文案是裸的英文 `unauthorized`。同一条 JWT 打 `/auth/me` 是 200，所以不是 token 的问题。
- **现网状态（数出来的，不是猜的）**：匿名只读一发 `GET /endpoints` 拿到的是**中间件**那句

  ⇒ 生产 `AUTH_ENABLED=true`，**这条缺陷在现网休眠**，亮着的是新部署与本地/测试配置。
- **选项（各含代价）**：
  A 这条路由改用 `utils.AuthenticateAny`（必须有归属账号：会话 JWT 或账号级 API Key）+

    `AUTH_ENABLED=false` 的部署里这条端点仍拒匿名，只是从"必然失败"变成"带凭证就行"。
  B 拿不到 `user_id` 时退回"公开清单"。代价：把按套餐过滤的治理信息变成公开面，同一端点两套口径。
  C 让 apiauth 在网关关闭时也解析并注入身份。代价：**动全局凭证语义**，
    所有挂在 apiauth 后的处理函数都可能从"拿不到归属→401"变成"拿到归属→按某账号走"，风险面远大于这一条端点。
  D 不做，只在 `.env.example` 与文档里注明"关掉网关时 `/endpoints` 不可用"。
    代价：明知有一个默认配置就会让一整块 UI 失效，用一句注释放行。
- **我的建议**：**A**（错误文案顺手改可读的中文）。**不选 C**——为一个端点改全局凭证语义，正是本仓反复讲的
  "改一处漂三处"；也**不选 B**——那块清单的价值恰恰在于它随调用者的授权变化。
- **影响范围**：`app/app.go` 一条路由的中间件 + 该处理函数两处 401 文案；**零 DDL、不改数据面、不改面板结构**。
