## 3. 三处执行时的判断，写明理由（比提交号更有价值的那一段）

### 3.1 P91 为什么没有用例
拍板的是"改代码、不写空转的用例"。follower 在 `continue` 之后通常会**自己变成 leader**，
新旧两种写法都在一次 `fn()` 后返回；要让它真的多等一轮，必须第三方每轮抢先占槽——那是时序竞争，
用例只会变成偶发红。所以这一条的正确性由读代码决定，风险放在"上游负载时序提前"那一侧，
它写在条目正文里而不是藏在提交信息里。

### 3.2 P94 的存量面靠的是第二半
写入端的新档位管不到**库里已有的旧形状值**。真正兜住存量的是发送端那个原本不存在的失败分支：
解不开就中止发码 + 一条带原始原因的 ERROR（对外仍是固定句「验证码发送失败，请稍后再试」——
`handlers/verify/verify.go` 早就按 P67 那对镜像处理了，本轮只是让它有东西可归因）。
另外确认过一件好事：`ApplySourceGroupLimits` **本来就要求显式 `limit`**（缺就 400），
所以 P69 把通用 CRUD 对齐过去，是消灭仓里唯一的异类，不是新立一条规矩。

### 3.3 P54 为什么连面板一起做
`/admin/stats` 加一格读数而面板不显示，就是 P58 那条「后端一直在发、面板从不显示」的复发。

那是 P25 的自省读数，从上线起没人读过。这条登记成新项 **P96**（E 类，UI 取向要拍）。

## 9. 续跑：P94 的面板档位，以及我上一轮自己开的一个口子

后端加了 `json_object` 之后，**面板并不认这一档**：`verify_http_headers` 走 `widget: 'secret'`，
而本地预校验的循环是 `changes.filter(f => f.widget === 'json')`、编辑弹窗的多行框是 `editItem.type === 'json'`——
两处都**静静跳过**这一档，坏值一路发到后端才 400。这就是 §4b 说的"不会自己报错的错"：构建绿、用例绿、面板能用。

修法与判据：
- 面板判"是不是 JSON 档"一律看**库里那一行的 `type`**（`GET /admin/settings` 本来就带 `type`），
  不自己抄第二份档位表（同 P46 那句"档位数字由响应下发"）；新增设置项的类型下拉补上 `json_object`；
  `json_object` 的键不再退回单行输入框——**多行粘贴正是坏形状的来源**，这个对照很讽刺。
- 本地校验按后端同一判据（对象且值全为字符串），坏形状不发请求。

**两档浏览器对照（同一把探针，只看 DOM 与网络事件）**：
| | 坏形状（数组 / 值写成数字） | 好形状 |
|---|---|---|
| 改前面板 | **PUT 真的发出去了**（`putCount=2`），错误由后端回给面板 | 存得下 |
| 改后面板 | `putCount=0`，toast「不是字符串到字符串的 JSON 对象，已取消保存」 | 存得下（`verify_http_headers` 一次 PUT） |

顺带把 P62 那句在浏览器里坐实了：这一格的 placeholder 是「已设置（内容不回显）——留空保存则保持不变」，
控件是 `TEXTAREA`；`verify_provider=mock` 时它置灰（切到 http 才可编辑）——**这些以前只有代码为证**。

### 9.1 那次对照还揪出我上一轮自己开的口子

我写的 400 文案是「当前值 %s 解不开」，**把管理员刚贴进去的令牌原值回显进响应**，面板再把它渲染进 DOM；
