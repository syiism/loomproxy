# 处理器自注册与数据源声明位

> 本页由 `AGENTS.md` §5 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

**新增数据源必须遵循：**

1. 源包落在 `sources/<源>`，在 `init()` 中：
   - `base.RegisterSource(base.SourceMeta{Code, Display, Category, Description, SortOrder, Status, Actions, FixedBaseURL, SearchTabs, LegacyGroups, DataFiles, MediaType, Settings, RequiredParams})` 声明数据源身份——这是路由对账、seed 播种（`data_sources` / `quota_costs` / `quota_limits`，含各内置套餐对该源的授权行）的**唯一事实来源**；
   - 声明位里 **`OnBoot func() error` 是装配后钩子**：`app.Run` 在 `conf.Load` 与 `db.Init` 之后、
     `pool.StartAll()` 之前按 `SortOrder` 顺序各调一次。源要读自己的环境变量开关、连库做初始导入、
     登记自己的号池，都放这里——**包 `init()` 里读不到 `.env`**（`conf.Load()` 在 `app.Run` 里才发生，
     而包 init 早于 main），症状是「在 `.env` 里改了却不生效」。钩子返回 error 或被 recover 的 panic
     都只记日志、不中断启动；它要写成幂等。用例见 `test/source_boot_test.go`。
   - **`RequiredParams map[string][]string` 声明每个动作的必填请求参数**（动作 → 参数名），由
     `middleware/source/reqparams.go`（链上 350）在**进 handler 之前**统一校验，缺任何一个直接
     `400 {"code":ErrorCode,"msg":"缺少必填参数: xxx"}`。为什么值得一个声明位：源自己判缺参的传统写法是
     返回 `legado.ContentResponse{ContentType:"error", Data:{message:"missing ..."}}` 且 error 为 `nil`，
     于是 HTTP 仍是 200 —— 下游 Legado 把那句「缺少参数」**当正文渲染进阅读器**，监控看到的是
     「成功 + 内容维度全空」（待办清单 P22、分支侧 S15）。三条约束：**排在 baseurl(300) 之后**
     （`baseUrl` 是解析出来放 context 的，不是请求带的）、**排在 access(400)/billing(500) 之前**
     （形态错误不该被套餐判定与计费走一遍，`succeeded()` 判的是 `status==200`，挡在这里等于顺手免掉扣额）、
     **未声明一律直通**（`search` 的空搜是合法形态，乱填会把正常请求判死）。声明了未声明的动作 →
     `RegisterSource` 期 `log.Fatalf`。用例见 `test/groupb/reqparams_test.go`。
   - 每个动作一次 `base.Register(name, factory, priority, metadata)`；
   - `FixedBaseURL: true` 表示上游地址写死在源实现内：该源路由不接收 `baseUrl` 参数、不做用户/平台配置回落，也跳过 SSRF 校验。
   - `SearchTabs` 声明自有搜索分类（多媒介/多站点形态）；不声明则 `/datasources` 下发底座通用 tab。**底座不按分类名做分支**，需要新形态请补声明而不是改 `handlers/catalog`。
   - `LegacyGroups` 声明该源历史所属的平台组码（组概念 2026-08-09 已移除）；seed 据此把存量按组码配置的行展开为本源码并清理组行。
   - `DataFiles` 声明该源附属的静态数据字典（文件名 + 说明）；`/data` 列表的说明列取自声明，底座不内置任何具体文件名。
     声明位有两个查询：`DescribeDataFile(name)`（取说明）与 `DeclaresDataFile(name)`（**有没有**被声明）——
     两者不能互相代替：声明可以不带说明，拿 `DescribeDataFile(...) != ""` 当"没声明"会把这类文件判成没人要的东西。
     声明还决定启动核对的范围（`CheckDeclaredDataFiles` 只查声明过的），代价见 `docs/运维/构建与部署.md` 的换装三查第 2 条：
     **没人声明却仍被请求的路径，只有请求期才显形**，那一半读数在 `handlers/catalog/misslog.go`（待办清单 P51）。
   - `MediaType` / `SearchTab[].MediaType` 声明**媒介**（`novel`·`audio`·`comic`·`video`，见 `base/media.go`），
     监控明细与 `/datasources` 都取此值。判定优先级（`base/legado/observe.go` 的短路链）：
     **响应自带**（正文 `contentType`、详情 `bookTypeCode`/`bookType`）> **请求 tab 命中的声明** >
     **同一本书的命名缓存** > **源默认 `MediaType`** > 空（未判定）。
     多媒介源（一站同时载小说/听书/漫画/短剧）**不要填源默认**，逐个 tab 声明才对；
     底座**不按 `Category` 推媒介**——那等于把数据源知识塞回骨架。
     声明值非法在 `RegisterSource` 期 `log.Fatalf`（源包 `init()` 都忽略 error 返回值，只回 error 等于静默放过）。
   - **`Settings []SettingDecl` 声明该源的自有设置项**（`{Key, Type, Default, Description, Sensitive}`）：
     这是「源要一个可热改、面板能编辑、又可能含令牌的配置」的通用声明位，底座不认识任何具体源键。
     声明之后由骨架统一办三件事——① `db.Init` 期把每项落成 `system_settings` 行（**行已存在只对账 `type`**，
     `value`/`description` 一律不覆盖，管理员填的值是最新的）；② `Sensitive` 的键登记进
     `db.SensitiveSettingKeys`（读接口回空串、写侧留空=保持原值，待办清单 P62）；
     ③ 行随 `GET /admin/settings` 下发，面板按响应的 `sensitive_keys` 渲染密钥控件。
     **读取仍由源自己走 `db.GetSetting`**——键的语义只有源知道，这一位只负责"声明与登记"。
     为什么要它而不是让源自己写：旧的绕过写法（`OnBoot` 里造 setting 行、自己往 `SensitiveSettingKeys` 塞）
     让键名与"有没有人读它"都不在骨架可见的清单里，面板会把这样的行落进「自定义配置」兜底卡、管理员看不见它归谁。
     两条约束：**类型必须在 `base.ValidSettingType` 的五档内**（`string`/`bool`/`number`/`json`/`json_object`，
     与面板写入端**同源**，免得"能声明"与"能保存"两份名单漂移）；**设置键跨源必须全局唯一**——
     两个源声明同一个键，谁先播种谁赢、另一个静默读到别人的值（症状是"我的配置改了没反应"）。
     两条都在 `RegisterSource` 期 `log.Fatalf`。用例见 `test/source_settings_decl_test.go`。
2. 处理器实现 `base.Handler`：`Handle(ctx, params)`、`GetPath/GetMethods/GetName/GetDescription/GetQueryParams/AuthRequired`、`PrefersIdentity`（**路由声明位**，对应 `BaseHandler.IdentityOptional`：命中鉴权白名单时要不要仍解析凭证——白名单免的是强制不是解析，见待办清单 P100/P64；默认 false，未声明的端点在白名单里拿不到身份是设计而非遗漏）；通常内嵌 `base/legado` 的基础处理器（复用 DTO 与上游缓存 TTL），或内嵌 `base.BaseHandler`（`NewBaseHandler()` 默认 GET、Auth 开、QueryParams 含 `api_key`）。
3. 携带清单加一行空白导入——**这份清单在装配仓 `loomproxy-deploy` 的 `sources/deploy_all.go`**（P116 定案：骨架的 `sources/` 是空包边界标记，`app.go` 只空白导入 `sources` 包本身，不因新源而改）。「本部署携带哪些源」由此一处决定。
4. 路由全部是根级 `/{source}/{action}`，无版本前缀。单路由中间件链由各中间件包的 `Def` 装配
   （`Applies` 决定挂不挂、`Order` 决定位置，常量集中在 `middleware/middleware.go`）：
   `apiauth(100，若 AuthRequired) → monitor(200，置于管控三轴之前以覆盖 403/429 与必填参数 400) → baseurl(300，resolve baseUrl：请求参数 → 用户配置 → 平台默认) → reqparams(350，按源的 RequiredParams 校验必填参数，缺失 400 且不进 handler) → gate.access(400) → gate.billing(500) → gate.ratelimit(600) → handler`。
   全局链同理由 Def 装配：`requestid → recovery → logging → cors → cachecontrol → ipblock`。
   **不要在 `app.go` 里逐行 `r.Use`/逐行 append 拼链**；装载集合是 `middleware/all/all.go` 的空白导入清单。
5. 需要凭证池的源在 §6 登记自己的号池，不要另写一套生命周期管理。

**测试夹具**：假源本体在 `testkit/fakesource`（三个假源 `fake_a`/`fake_b`/`fake_c`，动作集 search/detail/chapter/content/explore），处理器只做「按解析出的 baseUrl 取上游并原样返回」；`test/fakesource_test.go` 只在 test 包 `init()` 里调 `fakesource.Register()`，跨进程用例经 `cmd/fakegateway` 起同一套声明。三个假源各带声明覆盖不同形态（`fake_a` 的 `LegacyGroups`、`fake_b` 的 `DataFiles` + `Settings`、`fake_c` 的 `SearchTabs`）——`fake_b` 的 `Settings` 声明了密钥型与普通型各一个键，验证声明位的落库与敏感键登记。集成测试覆盖路由管线与 seed 播种全靠这三个假源——**它们只在测试二进制里存在，不属于产品功能**。新增管线类用例请继续用假源，不要引入真实书源依赖。
