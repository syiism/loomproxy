# 观测契约：信封与明细字段

> **正本页**（待办清单 P127① 拍定 2026-10-11：合并设计、正本在骨架）：骨架观察什么、
> 源必须往信封里填什么，集中在这一页。每格写清**期望内容、空值是不是合法状态、谁读它、
> 值由哪条用例守着（样本守卫）**。
> **变更规则**：信封与明细字段**增删必须同批改这一页**——与 `Settings`/`RequiredParams` 同形，
> 声明位是唯一口子。模型侧由 `make vet` 的 `observe-contract-check` 钉住
> （`models.ApiCallLog` 的每个 json 列与 `base.CallSubject` 的每个字段名都必须在本页出现，
> 改实现不改文档当场红）；**「源到底填没填值」机器检不了**，那半靠用例与样本守卫
> （判据页《断言空转》①），本页的「守卫」列就是那半的账。
> godoc 侧只有一段指路（`base/legado` 包注释），字段语义不复述在那里——第二份事实来源会漂移。
> 跨仓的阻塞关系（这条契约牵动装配仓的谁）见 [`跨仓阻塞与两阶段票据.md`](跨仓阻塞与两阶段票据.md)。

**留存同意位的一条总规则（P37 在 P122 上的判）**：用户关掉 `content_consent` 时，
`WithholdContent` 抹的是**内容维度**（`keyword`/`book_name`/`chapter_title`/`media`/`result_count`/两个 ident）；
`in_band_error`/`in_band_reason`/`in_band_code` **保留**——它们说的是「请求成没成、站方回了哪一档」，
不是用户读了什么。改 `WithholdContent` 的抹除名单必须同批过这一格。

## 三、信封侧：源要往响应里填什么

**空 = 没抽到 = 合法状态，读数按空处理、不猜**（`base/legado.ObserveCall` 尽力而为，
抽取失败只让维度留空，绝不影响响应）。多写法兼容的键取**第一个非空**：

| 动作 | 响应键（兼容写法） | 抽到什么 |
|---|---|---|
| search / explore | `bookList[]` 条目内：`bookId`/`u`/`url`/`bookUrl` ＋ `name`/`bookName`/`title` ＋ `bookType`/`bookTypeCode` | 标识、书名（灌命名缓存）、媒介（类型码优先于类型名）、结果条数 |
| detail | `name`/`bookName`、`bookId`/`book_id`、`bookType`、`bookTypeCode` | 书名、标识、媒介（显式类型名压过类型码） |
| chapter | `chapterList[]` 条目内：`itemId`/`u`/`url` ＋ `title`/`n`/`name` | 章节标识、标题（灌命名缓存） |
| content | `contentType` ＋ `data.content`/`text`/`body` | 媒介、正文非空=1 |

**error 信封（带内失败，P22/P122）**：`contentType="error"` ＋ `data` 里——
`message`（必有，出口过 `scrubInBandMsg` 脱敏）、`reason`（选填，S20 建议枚举：
upstream_network / upstream_status / pool_unavailable / parse_empty / unauthorized）、
`code`（选填，站方业务码：0/4001/401/403/429 一档）。**源不填 reason/code，两格就是合法的空**——
但装配仓 S104 的取证要靠它们，填了才分得开「会话被拒」与「配额/风控 429」。

**请求参数键**（骨架侧认的多写法）：搜索词 `key`/`keyword`/`query`/`wd`；
书标识 `bookId`/`book_id`/`id`/`bookUrl`；章节标识 `itemId`/`item_id`/`chapterUrl`/`chapter_url`/`url`。

**媒介判定优先级**（五层短路，正本在 `base/legado/observe.go`）：响应自带类型 ＞ 请求 tab 命中的
源声明（`SearchTab.MediaType`）＞ 命名缓存里同书此前的判定 ＞ 源默认声明（`SourceMeta.MediaType`）＞
都没有=空串。

## 四、读取面一览（谁读这些格）

- **成功率**：会话聚合（`base.RecordCall`）、维度榜、趋势图、保留期归档——全部 `2xx 且非带内失败`。
- **覆盖率**（`subjectrank.Coverage`）：`COALESCE(col,'')<>''` 只数**有**的行；分母不含 `content_withheld` 行；带内失败天然全空、单列 `in_band_failed`。
- **维度榜**：keyword 全动作；book/chapter 只算 `content`；人数/次数口径见 P18。
- **明细筛选**（`/admin/monitor/history`）：source/username/action/keyword/book_name/chapter_title/media_type 等值或 contains，`in_band_code` 等值。
- **公开榜**：维度白名单只有搜索词与书名，`in_band_code` 这类新格**不进榜**（§9 口径不因加格放宽）。
