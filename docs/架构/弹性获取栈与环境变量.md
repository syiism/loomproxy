# 弹性获取栈与环境变量

> 本页由 `AGENTS.md` §8 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

上游请求全部经 `base.BaseHandler`，因此自动获得：短 TTL 响应缓存 → singleflight 合并（键 = URL+请求头）→ 按 host 熔断（冷却期快速失败 503）→ 故障时降级返回过期缓存；代理池与 UA 轮换在 `base.Fetch` 层。
合并里 follower 的等待上限是 **per-call**：从进入 `Do` 起算最多 `timeout`（默认 15s = 客户端 10s + 5s 余量），
leader 失败或返回空结果时它脱离共享自己去执行，**但不再重新拿一整个 timeout**（P91）。

数据源相关处理器**不要自建 http.Client**；自定义超时/请求头通过 `BaseHandler` 字段设置。需要包内自持的获取器（如后台协程）用 `base.NewBaseHandler()` 并设 `Path`，使其同样命中代理门控与熔断口径。

全部配置为环境变量（`conf/conf.go` 为权威定义，含默认值）：

> **「填了但没被按填的样子接受」现在会出声**（待办清单 P98）：`envInt`/`envFloat` 拿到非数字、
> `envBool` 拿到既不是 `true` 也不是 `false` 的值时，**仍按老语义回落**（布尔只认真正的 `true`，
> `1`/`yes`/`on` 都是关闭；数字非法就用默认值），但启动日志里每个键留一条 `WARNING: 环境变量 …`。
> 以前这三族是静默的，而静默回落的方向恰好最危险：`MONITOR_RETENTION_DAYS=1y` 变成「永久保留且不清理」，
> `AUTH_ENABLED=1` 变成「网关关着」——两条都不报错，只会让下一个人从「读数为什么不对」开始查。
> 判据与设置侧同形（P60 在写入口直接拒 `1`/`yes`、P48 要求「填了没生效要说一声」），
> 差别只在启动期**不拒绝启动**：拒绝会把开发环境一起锁在外面，而填错的人需要的是那句话，不是墙。
> 会出声的只有这三族——凭证走 `envStr`/`envList`，没有「非法值」这个概念，因而也不会把原值带进日志。
>
> **默认值的钉子只有一处**：`test/conf_env_notice_test.go` 的 `TestEnvDocumentedDefaults` 跑的是解析器本身，
> 改这里的默认就会红。别在别的用例里靠 `conf.Config` 的字段值声称「默认是这样」——
> 脚手架那个结构体字面量没写的字段是 **Go 零值**，不是产品默认值，那种断言是假绿灯
> （`monitor_retention_test.go` 原来的一条就是这样，名字里的 `ByDefault` 已经去掉）。

- 服务：`SERVER_HOST`·`SERVER_PORT`·`SERVER_LOG_LEVEL`
- 网络与缓存：`TIMEOUT_CONNECT`·`TIMEOUT_POOL`·`CACHE_TTL`·`CACHE_MAXSIZE`·`UPSTREAM_CACHE_TTL`·`UPSTREAM_CACHE_MAXSIZE`；`REDIS_ENABLED`（**默认 true**：不配这几行服务也会去连 `REDIS_HOST:REDIS_PORT`；连不上只是命名缓存退成纯内存，请求不失败，症状是启动那一行「命名缓存为纯内存」）


  **`CACHE_TTL` 只管缓存存活时间**（待办清单 P82）：它过去还被 `utils/cache.go` 拿去当 Redis 的
  `ReadTimeout` 用——一个**运营口径**（留多久）被当成**网络参数**（等多久）读，于是"把缓存留久一点"
  顺带把"Redis 卡死时请求挂多久"也改了（现网那个值实际是 300 秒，库里默认 3 秒）。现在拆开：
  `ReadTimeout` 10 秒、`WriteTimeout` 3 秒、`DialTimeout` 3 秒，都不走配置。
  号池侧同族的一处：`POOL_HOOK_TIMEOUT_SEC`（默认 30 秒）是一次源钩子调用的上限，
  维护与装填持着池锁调钩子，没有它就是一个卡住的上游冻住整池（待办清单 P81）。
  **运行期坏了也要出声**（待办清单 P68）：接口缓存（`utils/cache.go`）的 Redis 那一段按
  写 / 读 / 失效三份独立状态计数，只在**好→坏**与**坏→好**翻转时各出一条（坏的是 ERROR，
  恢复那条带此前累计次数）；`redis.Nil`（正常未命中）不算故障——原来 `Set`/`Del` 连返回的错误都没接、
  `Get` 把"连不上"与"没命中"回成同一个 `(nil,false)`，于是缓存静默失效、上游被打穿而读数看不出来。
  `Close()` 刻意不接：收尾时报给谁都没意义、`REDIS_HOST`、`REDIS_PORT`、`REDIS_DB`（多套部署共用一个实例时靠它隔离，本部署用 3）、`REDIS_PASSWORD`（默认为空 = 无密码；`envStr` 把 `.env` 里的空值也当未设置，默认值写死密码会让无密码 Redis 连不上）
- 上游响应的两条带缓存通路，**按请求形态分**（`base/base.go`、`base/fetch_shared.go`）：
  - GET：`FetchJSON` / `FetchText`——缓存键由 `url + headersKey(headers)` 推得出，TTL 取
    `UPSTREAM_CACHE_TTL`（默认 10 秒，0=关），并发同键由 singleflight 合并，上游故障时回过期缓存。
  - **POST / 签名加密型：`FetchShared(url, method, headers, body, cacheKey, ttl)`**——返回**响应体字节**。
    这类请求的 body 每次都要重算（IV/nonce/时间戳/签名），**从请求内容推不出可复用的键**，
    所以键由调用方显式给；传输仍走 `Fetch`（熔断、代理池、UA 轮换照旧），另加同样的 singleflight 与缓存。
    **键必须含全部会改变响应的维度**：以纸间正文为例，响应是加密信封，
    解它要用当时那枚会话的派生键，所以键要带 sessionID——漏了这一维，"换会话后读到旧信封"会表现为解不开，
    比读到旧正文更难查。`ttl<=0` = 只合并、不缓存（想省上游又不留内容面就用这一档）。
    只缓存 **2xx 且非空**的响应：一次风控拒绝被缓存成"这本书读不了"，比没缓存更糟（同族见 S54 的"超限要报错不要截断"）。
    缓存实现在装配期由 `base.SetSharedCache` 注入（`base` 不得导入 `utils`，那条硬边界决定了端口只能这么放，
    适配器与注入调用落在同时看得见两边的 `app/shared_cache.go`）：
    现网接到 `utils.DefaultCache()` 的 Redis 那一段，用 `SetTTL` 让每条自带存活时间
    （**全局 `CACHE_TTL` 管的是计费读数与 `/datasources` 列表，不是正文**）。
    内存模式下这条 LRU 与它们共享 `CACHE_MAXSIZE` 格，会互相挤——Redis 模式按各自 TTL 过期，无此问题。
    **拍板记录**：正文响应走 Redis 是维护者 2026-10-08 的决定；它多开了一处「谁在读哪本哪章」的持久面，
    留存边界写在下面的《缓存》那一条与 `docs/规范/安全与合规.md`。
- 熔断：`CIRCUIT_BREAKER_ENABLED`·`_FAILURES`·`_COOLDOWN`
- 代理：`UPSTREAM_PROXIES`·`UPSTREAM_PROXY_FILE`（5s 热加载）·`UPSTREAM_PROXY_API`·`_API_SCHEME`·`_API_INTERVAL`·`UPSTREAM_PROXY_CHECK_URL`·`UPSTREAM_UA_ROTATE`；动态池自维护水位（低于 5 自动补充，复验存量 + 逐轮拉新）；**哪些接口走代理由系统设置 `proxy_enabled_sources` 决定**（逗号分隔，支持整源与单接口两种粒度，留空=不限制）
- 号池：`POOL_ENABLED`·`POOL_COLD_SPARES`·`POOL_MAX_HOT`·`POOL_MAX_DEAD`·`POOL_RENEW_BEFORE_SEC`·`POOL_MAINTAIN_SEC`
- 数据：`DATA_DIR`·`DATA_FILE_GLOB`·`TZ_OFFSET_HOURS`·`ERROR_CODE`·`RETIRED_SOURCES`（本部署已下线的历史数据源码，逗号分隔，默认空；启动时清理其配置表存量行——底座不携带源，清单归部署侧）·`MONITOR_RETENTION_DAYS`（接口调用明细保留天数，**默认 0=永久保留且不清理**；>0 时过期明细删除前先聚合进 `api_call_stats`）·`MONITOR_BACKFILL_SEC`（名称回填循环的间隔秒数，**默认 900**；0=关掉循环、只留 `POST /admin/monitor/backfill-subjects` 手动入口）·`BILLING_DEDUPE_SEC`（同接口同内容的额度扣减冷却秒数，**默认 300**；0=关掉冷却、回到每个成功请求都扣。见待办清单 P25）
- 鉴权：`AUTH_ENABLED`·`API_KEYS`·`AUTH_WHITELIST`·`JWT_SECRET`（**生产必须改**，启用鉴权时用默认值直接拒绝启动）·`JWT_EXPIRE_HOURS`·`ADMIN_USERNAME`·`ADMIN_PASSWORD`
- 时间：`TZ_OFFSET_HOURS`（默认 8）是**平台时区的唯一值**，而「今天零点」的唯一算法是 `utils.DayStart(days)`
  （`gate.StartOfDay()` 只是它的门面）。额度日界、验证码日限、面板「距下次重置」、统计的今日新增、
  榜单窗口、趋势图日标、名称回填窗口**全走这一处**——过去它们有七种写法（四处写死 +8、三处跟进程时区），
  改这个配置只有时间字符串的显示跟着变（待办清单 P71，已由 `make vet` 的 `tz-check` 拦住）。
  **那条已知的残留已收口（P72，2026-10-06）**：按天聚合的柱子高度原先由库侧 `date(created_at)` 分桶，
  sqlite 会把带 +08 的串按 UTC 归一日界（生产 MySQL + `loc=Local` 恰好不受影响），
  现在分桶与日标同在 Go 侧、同一个 `utils.DayStart` 口径生成。
- 缓存：`REDIS_*` 除接口缓存外，也用于「标识→名称」命名缓存（见 §9）与 `FetchShared` 的 POST 响应缓存的跨重启持久化。
  **最后这一条是新开的持久面**：键由源侧给定、必须含会话，值只有上游原样的密文信封（不解析、不改写、不入库），
  存活期由源侧的 TTL 决定。它能跨读者共用，是因为**上游会话是平台侧的那一枚**（号池或注入的三件套），
  不是每个下游读者各一枚。要清楚它换来什么代价：监控明细那条「留存同意」（P37）管的是 `api_call_logs`，
  Redis 里这一格**不受它控制**——关掉留存的读者照样会让「某本某章被请求过」这条键在缓存里留到过期。
  这半句是拍板时就摆出来的代价，不是事后补的（拍板：维护者 2026-10-08）；留存边界的正本在 `docs/规范/安全与合规.md`。
- 数据库：`DB_TYPE`（代码默认 **mysql**，`.env.example` 与镜像默认 sqlite）·`DB_HOST/PORT/USER/PASSWORD/NAME/SSLMODE`；SQLite 路径为 `DATA_DIR/DB_NAME.db`，经 DSN 启用 WAL + `busy_timeout` + `SetMaxOpenConns(1)`（读事务升级写会触发不被 busy_timeout 重试的 `SQLITE_BUSY_SNAPSHOT`，单连接彻底规避）

登录 token 时长解析优先级：用户个人设置 > 系统设置 `jwt_expire_hours` > `JWT_EXPIRE_HOURS` > 168h；任一级取 -1 即永不过期（JWT 不写 exp、会话表写 100 年）。
