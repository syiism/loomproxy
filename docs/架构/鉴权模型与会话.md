# 鉴权模型（两层）

> 本页由 `AGENTS.md` §7 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

1. **API 网关层**：`middleware/apiauth` → `utils.VerifyAuth`。仅 `AUTH_ENABLED=true` 时生效；白名单路径跳过；接受 JWT（`Authorization: Bearer` / `?token=` / `loomproxy_token` Cookie，统一走 `utils.TokenFromRequest`）或 API Key（`X-API-Key` / `?api_key=`）。
2. **用户层**：`handlers/auth` 的注册/登录等；守卫有三个，**按端点能不能被长期密钥使用来分**（待办清单 P26）：
   `AuthOrKeyRequired()`（三形态都收）保护 `/user/*`、`/quota/*`、`/rank/boards`；
   `AuthRequired()`（只认会话）保护 `/auth/*` 与 `/apikey`；
   `AdminRequired()`（只认会话 + 查库校验 admin 角色）保护 `/admin/*`、`/debug/pprof/*`。
   三条都从**同一个解析器**取身份（`utils.resolveJWT` / `utils.resolveAPIKey`，对外是 `VerifyAuth` 与 `AuthenticateAny`），
   不再各写一遍「先 JWT 后密钥」的顺序与失败文案。
3. **用户自助 API 密钥**（`/apikey`，JWT 会话保护）：创建（`lp_` 前缀，明文可随时查回，每人上限 10 个）/ 列表 / 撤销。网关匹配到用户密钥时**注入归属身份**，计费/配额/监控/套餐门控按归属用户生效；静态 env 键保持匿名语义。
   归属解析 `utils.LookupApiKeyIdentity` 有一层短缓存，而**命中缓存的分支不复查 `users.status`**——
   所以「禁用/删除这个用户」必须显式走 `utils.InvalidateUserApiKeys(userID)`，光吊销会话不够（待办清单 P47）；
   两处调用点紧跟在 `db.RevokeOtherSessions` 之后（P56 之后：那次吊销与状态写入同一个事务，缓存清理留在事务外——它是进程内动作，放进事务没有意义，失败自己会喊）。撤销单把密钥走 `InvalidateApiKeyCache`（同一键构造器）。
   两个状态码把两条通路分开可读：403「无效的 API Key」= 归属**查库**查不到人（失效已做成），
   401「用户不存在」= 身份来自**缓存**、往下才发现库里没人（`gate/access.go`）——
   面板与用例都按这两个码分辨，不断「非 200」。
   **密钥的两条硬边界**（有意收窄，不是遗漏）：① **凭证引导类端点只认会话**——`/apikey`（铸造与撤销密钥本身）、
   `/auth/me`、`/auth/password`、`/auth/privacy`、`/auth/sessions*`、`/auth/logout`；一把长期密钥若能铸造别的密钥或改密码，
   等于提权且无法靠「退出全部设备」止血；`/auth/privacy` 同组是因为它记的是「本人授权网关留不留我的阅读数据」，
   密钥泄露时攻击者可以替受害者重新打开留存，而这件事在会话列表里看不见。② **管理面只认会话**——`/admin/*` 必须一次登出就立刻关得掉，
   管理员自己的密钥也一样进不去（`test/three_forms_auth_test.go` 钉着这条）。
   静态 env 键在任何需要归属账号的端点上都是 403：它按设计匿名。
4. **会话**：JWT 的 `jti` 对应 `auth_sessions` 行（设备名/IP/最后活跃）；两层鉴权都校验会话未被吊销且未过期，**无 jti 的旧 token 一律 401**。会话行**就是执行点**（`AuthRequired` → `db.ValidateSession` 每请求查 `revoked_at`），所以"吊销没做成"等于那个人还能用。删除/禁用用户、改密、找回密码、改名都会吊销会话，且**与那次凭证写入同一个事务**（`db.RevokeOtherSessionsTx`，待办清单 P56）：分两条语句提交会造出"密码改了、旧设备还在、响应说成功"。改密与登出**保留当前会话**（传 `keepSessionID`），只有改名/禁用/删除/找回按语义连当前一起作废；`Logout` 在吊销失败时仍返回 200（挡人没意义）但响应带 `notice` + 一条 ERROR 日志。

## 登录与找回密码的防爆破（按 IP，进程内存）

- 计数与锁定都在 `handlers/auth` 的 `ipAttemptLimiter` 里：登录 10 次/分钟、找回密码 5 次/分钟；
  窗口超限或**连续失败 10 次**→ 锁 1 小时（`attemptMaxFails` / `attemptLockMinutes`）。被锁后即使密码正确也回 429。
- **不落库**，因此有三条必须知道的性质：① 重启即全清（重启本身就是一种「解锁」，只是代价是全局的）；
  ② 面板上那两个数字只反映**当前进程**，空列表不等于「最近没人试过」；③ 键是客户端 IP（经 `X-Forwarded-For` 还原），
  **不是账号**——所以挑一个账号慢速试、或用一批 IP 各试几次，都摸不到阈值。账号侧目前没有独立闸门（待办清单 P40 在册）。
- 管理面读写各一条，均在 `/admin/*` 组内、只认会话：`GET /admin/security/attempts`（快照，锁定项排前面）、
  `POST /admin/security/attempts/reset {ip}`（清掉该 IP 的锁与连击，返回 `cleared` 条数，0 不是错误）。
  条目另有回收：超过 4096 行时顺手扫掉「窗口已过且未锁定」的行，快照时也扫——此前每见一个新 IP 就永久留一行。
- **它与 IP 黑名单是两件事**：`blocked_ips` 在库里、拦该 IP 的一切请求；这里的锁只挡登录与找回密码两个端点。
  面板把它们放在同一页（「IP 拉黑」页的两节）正是为了让这两种「解锁」不会被按错。
## 多设备登录监控与自动处置（待办清单 P44）

- 每条会话一行 `auth_sessions`：`device`（UA 解析）、`ip`、`created_at`、`last_active_at`、`expires_at`、`revoked_at`。
  「一个账号近期几个设备、几个登录 IP、几把密钥」全从现有列算得出，**零 DDL**。
  调用侧的 IP 分布看 `api_call_logs`（`username` + `ip`）——用户密钥的调用也归属到用户名下，
  所以「只在 Legado 里填 key、从来不登录」的使用者也算得进来。
- **处置只有一个判据：活跃会话数**。`db.RevokeExcessSessions` 在 `issueToken` 之后收一次口子
  （注册/登录/找回密码三条路都过这里，处置点因此只有一处），保留最近活跃的 `max_active_sessions` 个。
  **IP 数永不作为移出理由**：一个出口 IP 后面可能是整家公司或一整个家庭。IP 分散只在面板标红。
- 开关 `device_watch_enabled` 默认 **false**：读数先上线、踢人后上线。默认档有用例实测（关着时超上限也不许动一个会话）。
- 它只是**提高借号成本，不是阻断**：被移出的设备重新登录就能回来（本轮没选「拦新登录」）。
  文案与文档都不要写成「已阻止共享账号」。
- 提示不建站内信表：登录响应带一句 `notice`，算法是「`revoked_at` 落在**上次登录时刻**之后的会话数」，面板 `Login.vue` 在登录成功后把它弹出来（10 秒，比一般 toast 长——这条要让人读完）。**这句曾经只在后端算好**：前端源码里 `notice` 出现 0 次，等于提示从没到过使用者眼前（待办清单 P58）；
  上次登录时刻必须取**值拷贝**（`*time.Time` 直接赋值复制的是指针，随后那次 Update 会顺着同一对象改掉它）。
- 库里 `revoked_at` 分不出「系统自动移出」与「用户自己点登出其他设备」，两者都只是一个时间戳——
  能分清的地方只有服务端 journal 那行 `SECURITY: 多设备监控自动移出会话 …`，所以它必须写清原因与数量。
- 管理端读数页 `/admin/devices`（面板「设备与密钥」）连同**当时口径**一起下发
  （阈值、窗口天数、开关状态）：没有口径，「8 个 IP」这种数就没法判断算不算异常。
  这页可按七个聚合列排序（待办清单 P45）：`sort`/`dir` 走**白名单映射到内存比较函数**，
  非白名单值回落默认排序而不是 400，参数**永不进 `ORDER BY`**；排序要跨页可比，
  所以取数是「全量命中的人 → 聚合 → 内存排序 → 切片」，不是「按页聚合再排」。
- **活跃会话只有一份定义**：`db.ActiveSessionCond`（统计窗口内建立 + 未吊销 + 未过期）。
  「设备与密钥」页的 `active_sessions`（`db.ActiveSessionCounts`）与用户管理的 `over_cap=1` 筛选
  （`db.UserIDsWithSessionsOver`）共用这条 SQL——两处各写一遍就会「筛出来的人和排出来的人不是同一批」。
  而**取会话明细那一条**用的是 `db.SessionWindowCond`（只要窗口、含已吊销）：
  「登录设备 / 登录 IP / 近期移出」这三列要的正是包含已吊销的全集（待办清单 P45 的坑，判据见踩坑判据）。
- 与自动拉黑**互不接线**：`middleware/ipblock` 的滑动窗口只统计**数据源路由**返回的 403/429
  （`monitor` 的 `Applies` 是 `s.Source != ""`），爆破登录不会产生黑名单行。要不要把登录失败也喂给它，是 P40 的另一半。

关键路由分组：`/auth/*`（register·login（用户名或邮箱）·forgot-password·me（GET/PATCH 资料）·password·**privacy（POST，同意位唯一写入口）**·sessions*·logout）、`/verify/*`（场景化验证码，`GET /verify/config` 供前端决定是否渲染输入框；发码通道 `mock`/`http` 模板适配器由系统设置切换，默认全部场景关闭）、`/quota/dashboard` 与 `/quota/usage-logs`、`/user/*`（baseUrl 配置·导入书源·卡密兑换；`GET /user/import-config` 只下发托管路径与 ready，绝对地址由前端同源拼）、`/rank/boards`（排行榜聚合榜，三形态鉴权，放行范围由系统设置 `rank_public_sources` **按数据源**指定，留空=不开放；
  放行名单为空时的 403 是**授权**拒绝，与鉴权形态无关——写用例时别把两者混成一个 403）、`/admin/*`（详见 §9）、`/data`（免鉴权，在默认白名单里；`/data/<分类>/<文件>.json` 原样直出文件，也是书源 JSON 的托管通道 `GET /data/shuyuan/bookSource.json`）·`/datasources`（**不在默认白名单**：`AUTH_ENABLED=true` 时匿名请求它拿 401「缺少鉴权凭证」，要匿名分发清单就把它加进 `AUTH_WHITELIST`——这是产品决策，现状是要鉴权）、`/announcement`、`/panel`。
