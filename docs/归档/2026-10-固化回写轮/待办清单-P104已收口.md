## P104 门禁那 446 秒里 76% 是 `-race` 的倍率，不是慢用例、不是装配：**唯一提速路径是并行度，而它要动测试骨架**【**已收口（2026-10-07）**：spike 两步（第一步 `1ce38ca`、第二步省 43%）→ 维护者拍「切 2 包」→ 正式拆分落地：`test/` + `test/groupb/` 两组，全量门禁 **470.7s → 253.4s（省 46.2%）**，`make build` `MAKE_EXIT=0`；跨组下沉 30 条（全是函数与常量，带方法的类型一条都没拆）；读数、三处隐性成本与一次"改名撞进字符串字面量"的自纠都在这条里】

- **现象/证据**（全部当场数出来，方法随条目留着）：
  `go test -race -count=1 ./... -json` 全量一遍（exit 0，279 条用例）：
  - 包 `loomproxy/test` wall **446.6s**，而**用例自身耗时合计 445.5s**——**编译 + 装配只占 1.1s**；
    其余三个包合计 3.6s（`base` 1.6 / `app` 1.0 / `utils` 1.0）。
  - **不是睡出来的**：全 `test/` 只有 **25 处 `time.Sleep`，最长 2.1 秒**，合计约 10 秒。
  - **没有毒瘤**：最慢单条 `TestCacheRedisDegradationSpeaks` 16.2s；最慢 10 条合计 95.9s（21%）；
    最慢的文件 `test/groupb/login_lockout_test.go` 39.3s（9%）。分布平到"点名修三个用例"这种解法不存在。
  - **倍率实测**（同一批最慢 10 条，隔离跑）：不带 `-race` **22.0s**，带 `-race` **94.2s** = **4.3 倍**；
    而隔离跑 94.2s 与全量里那 95.9s 一致——**没有互相干扰，慢是自己的**。
  - 外推：全量 446s 里约 **76% 是 race 检测器的开销**，"真实工作"约 100s。
- **为什么这不是可挤的水**：那 4.3 倍就是这条门禁**抓数据竞争的能力本身**——本仓 P77/P78/P93 那几轮
  （`base/pool/status.go` 解锁后无同步读 `p.cooldown`；一次 nil panic 把监控锁带走）全靠它。
  **摘掉 `-race` 或按包区分带不带，都是缩小门禁范围换读数，不做**（§12 那条纪律的另一形状）。
- **影响**：每颗代码 fix 的边际成本 +7.5 分钟；今天 8 颗代码 ≈ 1 小时纯等待，
  而这段等待期间能推进的只有文档——**这正是"长任务空转在带着文档"的直接机制之一**。
  `P102` 落地后（`deploy.sh` 改走 `make vet && make test`），**这条成本同时进了发布链**。

    **瓶颈是"一个包 = 一个二进制 = 一条串行的用例流"，不是机器不够**，这正是并行度能吃掉的那块。
  - **第一步已落地**（提交 `1ce38ca`）：`testkit/server.go`（实现，导出）+ `test/testserver_test.go` 改成转发层。


    并行那次里跑完的那包是 253.3s（单独跑 244.6s），**争用代价 +3.5%**，可接受。
    **判据「降不到 300s 以下就不做」通过** → 正式拆分值得做，但它不在本条拍板的两步范围内，见下面"下一步"。
  - **失败归因（这条是拆包必须带走的第二件东西）**：新包 `probeb` 单跑 32 条 FAIL，
    全是要打假源路由的那些（聚合搜索 / 计费 / 限流 / 访问控制 / 隐私留存 / 额度转移），

    同一批用例在单包跑里同样红，而留下的那包在并行跑里 253.3s 全绿。
