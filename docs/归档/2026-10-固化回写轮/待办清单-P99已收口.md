- **为什么这不是"风格问题"**：三处后果实测过（其余是面板格显示 0 那一类，见下面的分档）——
  1. **注册的默认角色回落是静默的**（`handlers/auth/auth.go`）：旁边那段**默认套餐**的回落早在 P48/P53 补了出声，
     同一个函数里的同一个形状写了两遍，角色那一半一直没跟上。查不到角色时把**零值 `Role`** 塞进
     `many2many:user_roles`，GORM 会去插一行新角色（`name`/`code` 都是空串，两列是 `uniqueIndex` + NOT NULL，
     空串合法）→ 第一次留下一个谁也对不上的幽灵角色且注册"成功"，第二次起唯一索引**把注册本身打成 500**。
  2. **发码的三道闸读不动时等于没有闸**（`handlers/verify/verify.go`）：同目标冷却、同目标当日、同 IP 当日上限
     全靠读 `verification_codes` 算，三处读都不取结果 → 一次数据库抖动把三道闸一起读成 0，
     而它一路走到 `sender.Send`（要花钱的通道）才在落库那步失败——事后日志是"发出去了却查不到码"，
     那正是 P40 那族防爆破要守的东西。现在：读不到行照旧放行（合法状态），**读失败=拒绝发码 + 出声**，
     对外的句子是新的 `ErrStorageUnavailable`（503），不带表名也不带驱动原文（P90 那条）。
  3. **`db.NoticeReplacedSetting` 的去重形状漏在"两步回落链"上**（`db/setting.go`）：它按 `key -> 上一次的样子`
     存一条，于是同一个键的两个不同原因**交替**出现时，每次都被判成"和上次不一样"→ 每次注册喊两条。
     承诺的"同一种替换只说一次"就这么漏了。现在按 (键, 原因, 填的值) 三元组去重。
     这条是用例逼出来的：默认角色的回落链正好是两步，改前那条测试写法（期望第二次 0 条）当场红。

    ① `UsageLogs.vue` 与 `Dashboard.vue` 各有一条 `v-else-if="list.length === 0"` 的 **UiEmpty「暂无流水记录 / 暂无调用记录」**，
