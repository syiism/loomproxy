## P107 面板引用站点根的 `/favicon.svg`：**我先把它误报成仓库缺陷**（维护者指出那是部署约定——换图不必重建）【改判·自纠 → **已收口**：约定落进运维页、探针加了路径归属、生产只读核到 200】

- **② 已核（2026-10-07，维护者给了现网域名，只读 GET）**：
  ```bash
  curl -o /dev/null -w '%{http_code} %{content_type} %{size_download}B' https://loomproxy.dpdns.org/favicon.svg
  #   200 image/svg+xml 91137B
  curl -o /dev/null -w '%{http_code}' https://loomproxy.dpdns.org/panel/admin/quotas   #   200（SPA 回退正常）
  curl -o /dev/null -w '%{http_code}' https://loomproxy.dpdns.org/datasources            #   401（未带凭证，正常）
  ```
  **那条引用在生产上是可达的**，而且 91137 字节与 `configs/icons/syiism.svg` 同大小——线上放着的就是那张图。于是本轮那个"404"从头到尾都只是**我这台没有前端服务器的裸实例**的读数；归因筛第一条（先问"这是在哪个形态上量的"）今天有了双向证据：本机 404 与现网 200 都没错，**错的是把前者写成仓库事实**。


- **本轮我做错了什么**：探针在本机裸实例上抓到 `404 /favicon.svg`，我据此写成"这个引用从建仓起就没被满足过、是缺陷"，
  还建议"删掉那一行"。**那个 404 测的是"我起的这台实例前面没有 nginx"，不是"仓库少一个文件"。**
  §4b 的归因筛（环境 → 信息 → 推理）我跳过了第一条：本仓的生产形态是**本机 nginx 在站点根提供静态文件**
  （`docs/规范/开发约定.md:65` 就写着可信代理是 127.0.0.1 的 nginx），而 `href` 落在**站点根**正是维护者的设计——
  **上线后替换图标只要往根目录放文件，不需要重新构建前端、不需要动二进制**。
  我还真的动了一次手：把引用改成 `%BASE_URL%favicon.svg` 并往 `web/public/` 塞了一张图——**那会改掉这个约定**，已撤回
  （`git checkout -- web/index.html`、`rm -rf web/public`，只看本轮自己造的改动）。
- **证据边界**（按判据页《阻塞项》那条：环境断言要带命令与输出，拿不到证据就写"我没核过"，别写"没有"）：
  - 核过的：`grep -n favicon web/index.html` → 绝对路径 `/favicon.svg`；`ls web/dist` → 产物里没有；
    本机裸实例 `curl -o /dev/null -w '%{http_code}' http://127.0.0.1:PORT/favicon.svg` → **404**。
  - **没核过的**：现网站点根是否真放着那个文件——那要读 nginx 配置或访问域名，两者都不在本轮目录白名单内。
  - 所以这条现在的事实是一句半话：**本机形态不可达；生产形态大概可达，但我没有证据**。
