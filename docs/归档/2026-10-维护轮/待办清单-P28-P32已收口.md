## P28 管理面有四处「同一件事两个入口」，其中套餐↔数据源关联会互相覆盖（同 P17 的形状）【已处理】（提交号：`18709b5`）

- **现象/证据**（2026-10-03 维护者要求「管理界面功能去冗余，能合并的就合并」；下列四处都逐条实读代码核过）：
  - **A1 真会互相覆盖**：`quota_plan_data_sources` 有**两个编辑器**——
    `web/src/pages/admin/Datasources.vue:530-550`（按数据源勾套餐，`savePlanPerms` 用 `addPlanDataSource`/`removePlanDataSource` 逐条 delta）
    与 `web/src/pages/admin/Quotas.vue:286-315`（按套餐勾源，`batchAddPlanDataSources`/`removePlanDataSource`）。
    两处各自在打开时对成员做**快照**、保存时按「快照 vs 当前勾选」算 delta ——
    先后保存时，后一个会拿**旧快照**把前一个的增删当成自己的删除/恢复项回滚掉。这与 P17 同形同因（P17 是两处改同一个设置项）。
  - **B1 同一份数据显示两遍**：`Dashboard.vue:124-163` 的管理员「全站调用流水」与 `pages/admin/UsageLogs.vue`
    打的是同一个 `GET /admin/usage-logs`，Dashboard 那份还是**无筛选的子集**。
  - **B2 同理**：`Dashboard.vue:110-117` 的接口×消耗块（读 `/quota/dashboard`）与 `admin/Interfaces.vue` 的可编辑表重叠。
  - **D1 两个落地页抢定位**：`/admin`（`Admin.vue:57-65` 用户计数卡 + 快捷入口）与 `/dashboard` 的管理员块
    （`Dashboard.vue:202-230` 全站额度卡）都是「总览」。**这条不动**——它改的是普通用户也看到的 `/dashboard`。
  - **E1 端点侧重复**：`PUT /admin/quota-costs/plans/:id`（只更已有行）与 `POST /admin/quota-costs/plans/upsert`
    （建行）语义重叠，`Interfaces.vue:441` 与 `:485` 两个都调。**本轮只做前端统一走 upsert**，后端两个端点都留着
    （砍端点会打到脚本侧，属对外可见）。
- **别当成冗余合并掉**（都有设计理由，实测读到了出处）：`/rank/boards` vs `/admin/monitor/subjects`
  （公开榜只出名称与次数，理由在 `handlers/rank/rank.go:1-11`）；用户面 `/datasources` vs 管理面数据源页
  （信任边界不同，`handlers/catalog/datasource.go:82-160`）；`/user/source-configs`（个人覆盖）vs
  `/admin/source-configs`（平台默认）；**按组套用限额**（AGENTS §5：组只是批量写入口，键仍是每源一行，
  它与限额页写同一张 `quota_limits` 是有意的刀，不动）；`PUT /admin/settings/:key` 对 `rank_public_sources`
  仍是全量入口（P17 刻意留给脚本/部署）。
- **建议修法**（照 P17 的收法：留一处编辑、另一处降成「只读摘要 + 跳转」）：
  A1 → Quotas 页为唯一编辑器，Datasources 行的「套餐权限」降为「纳入 N 个套餐」摘要 + 跳 `/admin/quotas`
  （该页副标题 `Datasources.vue:3` 本来就已自认是快捷入口）；B1 → Dashboard 收成「最近 5 条 + 跳流水页」；
  B2 → Dashboard 那块改成「已配 X 项 + 跳接口页」；C1（`Users.vue:469-509` 的个人额度覆盖）与限额页是
  **不同表、追加语义**，不合并，只加双向跳转，免得有人在两处找同一件事。
- **代价分级**：A1/B1/B2/C1 纯前端；E1 的前端部分纯前端、后端收敛要动端点（不在本轮）；D1 改用户可见页——**列进等人拍板**。
- **发现处**：2026-10-03 维护者提的三条之一；清点由面板 12 个管理页逐页实读 + `handlers/admin/admin.go:24-96` 端点对照得出。
- **已处理（`18709b5`）·偏离原建议之处**：
  - A1 按 P17 收法做完（删弹窗与两个函数，行内降成 `套餐 N` 只读计数 + 跳额度页，页顶副标题不再承诺「快捷调整」）。
  - **B2 没有删掉读数**，只把「接口消耗」那行标题变成去接口页的入口——Dashboard 的消耗 chip 是
    额度看板上下文的一部分，删了要让管理员在两页之间跳来对数；冗余的根问题是**编辑落点**不是显示。
  - B1 管理员视角收成最近 5 条 + 跳转（`visibleLogs`），**普通用户看自己的全量分页不变**。
  - C1 不合并（不同表、追加语义），两处互加跳转。E1 只做前端：面板统一走 `upsert`
    （`PUT …/plans/:id` 只能改已有行，重置时恰好没有套餐级行就会漏），**PUT 端点保留给脚本/部署**，
    砍端点属对外可见，不在本轮自主范围。

## P29 接口监控的「内容维度」整段过长，读一次要滚半屏【已处理】（提交号：`18709b5`）

- **现象/证据**：`web/src/pages/admin/Monitor.vue` 这一页从上到下依次是：内容维度覆盖率表（`:94-118`，11 列）
  + 其上的口径说明（`:87-91`）+ 其下的缓存/媒介状态说明（`:119-126`）+ 两张维度榜 + 最近调用（`:163-188`，12 列）
  + 历史明细（`:209-238`，**13 列**）。P24 刚把空态的长说明收掉，但**有数据时这一大段仍然全展开**，
  管理员日常只盯成功率与两三本热书，却要为一眼看不完的表滚半屏。
- **维护者的要求**：「内容维度监控过长请添加折叠功能减小阅读负担」——点名的是**内容维度那一段**，不是整页。
- **建议修法**：给「内容维度」这一段（覆盖率表 + 两张榜）加**默认收起的折叠块**，收起态留一行摘要
  （例：`内容维度：3 源×4 动作，覆盖率最低 47%，2 条带内失败`），展开态是现有整块——
  摘要是**读数**不是形容词，收起不等于信息丢失。折叠状态记进 `localStorage`（下次进来还是上次的心智）。
  **注意 P24 的那条判据仍成立**：空态时长说明本来就不该显示，折叠不能把它在空态又放出来。
- **要新做一个共享件**：全仓现在**没有任何** `<details>`/折叠/tooltip 组件（已 grep 证实，最接近的是
  `UiField.vue:7` 的恒显 `hint`）。所以这是一个新组件 `UiCollapse.vue`（或直接用原生 `details` + 基样类），
  落点写在 `styles.css` 的 `@layer components` 里复用，别在页面里散写内联样式（§10 的复用约定）。
  P30 的移动端长文条目与这条共用它。
- **发现处**：2026-10-03 维护者提的三条之一。
- **已处理（`18709b5`）**：新增 `components/UiCollapse.vue`（`storageKey` 记展开态、隐私模式抛异常也不白屏），
  `Monitor.vue` 的「内容维度」整段默认收起，收起态摘要是一行读数
  （`覆盖率 N 组 · 书名最低 X%（源/动作）· 带内失败 M · 榜 K 条`）。
  **组件里顺手兜住了 `reveal` 的新变体坑**：`v-show` 收起时段内 `.reveal` 观察不到、展开后停在 `opacity:0`，
  所以 `UiCollapse` 展开时自己补一次 `nextTick(revealObserve)`——约定里也记了一笔。
  P24 那条判据没被折叠破坏：长说明仍只在有数据时显示，折叠只是把它们再收一层。
  **验证边界**：本环境无浏览器，做到的是 `pnpm build` 编译通过 + 断言「收起态摘要有数」的代码走读，
  展开/收起的实际观感**未经渲染验证**。

## P31 样式类名写错没人拦：`btn-secondary` 用了 7 处而它根本不存在【已处理】（提交号：`18709b5`）

- **现象/证据**：`styles.css` 的 `@layer components` 只定义了 `.btn`/`.btn-primary`/`.btn-ghost`/`.btn-danger`，
  而全站 7 处写 `class="btn btn-secondary"`（`pages/admin/Interfaces.vue:12-18` 等）。Tailwind 对不存在的类**静默跳过**，
  所以这些按钮没有底色、与卡片背景糊在一起——**桌面端一直在，没人发现**，因为构建不报错、用例跑不到、肉眼扫代码也看不出来。
- **真因（机制）**：类名是自由字符串，写错的一刻没有任何一处会失败。这一类与 `keys` 别名撞保留字同族：
  **SQLite 不报错的东西，MySQL 报错；而 Tailwind 连报错都没有——它只是不产出 CSS。**
- **判据**：能被机器拦的「约定」别停在文档里。加一条前端扫描：从 `web/src/**/*.vue` 抽出 `class="…"` 里的
  `btn-*`/`card`/`table-*`/`input*`/`tag*` 等自定义类，与 `styles.css` 的 `@layer components` 定义集比对，
  未定义即 `make vet` 失败（与 `scripts/check-sql-reserved.sh` 同形态、同一个挂载点）。
- **建议修法**：先补定义（`btn-secondary` 就是次级按钮，与 `btn-ghost` 的区别该由维护者定）还是改用现有类，
  二选一后落扫描。**本轮先落扫描 + 把这 7 处改成既有类**（不改视觉语义），把「次级按钮要不要新的底色」留给拍板。
- **发现处**：本轮 P30 移动端巡检的副产物——维护者要求的「清单完成后主动检索源码」机制的第一批产出。
- **已处理（`18709b5`）·走完了阶梯**：7 处 `btn-secondary` 换成体系里已有的描边按钮（`btn-ghost`，
  不新造视觉语义），扫描 `scripts/check-css-classes.sh` 挂进 `make vet`——**这一类从此由机器拦**。
  扫描一落地就又抓到两个同族的空类：`label`（17 处，字段小标题原来是裸文本）与 `checkbox`（5 处），
  这次**补成真定义**（`.label` 对齐 `UiField` 的外观、`.checkbox` 画一个能看的方框并在小屏抬尺寸），
  因为它们的意图明确、不存在「要不要新底色」那种取向问题。
  变异验证两次：注入 `btn-nope` → 红；换成同名类 + 本文件 `<style>` 定义 → 绿（证明「同文件定义算已定义」这条通路有效）。
  口径的限制写在脚本头：只盯本仓自定义类，Tailwind 工具类词汇表太大不判；`:class` 只取引号内字面量。

## P32 `.env.example` 里没有 Redis 那一段，而 `REDIS_ENABLED` 默认是开的【已处理】（提交号：`e2135b0`）

- **现象/证据**（本轮 §4b 主动巡检的产出）：`conf/conf.go:255-259` 读 `REDIS_ENABLED`（默认 **true**）、
  `REDIS_HOST`/`REDIS_PORT`/`REDIS_PASSWORD`/`REDIS_DB` 五个键，而 `.env.example` 里**一个都没有**
  （`grep REDIS .env.example` = 0 命中）。文档侧写的是族名 `REDIS_*`（`docs/架构/弹性获取栈与环境变量.md:13,19`），
  所以看文档能找到、看模板找不到。
- **影响**：新部署照 `.env.example` 复制 `.env` 之后，服务仍然会去连 `localhost:6379`。
  连不上不是失败——症状只有启动日志那一行「命名缓存为纯内存（未启用 Redis 或连不上）：重启后清空」，
  代价是每次重启把 warm 起来的书名/章节名全丢掉，明细的名称维度靠回填循环慢慢补（§9 的命名缓存、P20 的循环）。
  **默认开着的外部依赖**最容易在这种地方咬人：它不报错，只是让某项能力静默退化。
- **建议修法**：`.env.example` 补一段 Redis（含「默认 true」与连不上时的症状），
  环境变量页把族名展开成逐个键；生产那侧不动（本部署 `REDIS_DB=3` 已是部署事实，S 系列有记录）。
- **发现处**：2026-10-03 长任务巡检（维护者要求的「清单完成后检索一次源码」机制的第二批产出）。
- **已处理（`e2135b0`）**：`.env.example` 补了 Redis 段（含「默认 true」与连不上时的症状），
  环境变量页把 `REDIS_*` 展开成逐个键。生产侧未动。
  **同一次巡检自己的四条假阳性（漏了 `envFloat` 这个读取入口）记进了 `踩坑判据`**——
  判据是「扫差集前先穷举 B 的口径，产出逐条反查字面名」，不写下来下一个写漂移检查的人会原样再错。
