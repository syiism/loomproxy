## P115 零停机升级：systemd socket activation【已收口（2026-10-09，代码 `ff3410a`、线上 12:54 切换 + 12:56 带压验收通过，数据见追加节）】

- **现象**：当前升级 = `systemctl restart loomproxy`，restart 瞬间端口关闭，在途请求被拒绝、新连接 RST。
- **方案**：systemd socket activation——端口由 systemd 监听，进程从 systemd 手里接过 fd；升级时 systemd 保持 socket 打开，老进程处理完在途请求退出，新进程 ready 后接新连接。
- **改动量**：约 30 行 Go（main.go 里 `activation.Listeners()` 取 fd，否则回退 `net.Listen`）+ 两个 systemd 单元文件（`loomproxy.socket` + `loomproxy.service` 改 `ExecStart` 与 socket 绑定）。
- **验收**：`systemctl restart loomproxy` 期间，持续 `curl` 不出现 connection refused；老进程在途请求处理完才退出（`TimeoutStopSec` 兜底）。
- **发现处**：2026-10-09 维护者提出，评审确认方案。
- **落地记录（2026-10-09）**：改动落点在 `app/app.go` 的 `Run`（`net.Listen` 原本就在那里而非 main.go，
  main 维持"薄"契约不变）；`deploy/loomproxy.socket` 新增、`loomproxy.service` 加 `Requires=` 绑定与 `TimeoutStopSec=30`。
  本地双路径已验：回退 `go run .` 正常起；`systemd-socket-activate --now` 走 activation 路径起并 200。
  原理/升级步骤/回退见 [`docs/架构/部署-零停机.md`](../架构/部署-零停机.md)。**剩下的只有线上按该页 §3 切换并做 restart 不拒连验收。**
