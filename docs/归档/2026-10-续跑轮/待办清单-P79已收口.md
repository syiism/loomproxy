## P79 部署脚本逐字节写「正在被执行的那条路径」——半截二进制会被 `Restart=always` 立刻 exec【已处理】

- **状态**：已处理 `9cb66dd`（第二十遍；门禁 `MAKE_EXIT=0`，`-race` 套件全绿）。
- **现象/证据（现网 14 天 journal 只读计数）**：`Main process exited` 共 236 次，集中在三个窗口：
  09-28 23:42（118×`code=exited, status=203/EXEC` + 118×`code=killed, status=11/SEGV`）、
  10-01 10:58、10-04 01:10。后两轮的每一次 SEGV **都没有任何应用日志**（Go 还没跑到 main 就死了），
  而每一轮之后服务又"正常"了——共同形状就是**重启落在文件还没写完的那一刻**。
  `Restart=always` 把它伪装成「运行中」，运维看到的是「一直在启」而不是「崩了」。
- **真因**：`scripts/deploy.sh` 的 systemd 分支用 `$SUDO install -m 0755 源 目标`，回滚分支用 `$SUDO cp 备份 目标`——
  两者都是**打开活路径逐字节写**（inode 不变），写完之前目标是一个既非旧版也非新版的文件。
  **实测对照**：`place()`（同目录临时名 + `mv -f`）覆盖前后 inode 变了，`cp` 直写前后 inode 没变。
- **为什么这条值得单独立**：`docs/运维/构建与部署.md` 的换装三查第 2 条**早就要求**「核 md5 与 install
  在同一条远端命令里、装完再复算目标文件」，但那句话管的是**手工**换装；脚本自己没做到，
  于是"用脚本"反而成了绕过纪律的路。**文档要求人记住的步骤，脚本没执行就等于没执行。**
- **修法**：新增 `place() { 临时名 → $SUDO mv -f → $SUDO md5sum 目标 → 与源比较，不一致 die（不重启） }`，
  安装与回滚两条路径都改走它；`make vet` 加第 9 条 `scripts/check-deploy-atomic-install.sh`：
  ① 活路径 `"$DEPLOY_DIR/$BIN"` 作为 `install`/`cp`/`tee`/重定向的**目的地**出现即红
  （作为备份的**读取源**不算，所以判据锚在行尾）；② `place` 里少了 `mv -f`、少了**对目标**的 `md5sum "$dst"`
  复算、或少了 `md5_src = md5_dst` 比较，都红。
- **用例与变异**：扫描器五次变异各拦一处（安装退回 `install` / `mv` 换 `cp` / 删目标复算 / 比较改永真 / 回滚退回 `cp`）。
  **第一次做规则② 时它没拦住"删掉目标复算那一行"**——因为只 `grep md5sum`，源文件那一半还在；
  判据：**规则要指向被删的那个东西本身**。`place()` 另跑了一次真沙箱功能验证（inode 变化、无残留、缺源 die）。
- **刻意没做**：没让 `place` 去管 `favicon.svg` 与 `data/` 目录——它们不是「被 exec 的产物」，
  `cp` 半截最多是一张 404 的图标，不值得把 rename 的复杂度铺过去。
- **发现处**：第二十遍（判法：现网 journal 考古）。
- **被它阻塞的条目**：无。
- **答复后回写位置**：不需要答复（已收口）；若维护者更希望"先 stop 再装"，那是另一种口径，改 `place` 与 `restart_service` 的次序并同步本页与运维页。
