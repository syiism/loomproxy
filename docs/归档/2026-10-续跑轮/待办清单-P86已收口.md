## P86 六个端点各自内联分页夹，且 `page, _ := strconv.Atoi` 丢掉 err：越界页码得到 MaxInt64 → 负 offset → GORM 丢掉 OFFSET ⇒ 第一页的数据配一个不存在的页码【已处理】

- **状态**：已处理 `0bbac40`（第二十六遍巡检撞出；门禁 `MAKE_EXIT=0`，`-race` 套件全绿）。
- **成因分三层，缺一层都不会露出来**（每一层单看都合理）：
  1. `strconv.Atoi` 对超出 int64 的输入返回 `ErrRange`，**但返回值仍是钳到 `MaxInt64` 的结果**——
     `page, _ := strconv.Atoi(...)` 丢掉的不是失败，是"这个值不可信"那句话；
  2. 旧守卫只有 `if page < 1 { page = 1 }`，`MaxInt64` 顺利穿过；
  3. `(page-1)*pageSize` 在 `int` 上溢出成**负数**（实测 20 一页 = -40），
     而 **GORM 对负 offset 是整段不写 `OFFSET`**（DryRun：`... ORDER BY id DESC LIMIT 20`）。
- **可见后果（不是崩溃也不是 500）**：`/admin/monitor/history?page=999999999999999999999` 返回**第一页的行**，
  响应体里 `"page"` 回显 `9223372036854775807`。六个端点同形状
  （`/admin/users`、`/admin/devices`、`/admin/monitor/history`、`/admin/redeem`、admin/user 两侧 `usage-logs`）。
  这类"读数骗人"的坑不会因为不崩就不严重：翻页的客户端与面板都按回显的页码继续走。
- **还有 `err=nil` 的那一支**：`?page=9223372036854775807`（正好 MaxInt64）根本不报错，
  **只判 err 会漏掉它**——所以必须连上限一起判。
- **修法**：六处收成一处 `utils.Paginate(pageRaw, sizeRaw, 默认页长)`；
  `PageSizeMax = 100`（沿用六处一致的值）、`PageMax = 1000000`
  （取 1e6 而不是 MaxInt32，是为了让 `(page-1)*pageSize ≤ 1e8` **在 32 位 int 上也不溢出**——这条夹唯一要做到的事）。
  各端点的默认页长保留（面板 20、用户侧流水 10）：默认值是部署事实，不在这里统一。
- **门禁**：`make vet` 第 10 条 `scripts/check-pagination-single-source.sh`
  ——① 控制面出现就地 `strconv.Atoi(c.Query/DefaultQuery("page…"))` 即红；
  ② `utils/paging.go` 少了 `PageSizeMax` / `PageMax` 的定义或使用即红（"定义了不夹等于没定义"）；
  ③ 旧的内联夹 `pageSize < 1 || pageSize > 100` 复活即红。
- **用例**：`utils/paging_test.go`（新旧两式在 12 组输入上逐点同值 + 把"旧式拿到 MaxInt64/offset 为负"
  这个**成因本身**也断言下来）+ `test/pagination_out_of_range_test.go`（三种越界页码都得回显 `page=1`
  且与第一页逐行相同；并先要求第一页非空，否则比对是空转）。
  变异：让 `Paginate` 退回旧语义（只看值）→ 单元 2 条 + e2e 3 条同时红，e2e 读到的是
  `page=9.223372036854776e+18`（正是修前那个荒谬回显）。
- **过程里我自己的两次**：① 第一版等价用例直接把这个缺陷照了出来——**"新旧两式同值"比"测新函数"更容易揪出被顺手改掉的行为**；
  ② 第一次做 handler 侧变异红在编译不过（`utils` 变未使用），那不算牙齿，改在 `Paginate` 里复刻旧语义才是行为变异。
- **发现处**：第二十六遍（判法「`Atoi` 的错被 `_` 丢掉之后，那个值走到哪里」）。
- **被它阻塞的条目**：无。
