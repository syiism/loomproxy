## Go语言迁移方案

### 1. 核心设计模式映射

| Python概念 | Go实现方案 |
|-----------|-----------|
| 类变量/ClassVar | 包级全局变量 + sync.RWMutex |
| 类方法/@classmethod | 包级函数 |
| 抽象基类/ABC | interface |
| 装饰器 | 工厂函数 + 注册函数 |
| 类型注解 | interface{} / 泛型 |
| dataclass | struct |

### 2. 架构设计方案

#### 2.1 注册表设计

**核心思路**：使用包级全局变量存储处理器信息，用读写锁保证并发安全。

```
// 处理器信息结构
type HandlerInfo struct {
    Handler    interface{}
    Priority   int
    Metadata   map[string]interface{}
    IsInstance bool
}

// 全局注册表
var (
    registry = make(map[string]HandlerInfo)
    mu       sync.RWMutex
)
```

#### 2.2 处理器接口设计

**核心思路**：定义标准接口，所有处理器实现该接口。

```
// 基础处理器接口
type Handler interface {
    Handle(ctx context.Context, params map[string]interface{}) (map[string]interface{}, error)
    GetPath() string
    GetMethods() []string
    GetDescription() string
}

// 带配置的处理器接口（可选）
type ConfigurableHandler interface {
    Handler
    Configure(config APIConfig)
}

// 支持归一化的处理器
type Normalizer interface {
    Normalize(rawData map[string]interface{}) map[string]interface{}
}
```

#### 2.3 APIConfig 结构体

**核心思路**：使用struct存储配置，支持函数字段（用接口替代）。

```
type APIConfig struct {
    BaseURL      string
    Endpoint     string
    Method       string
    Headers      map[string]string
    Timeout      time.Duration
    AuthRequired bool
    FieldMapping map[string]string
    TransformFunc func(map[string]interface{}) map[string]interface{} // 函数作为字段
}
```

### 3. 三种注册方式在Go中的实现

#### 3.1 类注册（注册工厂函数）

```go
// 注册处理器工厂
func Register(name string, factory func(APIConfig) Handler, priority int, metadata map[string]interface{})
```

#### 3.2 实例注册

```go
// 直接注册实例
func RegisterInstance(name string, instance Handler, priority int, metadata map[string]interface{})
```

#### 3.3 无参数注册（使用结构体名）

```go
// 约定：结构体名作为默认注册名
func RegisterHandler(handler Handler, metadata map[string]interface{})
```

### 4. 装饰器模式的替代

Python装饰器在Go中无法直接实现，使用以下替代方案：

#### 方案A：init函数自动注册

```go
func init() {
    registry.Register("github_repo", NewGitHubHandler)
}
```

#### 方案B：使用代码生成工具

```go
//go:generate go run gen_registry.go
```

#### 方案C：手动注册（最清晰）

```go
func RegisterAll() {
    Register("github_repo", NewGitHubHandler)
    RegisterInstance("github_instance", &GitHubHandler{})
}
```

### 5. 泛型支持（Go 1.18+）

```go
// 使用泛型约束处理器类型
type HandlerRegistry[T Handler] struct {
    items map[string]HandlerInfo
}

// 类型安全的获取
func Get[T Handler](name string) (T, error)
```

### 6. 并发安全设计

```
type SafeRegistry struct {
    mu      sync.RWMutex
    items   map[string]HandlerInfo
}

// 读操作使用读锁
func (r *SafeRegistry) Get(name string) (HandlerInfo, bool) {
    r.mu.RLock()
    defer r.mu.RUnlock()
    // ...
}

// 写操作使用写锁
func (r *SafeRegistry) Register(name string, info HandlerInfo) {
    r.mu.Lock()
    defer r.mu.Unlock()
    // ...
}
```

### 优势对比

| 特性 | Python | Go |
|------|--------|-----|
| 装饰器 | ✅ 原生支持 | ❌ 需用init/代码生成替代 |
| 类型安全 | ⚠️ 运行时检查 | ✅ 编译时检查 |
| 并发安全 | ⚠️ 需额外实现 | ✅ 原生支持(channel/锁) |
| 性能 | ⚠️ 较慢 | ✅ 快 |
| 动态注册 | ✅ 运行时 | ⚠️ 需编译时确定 |
| 内存占用 | ⚠️ 较高 | ✅ 较低 |
| 依赖管理 | ⚠️ pip | ✅ go mod |
| 泛型 | ⚠️ 有限 | ✅ 1.18+支持 |

3. **第三阶段**：实现配置热更新
4. **第四阶段**：完善错误处理和日志
5. **第五阶段**：添加性能监控和指标

### 注意事项

1. Go中**不能直接传递函数作为字段**（除非使用接口），建议用接口替代
2. 注意**接口的零值**问题，Get方法应返回`(Handler, error)`而非`Handler`
3. 使用`sync.RWMutex`保护全局注册表
4. 优先使用**工厂函数**而非直接注册实例，更符合Go惯例
5. 避免在init中执行复杂逻辑，建议显式调用初始化函数
6. 使用**context**传递请求级别的配置和取消信号

这个方案充分利用了Go的并发特性、接口系统和编译时类型安全，同时保持了原设计的灵活性。
