- **已落地（2026-10-17）**：工作流的全部动作是「装工具链 → `pnpm install --frozen-lockfile` → `make build`」，
  触发 = push `main` / 针对 `main` 的 PR / 每日 UTC 18:00 定时 / 手动。**不在工作流里列检查**是本条的硬约束——
  两处列检查就是两个事实来源，加检查改 Makefile 的 vet 块。口径随动的文档同批改完：
  AGENTS.md §3 与 §12、`docs/运维/构建与部署.md` 新增的 CI 段、`已知取舍`、`设计评审说明` 两处「无 CI」、
  `目录结构与模块边界` 的树、`踩坑判据` 里两句以"本仓无 CI"为前提的表述。
- **顺带修掉的坑（本机也在这族里，不是"只有 CI 会红"）**：
  `test/monitor_integration_test.go` 的今日分桶断言原本 `time.Now().Format(...)` 取**进程时区**的今天，
  而日标由服务端按平台时区打（`utils.DayStart` 是日界唯一处）——开发机的时区是 **UTC+0000**，
  平台偏移 +8，于是凡进程时刻落在 UTC 16:00–23:59（北京 00:00–07:59）那八小时，两个钟就不是同一个日历日，
  **在开发机上照样红**。取证不靠墙上时间的断言：FAIL 那行直接印出服务端标的 `day:2026-10-17`，
  而进程侧当日是 `2026-10-16`（同一刻 `date -u` 与 `TZ=Etc/GMT-8` 两个读数并列可复算）。
  **CI 里刻意不设 `TZ`**：钉上时区就等于把这一族差异重新藏回去——判据页「CI 会红、线上不会红」那族是它的镜像方向。
- **还开着的四处**：
  ① **pnpm 钉子有两处**：CI 钉 `10.33.0`（与开发机同版本，认 `web/pnpm-workspace.yaml` 的 `allowBuilds`），
    Dockerfile 里仍钉 `10.28.1`。收成一处的方式是给 `web/package.json` 加 `packageManager` 并让 corepack 与 CI 都读它——
    本轮没做，因为它要同时动 Dockerfile 与本地安装路径，而拍定的范围只到"骨架加一条工作流"。
  ② **首跑已红，第三跑定位到真因——坑本身已修**：三跑都在 `make vet` 那一步（62 s；`make web` 3 s 绿、`make test` skipped），
    而本地三种组合全绿（工作树 + go1.26.5、干净克隆 + 本机 1.27.2 全量、干净克隆 + go1.26.5）——差别只剩 runner 的系统工具。
    卡点在"日志读不到"：`GET /actions/runs/{id}/logs` 未认证 403（要仓库管理员权限）。
    于是给 CI 加了一条 `if: failure()` 的回显（把失败那一步的日志末尾 25 行发成 annotation，annotation 免鉴权可读），
    第三跑它就送来了真因：**`/bin/sh: Syntax error: "(" unexpected` → `Makefile:198 nav-check`**。
    根因是 `nav-check` 用了 bash 专有的进程替换 `<(...)`，而 **Makefile 从没声明 `SHELL`**，make 于是拿 `/bin/sh` 跑 recipe：
    Ubuntu 是 dash、解析不过；开发机的 `/bin/sh` 指向 bash，**所以这段静态门禁在本地"绿"了一年多，在别的机器上直接缺席**。
    修法是声明 `SHELL := /bin/bash`（与 `scripts/` 那 26 支脚本的 shebang 同口径），并给 `check-script-syntax.sh`
    加两半（断言声明位在 + recipe 行 `bash -n`），判据页与开发约定各落一条。**档位只到 `部分`**：
    这两半拦得住"忘声明"和"写坏 recipe"，**拦不住方言**（`<(...)` 在 bash 下合法），方言那一半靠 CI 这台非 bash-sh 的机器实跑。
  ③ **`viewport-check` 仍未被任何东西跑**：`scripts/run-viewport-probe.sh` 要浏览器与一份临时实例
    （假定 `~/.cache/ms-playwright` 或 `CHROME=<路径>`），所以没进 `make build`、也没进 CI。
    P65 那一族（共享件插槽的窄屏溢出）现在仍然靠人临时想起来量一次。出路是给一支单独的 workflow（**不做 PR 必过项**），
    别把它挂进 `make build`——那会把门禁变成等待。
  ④ dependabot 未开（建议只跟 `github-actions` 生态；npm/go 依赖的自动 PR 会和 §11「引入新依赖先确认许可证兼容」打架）。
