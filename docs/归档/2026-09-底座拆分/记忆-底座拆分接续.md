## 3. 已定决策（不要重开）

| 决策 | 结论 |
|---|---|
| 结合方式 | **fork 模板**：base 是可运行骨架，源项目在 base 上加包；不做 Go plugin，不做运行时分离 |
| 源的组织 | **单一 sources 仓库 + 同仓分支**（2026-09-30 简化定稿）：骨架 `main` 零源；`sources/private` 携带全部 6 源；公开版**不建长期分支**（2026-09-30 定）：需要发布时从 `sources/private` 拉临时分支，删 `sources/all.go` 里 fq_hg/xmly 两行 + `RETIRED_SOURCES` 追加这两源。原「两个 fork + `git subtree` 单向搬运」作废（宿主已是骨架仓库，subtree 不再必要）。`sources/` 内部仍要求「源包只依赖骨架声明位」，保证同一份源包在公开/私有两种裁剪下都能编译 |
| 源包目录 | **顶层 `sources/<源>`**（2026-09-30 定，`6cc34e3` 已落地）：导入清单 `sources/all.go`（package `sources`），`app.go` 只空白导入 `loomproxy/sources`；`handlers/common` 同期更名 `handlers/catalog`；**`handlers/` 此后专指控制面**。选它而非 `handlers/<源>` 的理由：fork 的受保护路径 allowlist 要按路径前缀做 diff，`sources/` 可执行，「handlers 下除控制面包之外」的否定式不可执行 |
| 号池归属 | **通用号池留在底座**（`base/pool` + `pool_devices` + `Provider` 接口 + `/admin/pools`），源只登记自己的池。比原方案的「源私有状态归 fork」更好，已采纳 |
| 面板扩展 | **不做前端插件化**：源私有运维页不进公开面板（原 xmly 号池页即反例） |
| 落地顺序 | 先解耦（A，已完成）→ base 成型（B）→ 数据源迁入（C，已完成并追平 skeleton-v2）→ D（私有 fork 与 subtree）**取消**：宿主即骨架仓库，公开版走临时分支裁剪 |
| 模块名 | **已执行**（`ec007d9`）：模块名 `loomproxy`。**产物名与部署链路仍是 `loomproxy-go`**——Makefile `BINARY`/`RELEASE_BINARY`、Dockerfile、`docker-compose.yml`、`deploy/loomproxy.service`、`scripts/deploy.sh` 的 `BIN=`、`.gitignore`、README 示例全部未动，动它们牵连线上路径 |
| 阶段 C 宿主与提交形态 | **在当前仓库开分支**（2026-09-30 定，方案 `阶段C-数据源迁入方案.md`）：`main` 永远是零接口骨架，源在 `sources/private` 分支上；loomproxy-go@dev 只作只读供体。**推送**：`main` 可推（公开基座），`sources/*` 暂不推、其源包不在公开许可覆盖范围内 |
| 项目定位 | **上游接口的代理与治理平台**：Legado 书源的字段归一化只是一种下游输出契约。别把它窄化成「小说书源聚合服务」——动作集与输出形状由接口包声明，底座不做书源特化分支 |
| 许可 | 骨架按 **AGPL-3.0** 发布（Copyright © 2026 syiism）+ `DISCLAIMER.md`；新依赖须与 AGPL 兼容；「LoomProxy」名称与标识不随许可授予；版权持有人保留另行授权的权利 |

## 4. 底座 ↔ 源的唯一契约：`base.SourceMeta`

源包 `init()` 里 `base.RegisterSource(...)` + `base.Register(...)`，再在 `sources/all.go` 加一行空白导入。
`app.go` 与 `db/seed.go` 永远不因新源而改——**出现需求就是契约缺位，补声明位而不是改底座**。

| 字段 | 语义 | 底座消费方 |
|---|---|---|
| `Code / Display / Category / Description / SortOrder / Status` | 数据源身份 | 路由对账、`data_sources` 播种、面板展示 |
| `Actions` | 动作集 | 路由对账、`quota_costs` 播种 |

## 4b. 装配层：中间件也是「清单 + 自注册」（`31f0c91`）

`middleware/middleware.go` 是注册表（叶子包，只依赖 gin）：`Def{Scope, Order, Applies, Build}` +
`Globals()/RouteChain()/RouteNames()/GlobalNames()/Build()/Describe()`；Order 常量集中在此
（全局 10..60、路由 100..600，留 100 间隙）。装载集合是 `middleware/all/all.go` 的空白导入清单
（transport / ipblock / apiauth / source / gate 五行）——**清单必须单独成包**：放 `middleware` 根包会成
`middleware → transport → middleware` 的导入环，这是它与 `sources/all.go` 唯一的形态差异。

分包：`transport`（requestid/recovery/logging/cors/cachecontrol）、`ipblock`（黑名单拦截 + 自动拉黑计数，
导出名现为 `ipblock.RecordFailure`）、`apiauth`、`source`（baseurl + monitor）、
`gate`（按轴拆 access/billing/ratelimit/plan/usage 五文件）。`app.go` 不再逐行拼链；
跨包的 `_resolved_baseUrl` 裸字符串契约已提为 `middleware.CtxResolvedBaseURL`。

fork 侧纪律：源专有逻辑优先用 `SourceMeta` 声明表达，不要加中间件包；确实需要新中间件就提回 base，
否则 merge 时 `middleware/all/all.go` 会冲突（它已进接缝清单，见 T1）。

## 7. 上手就会踩的坑（本仓特有）

- **模块名 ≠ 产物名**：`go.mod` 是 `loomproxy`，二进制仍是 `./loomproxy-go` / `./loomproxy-go-release`。
  看到两者不一致不要「顺手修正」，那是部署路径（AGENTS.md §2 已写明）。
- 源包在 `sources/<源>`，清单 `sources/all.go` 的 package 名是 `sources`；`handlers/` 下只剩控制面包
  （`catalog` 是原 `common`）。
- **中间件链的顺序改动必然弄红 `test/middleware_chain_test.go`**——那是设计意图（顺序从「注释里约定」
  变成「有断言钉住」），要改的是 `middleware/middleware.go` 的 Order 数字并说明理由，不要顺手改断言。
  同作用域 Order 撞车或重名会在 `Register` 期 `log.Fatalf`（宁启动失败不带病装配）。
- `middleware` 根包是叶子包：给它加子包或 `gate` 的导入直接成环。装载清单只在 `middleware/all/all.go`。
- **迁入源分支时的四个新坑**（详见 `阶段C-数据源迁入方案.md`）：
  ① 骨架与本仓**无共享 git 对象**，`git merge` 即全树 add/add——供体内容用 `git checkout donor/dev -- <路径>` 定向取，别 merge。
  ② `sources/<源>/internal/…` 这个目录名会切断 `test/` 的导入（Go internal 规则按父目录子树授权），必须改名（`protocol`/`api`）。
  ③ xmly 的 `app_key`/签名密钥**是上游协议的固定客户端标识**（所有客户端二进制同一对，非部署密钥）：
  迁入驻把它从 `conf/` 挪进 `sources/xmly/client` 作协议常量，env 仅作覆盖入口，不设 fail-closed 门槛、不需要轮换。
  dev 的问题只是位置错（让骨架 `conf/` 看起来感知了数据源），不是泄密。
  ④ 供体仍跟踪 `web/app.js`、`web/styles.css`（骨架 `c01ac75` 已删）——`git checkout donor/dev -- web/…` 是禁手。
- **merge main 之后必须补一个新的骨架基线 tag**（`skeleton-v1`→`skeleton-v2` 就是这么来的）：判据里的
  三点 diff 若仍指向旧 tag，main 自己的新骨架改动会被算成分支违规。AGENTS.md §0 与迁入方案都要同步换指向
  （当前 `skeleton-v3` = `2b5f68d`；历史 `skeleton-v2` = `6028c15`、`skeleton-v1` = `31f0c91`）。
- **`SourceMeta.MediaType` 源默认只适用于「一源一媒介」**，判据是**搜索阶段能否确定媒介**，不是解析函数的兜底分支。
  uxx 就是反例：搜索不支持按分类筛选、媒介只在详情可见（列表项 `kind` 是付费类型），填任何默认都会把误判固化
  ——它先被填成 `video`、随后撤回（`a9f3eb4`）。多形态源一律逐 tab 声明（fq_hg 五档）或留空，
  留空在媒介榜上是「未判定」空桶，属诚实状态而非缺陷。
- **`/data` 的文件列表按 category 目录取**（`handlers/catalog/datasource.go:174`），`SourceMeta.DataFiles` 只供「说明」列文案；
  `DATA_DIR` 同时被号池运行时状态使用（实测落点是 **`DATA_DIR/state.json`**，即 `data/state.json`——
  `sources/fq_hg/protocol/session.go:63` 用 `filepath.Join(stateDir, "state.json")`，`stateDir = conf.Config.DataDir`；
  此处原记 `data/fq_hg/state.json` 有误，2026-10-01 升级演练实测更正）。
  顶层文件不在任何 category 目录下，故不被 `/data` 列出；真正的暴露面是**旧 `data/fq/` 字典目录**：
  `fq_hg` 的 `Category` 同为 `fq`，残留文件会挂到新源名下并由免鉴权的 `/data/<分类>/<文件>.json` 直出
  （详见 ``docs/数据源/生产旧实例升级-2026-10.md`（在携带数据源的分支上，骨架仓库没有该页）` §4.4）。
- `make web` 必须先跑：`web/embed.go`（只 embed `dist/*`）在 `dist` 缺失时 `log.Fatal`。pytest 的 harness 会自动补占位文件。
- 集成测试**禁止 `t.Parallel()`**：`conf.Config`、`db.DB`、`utils.DefaultCache`、限流器、号池注册表都是进程级共享。
- `conf.Config` 是全局指针，测试直接赋值；`db.retiredSources()` 之类别依赖 `conf.Load()` 已被调用。
- **`/datasources` 自带 `{code,msg,data}` 信封，但 `/data*` 返回裸对象**（`app.go` 对 `data_files` 特判：
  返回 `[]byte` 时直接写响应体）。写用例时 `doJSON` 解析 `/data` 会拿到空 `data`——用 `doRaw`。
- gofmt 豁免清单在 Makefile `GOFMT_EXEMPT_RE`（存量未格式化文件），别顺手格式化它们。
- pnpm 构建白名单：`web/pnpm-workspace.yaml` 的 `allowBuilds.esbuild` 删了 `make web` 就挂。
- SQLite：`SetMaxOpenConns(1)` + WAL，测试用 `DB_TYPE=sqlite`，`conf.go` 代码默认却是 **mysql**（文档反复强调以代码为准）。
- 前端规范禁用 emoji/渐变/重阴影，标签一律 `UiTag`；系统设置新增 key 要加进 `Settings.vue` 的 GROUPS 或走兜底卡。
