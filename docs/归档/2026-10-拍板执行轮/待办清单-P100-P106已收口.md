## P100 白名单路由把「免强制」连「解析」一起免掉了：带合法 VIP 凭证请求 `/datasources`，拿到的是免费版视图【已处理·按 C 落地（新增路由声明位 `IdentityOptional`，一条管道走完，默认 false 不动现有行为）；手工 Build 的 `/endpoints` 一并补上；现网走不到这条（生产 `/datasources` 不在白名单），只由用例保证】

- **现象/证据**（`utils/auth.go` 的 `VerifyAuth`）：
  ```go
  path := c.Request.URL.Path
  if IsWhitelisted(path) {
      return nil            // ← 凭证一个字都不解析
  }
  ```
  同一函数里 `AuthEnabled=false` 那一支写的却是另一套（P64 那轮定的）：先 best-effort `resolveJWT`/`resolveAPIKey`，
  **解析成功就挂身份、失败按匿名放行**。于是白名单免的不只是**强制**，把**解析**也一起免了。
  实测（`test/datasources_cache_key_test.go` 的 `TestWhitelistedDatasourcesDropsIdentity`）：
  回收免费套餐对 `fake_b` 的授权、把用户挂到 vip 套餐之后，
  带**合法 VIP JWT** 请求白名单上的 `/datasources`，返回的仍是免费版那份列表（`fake_b` 不在里面）。
  同一条请求把 `/datasources` 移出白名单（`TestDatasourcesViewFollowsPlanWhenIdentityParsed`）就立刻正确。
- **为什么这不是"测试脚手架的事"**：`/datasources` 在**默认白名单里没有**（`AUTH_WHITELIST` 默认是 `/,/data,/auth/register,/auth/login,/panel`），
  现网默认配置下这条休眠。但文档里**明确建议**运维把它加进白名单来匿名分发清单（AGENTS §11、鉴权页那句
  「要匿名分发清单就把它加进 `AUTH_WHITELIST`——这是产品决策，现状是要鉴权」）。
  **谁照那句做，谁就在同一天让所有登录用户的 `/datasources` 退化成免费版视图**：VIP 看不见自己有权用的源，
  没有任何报错、没有任何日志——`/datasources` 的按套餐裁剪那一段代码从此是死代码。
  这条之所以归到"不会自己报错的错"：症状在另一个人的界面上（书源列表少了几项），而配置改动是三天前的一次运维手笔。
- **影响面**（同一个开关下还有谁受影响）：白名单是**前缀匹配**（`path == wl || strings.HasPrefix(path, wl+"/")`），
  所以 `AUTH_WHITELIST` 里任何一项盖住的路由都拿不到身份。现网默认那五项里 `/` 与 `/panel` 是静态面，本来不需要身份；
  真正会踩的是**后来被加进去的数据面/清单类路由**（`/datasources` 就是第一个）。
- **三个修法**（拍一个才动代码，§3b 停在执行门前）：
  | 选项 | 做法 | 代价 |
  |---|---|---|
  | A | 白名单分支改成 best-effort 解析（与 `AuthEnabled=false` 那一支同形，P64 的判据直接搬过来） | 语义最一致，但**所有**白名单请求都要多解一次凭证：`/panel/*` 是静态资源，浏览器每次加载带几十个子请求、每个都带 HttpOnly Cookie ⇒ 每个多一次 `db.ValidateSession` 查询（会话行是每请求的判定入口，不能省） |
  | B | 只改 `/datasources`：在 handler 里自己解析 | 违反 P26「不要在第二处再写一遍凭证解析顺序」；也修不到下一个被加进白名单的路由 |
  | **C（我的建议）** | **补声明位**：给路由一个「要身份但不强制」的声明（`base.Handler` 侧加一个可选位，或复用 `middleware.Spec.AuthRequired` 旁边加 `IdentityOptional`），`apiauth` 的 `Applies`/白名单分支按这个声明决定要不要 best-effort 解析 | 静态面不付那次查询；新增路由自己声明，默认行为不变（AGENTS §5 的「需要新行为优先补声明位而不是改骨架」）；代价是又一个声明位，得同时进 `docs/架构/处理器自注册与数据源声明位.md` |
  三个选项的共同点：**解析失败一律按匿名放行**（白名单的语义是不拦，这条不许变），
  且都不改变「白名单免强制」这句话本身——改的只是"免强制不免解析"。
- **随这条一起做的两件**（无论选哪个）：
  ① `docs/规范/../架构/鉴权模型与会话.md` 与 AGENTS §7 补一句：白名单免的是强制、不是解析（或按 C 的说法：按声明位）；
  ② 文档里那句「要匿名分发清单就加进 `AUTH_WHITELIST`」要加一句代价提示——现在的写法只说了收益。
- **已固化的部分**：`test/datasources_cache_key_test.go` 三条（身份被解析时视图按套餐裁剪 / 缓存键含 uid 的隔离 / P100 tripwire）。
  其中"缓存键含 uid"那条是**双重的**：把 `handlers/catalog/datasource.go` 里 `cleanParams["uid"] = userID` 删掉，用例当场红
  （变异验证过）——那行是 P84 那一族（键少一段维度）在这个 handler 里的现存防线，注释却两次写着"同套餐用户共享缓存"，
  **注释与代码相反**：下一个人照注释把它"简化"掉，就直接把 A 用户裁剪过的列表发给 B 用户。已顺手把那两句注释改成事实。
- **被它阻塞的条目**：无。**它依赖的条目**：P64（同一句判据的第一次落地）、P26（凭证解析只在一处）、P84（缓存键的维度）、
  P34（删限额行=回收，用例的前提）、§5 的声明位纪律（选项 C 的落点）。
- **答复后回写位置**：本条状态行 + `docs/架构/鉴权模型与会话.md` 的白名单段；选 C 则 `处理器自注册与数据源声明位.md` 补那一位，
  并把 `AGENTS.md` §5 的声明位清单加一行（**只一行**）。
- **落地记录（按 C，2026-10-06；维护者授权代拍）**：
  - **管道一条，没有新增第二处解析**：`base.BaseHandler.IdentityOptional`（新字段 + `PrefersIdentity()`，并进了 `Handler` 接口）
    → `middleware.Spec.IdentityOptional` → `middleware/apiauth` 的 `Build(s Spec)`（**它原来写着 `func(middleware.Spec)` 却把参数丢掉**，
    这一位正好是它第一次真正用上 spec）→ `utils.VerifyAuth(c, wantIdentity)`，白名单那一支由"什么都不做"改成
    "声明过就 best-effort 解析、失败仍匿名"。默认值 false，所以**现有端点行为一字未变**。
  - **比原建议多做的一处**：`/endpoints` 是 `app.go` 里手工 `middleware.Build("apiauth", middleware.Spec{})` 挂的，
    不走注册表那条填 Spec 的路——**空 Spec 等于没声明**，所以给它显式传了 `IdentityOptional: true`。
    这不是同类扩展，是这一族的**新形状**：手工 Build 的端点必须自己传位，将来再加第三条这类路由，忘了传就是 P100 复发。
  - **原回写清单里没执行的一条（偏离，理由写在这儿）**：`AGENTS.md` §5 那句声明位清单**没有加这一行**——
    那一行列的是 `SourceMeta` 的位（`Actions`/`FixedBaseURL`/`OnBoot`/`RequiredParams`…），
    而 `IdentityOptional` 是 `BaseHandler` 上的**路由声明位**（与 `Auth` 同族，那一族 AGENTS 从未逐个列过）。
    写进去等于把两处声明混成一处——那正是本条要防的"同一个概念两个落点"。
  - **用例**：`TestWhitelistedDatasourcesDropsIdentity` 原是 **tripwire**（它断言缺陷、并在消息里交代修好后怎么改），
    按它的交代改成 `TestWhitelistedDatasourcesStillParsesIdentity`，**两支各钉一个失效方向**：
    ① 带合法 VIP 凭证 → 按套餐裁剪；② 匿名 → 仍 200 且拿匿名那份。
    两次变异各拦一处：摘掉 `IdentityOptional` 声明 → ① 红；把白名单改成"要鉴权" → ② 红。
    ②那一支同时是**防断言空转的前提检查**（先确认匿名视图确实不含 `fake_b`）。
  - **文档**：`docs/架构/鉴权模型与会话.md` 开篇那句「白名单路径跳过」是这条缺陷在文档里的形状，已改成
    "跳过强制，不等于跳过解析"并写清未声明的端点拿不到身份是设计而非遗漏；
    判据页新增一条（同一形状第二次命中：P64 在 `AUTH_ENABLED` 那一支、本条在白名单那一支），
    档位 **`部分`**——机器拦不住"新端点需要身份却忘了声明"，等第三次再想扫描器。
  - **没验的**：现网 `AUTH_ENABLED=true` 且 `/datasources` **不在**默认白名单，所以这条在生产上今天走不到；
    正确性只有用例与这份读数保证，**发布后不要把它算成"现网验过"**。

## P106 单日额度的清零钟点可由本人切换（`day` 自然日 0 点 / `subscription` 注册钟点）——只移起算点，不动限额、不动窗口长度【已发布（2026-10-06 17:08:31 随 v87 上线，`3018672`）】

- **需求**（维护者 2026-10-06）：用户可手动切换额度刷新周期，默认自然日 0 点刷新，可切到"从订阅日起算刷新周期"。
- **三个岔口先拍后写**（问出来的，不是我替他默认的）：
  1. **周期长度**：仍是 **1 天**，只把清零的那一刻从 0 点挪到锚点钟点。**不**做成"从订阅日起算 30 天"——
     那会重开 P70「额度只有一个窗口：当日」，让 `quota_limits.period` 第一次被判定读（顺带把 P105 那笔账单变成
     "必须有个说话算的写方"），限额数字、监控当日读数、`/quota/dashboard` 全要重定义，还是一次生产 DDL。
  2. **锚点来源**：**`users.created_at` 的钟点**。库里从来没有"套餐绑定时刻"这一列（只有 `PlanExpireAt`，NULL=永久，
     且续期会往后推，不能反推订阅日）；在 24h 窗口下只有**钟点**有意义，注册时刻人人都有 ⇒ 零新列做锚点、零回填、无未定义分支。
  3. **谁能切**：**仅本人**，`POST /auth/quota-cycle`（只认会话，与 `/auth/privacy` 同一组理由——
     长期密钥不该能改本人的额度节奏；泄露时攻击者可以用它把当天用量"洗"掉一次）。
- **这个功能唯一的危险，以及为什么必须限频**：切换**不冲正任何流水、只移动起算点**，
  而起算点一旦后移，之前那段用量就不在窗口里了——`UsedToday` 正是按起算点求和的。
  不限频的话"来回切两次"等于每月无限次把当天额度清空一次，**而监控与流水看不出任何异常**。
  所以有 `users.quota_cycle_changed_at` + **30 天冷却**（`models.QuotaCycleSwitchInterval`，
  与「用户名每 30 天限改一次」同族），算法只在这一处：面板要显示"何时可再切"、端点要拒绝、用例要钉边界，三处必须同一个数。
  限频数字由 `/auth/me` 与 dashboard 随响应下发（`switch_allowed_at`），**面板不自己抄 30 天**（P70 那条做法）。
- **默认方向**：`quota_cycle_mode` 的列默认值是 **`day`**，且 `EffectiveQuotaCycleMode()` 把**空串归一成 `day`**——
  默认必须是旧行为而不是新行为（P85：默认方向一旦是新行为，升级本身就等于给所有人改了口径）。
  AutoMigrate 给存量行补的也是 `day`，所以**升级前后所有人一字不变**，不需要一次回填写库。
- **实现落点**（起算点的定义处仍然只有一处，P41 那条没被破坏）：
  `utils.DailyAnchorStart`（与 `DayStart` 同族，时区只在这里取一次）+ `utils.ClockHHMM`（钟点显示口径）；
  `gate.UsageSince` 的候选从两个变三个（自然日 / 锚点钟点 **二选一**，管理员刷新时刻在两种模式下都仍**压过**它们）；
  `handlers/quota/quota.go` 的 `nextResetTime(user)` 与根响应三格；`handlers/auth` 的写入口；
  面板 `Profile.vue` 新增「额度清零时间」一节（`computed` 判限频，失败把开关拨回服务端事实）。
  **一处被编译器教的边界**：锚点格式化本想写在 `models.User.Public()` 里，
  但 `utils/auth.go` 已经在用 `models` ⇒ `models → utils` 是环；钟点那一格改由读侧调 `utils.ClockHHMM`。
- **验证**：`test/quota_cycle_test.go` 四条（锚点保平台时区 + 退化情形等于 `DayStart(1)`；三种模式的起算点与
  "管理员刷新压过锚点"；切换后窗口仍 24h 且 `next_reset = 起算点 + 24h`；限频 + 重复提交不占名额）。
  **变异 7 次全红**：默认方向漂成 subscription / 起算点不读模式 / 去掉限频 / 管理员刷新被压过 /
  锚点未到不回推一轮 / 面板 next_reset 忽略模式 / 重复提交也判变更。
  **两处归因要写准**：第 7 次红在「重复提交返回 429」那一头，不是红在「时刻没被刷」那一头——
  断言确实咬住了同一个错误，但红的位置不同（同 S63 那次教训：红要在，红在哪也要说清）。
  **用例自己错过一条**：我先把"锚点还没到"写成"起算点应距现在接近 24h"，而正确性质是
  `now ∈ [起算点, 起算点+24h)`——锚点离现在越近，回推出来越短（03:33 时锚点 06:33 → 只差 21h）。红的是用例不是被测函数。
- **发布形状**：AutoMigrate 加两列（`quota_cycle_mode` 带默认、`quota_cycle_changed_at` 可空），
  **零回填、零手工 DDL**；`users` 是大表但 MySQL 8 对"带默认值的新列"是 instant。
  现网默认仍是 `day` ⇒ 发布本身不改变任何人的额度节奏，功能要等有人去个人中心切换。
- **依赖与关联**：P41（起算点唯一处，本条在它上面加候选而不是另开一处）、P70（窗口长度不变这条是它的守卫）、
  P105（如果哪天改成"30 天周期"，`period` 就必須有个真正写方——那一拍要看这条）、P52（只在有效值真变时盖时刻）、
  P85（默认方向）、P71（日界与钟点都归 utils 一处）、P90/P67（固定句对外 + 服务端有声）。
- **状态**：已发布——2026-10-06 17:08:31 随 v87 上线（`skeleton-v87`）；现网默认仍是 `day`，升级前后所有人的清零节奏一字未变，功能等用户在个人中心自行切换。
