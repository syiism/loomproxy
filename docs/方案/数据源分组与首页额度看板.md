# 数据源分组管理 + 首页额度看板改版

> 需求 P0-2（管理面板的分组管理）与 P0-3（首页布局参考 `buju.md`，在现有基础上改）。
> 状态：**已落地**（后端 `handlers/admin/source_groups.go` + 面板「分组管理」卡 + 首页分节筛选）。
> 两件事一起做是因为首页看板的分组维度正是前者的产出。
> 关联：拆分方案在携带数据源的分支上（`sources/private` 的 `docs/数据源/方案-数据源拆分-fq_hg五分.md`）——
> 拆完源数变多，「一眼看全」这件事就落到分组上。

## 1. 分组是什么、不是什么

**是**：管理员自建的**归类与筛选视图**（相当于给数据源打标签）——组名自由（音频 / 小说 / 视频 / 漫画 /
甚至「伤身体」），成员是数据源，一页能看完、一键能批量套用限额。

**不是**：计费键，也**不参与额度、计费、限速的解析**。2026-08-09 删掉的那个「平台组」正是死在这里——
它当时是 `quota_costs` / `quota_cost_plans` / `user_quota_overrides` 的 `group_code` 键，一个源的配置散在
组行与源行两处，最后靠 `LegacyGroups` 声明把存量组行展开成每源一行才收拾干净
（见 `docs/架构/管控-额度限流与监控.md`）。**本次分组不再充当任何键**：限额、成本、套餐关联、监控维度、
代理白名单、榜单白名单的键**一律仍是数据源码**，组只是「选中一批源」的入口。
「按组套用限额」因此只是**写入时的批量入口**，落库仍是每源一行 `quota_limits`，解析路径完全不知道组的存在
（回归用例 `TestApplyGroupLimitsWritesPerSourceRows` 钉住这一点：套用后不允许出现任何以组名为键的行）。

## 2. 数据模型

```
source_groups        id, name(unique), sort_order, status, description, created_at, updated_at, deleted_at
data_sources.group_id  nullable FK → source_groups.id（AutoMigrate 加列，存量行为 NULL=未分组）
```

- **一源至多一组**（`group_id`），不做多对多。理由：首页与批量套用都要「这批源」有唯一归属，
  多组会让「本组今日消耗」这类口径含糊；真需要交叉视图时用筛选解决，不加关系表。
- `group_id` 为 NULL 的源在首页落入「未分组」，仍然可见可用——**分组不是准入开关**，
  没分组不影响访问控制与计费。
- 删组时不删源：`group_id` 置回 NULL（后端在删除组的事务里一起做，避免留下指向已删组的孤儿引用）。
  组行本身**硬删**（`SourceGroup` 不带软删列）：留一行只会占住 `name` 唯一索引，让同名重建撞 409。
- `status=0`（停用）是纯展示开关：其成员在首页分节、筛选按钮与 `/datasources` 里都按**未分组**处理，
  源照常可见可用——分组从来不是准入开关，访问控制只认套餐关联。
- 组的显示顺序 = `source_groups.sort_order`，组内源顺序沿用 `data_sources.sort_order`。

## 3. 与媒介（`MediaType`）的关系

`MediaType` 是**源在协议层自述的事实**（由声明位与响应判定链得出，`docs/架构/弹性获取栈与环境变量.md`），
分组是**管理员的经营视图**。两者允许不一致（把红果短剧放进「小说」组是管理员的自由），但面板要在
源编辑处给一条**提示**（不是校验、不拦保存）：所选分组的名称与本源媒介不同名时提示「与声明媒介不一致」。
不把分组等同于媒介、也不自动按媒介建组——那等于把数据源知识塞回骨架的键设计里。

## 4. 后端端点（路由前缀统一 `/admin/data-sources`、`/admin/source-groups`）

| 端点 | 用途 |
|---|---|
| `GET /admin/source-groups` | 组列表（`groups[]` 带 `member_count`）+ `ungrouped_count` |
| `POST /admin/source-groups` · `PATCH /admin/source-groups/:id` · `DELETE /admin/source-groups/:id` | 组的增删改；改名/同名走 409 预检，删除时成员 `group_id` 置 NULL |
| `PUT /admin/source-groups/:id/members` | 整盘提交成员源码列表（列表即成员全集，未知源码 404 报错而不是静默丢弃） |
| `POST /admin/source-groups/:id/apply-limits` | 按组批量套用限额：`{plan_code, limit, period?}` → 逐源写 `quota_limits`（**存储仍是每源一行**） |
| 现有 `PATCH /admin/data-sources/:id` | 增加 `group_id`（归入）与 `clear_group`（摘出，二者互斥）|

- 消费侧输出补分组信息：`/quota/dashboard` 的源带 `group_id`/`group_name`，顶层另发 `groups[]`（含可见源计数）
  与 `ungrouped_count` 供筛选栏；`/datasources` 的条目带 `group_id`/`group`（下游可按组过滤，客户端不依赖也行）；
  `/admin/data-sources` 的行带 `group_id`，组名由面板从 `/admin/source-groups` 取（不为一个下拉框做联表）。
  `/rank/boards` 不带组（榜单按源）。它后来按待办清单 P3 加了 `media` 筛选——媒介本来就是明细列，
  与「不引入新的组维度」不冲突。
- 写操作要照现有约定失效缓存：组名会进 `/datasources`，所以组的增删改、改名、成员变更一律调
  `InvalidateDatasourcesCache()`（`/datasources` 与 `/data` 走 Redis 缓存，见 `docs/规范/已知取舍.md`）。
- 鉴权：全部在 `/admin/*` 下，后端 `AdminRequired()` 是唯一信任边界（前端路由守卫不算）。

## 5. 管理面板（`web/src/pages/admin/Datasources.vue`）

该页已有三块：数据源 CRUD、套餐-源关联矩阵、平台级 baseUrl 配置。新增第四块「**分组管理**」：

- 左侧组列表（可增、可改名、拖不动就用 `sort_order` 数字输入、可删），右侧成员勾选。
- 勾选即 `PUT /members`；每个源行显示 `DisplayName / code / 声明媒介 / 当前组`，与矩阵区共用语义。
- 「按组套用限额」按钮 → 弹窗选套餐 + 数值 → `POST /apply-limits`，成功后 toast 列出实际写了几行。
  这一条是「方便聚合管理」的落点：**批量入口在组，存储在源**。
- 分层照旧：`api/index.js` 加方法，页面不拼路径；组件一律用既有的 `UiTag/UiModal/UiField/…`，
  不写一次性样式（`docs/规范/开发约定.md`）。

## 6. 首页额度看板改版（`web/src/pages/Dashboard.vue`，参考 `buju.md`）

现有页面已经具备：`max-w-6xl` 容器、4 张统计卡（`grid-cols-2 lg:grid-cols-4`）、
窗头三点装饰的源卡、`有效总额/今日已用/今日剩余` 三列、进度条、`日额度`/`下次重置` 明细、
底部「调用流水」（管理员看全站、用户看自己，含空态）。所以**改版是补三样，不是重写**：

1. **筛选栏**：左侧分类按钮组（「全部 N」置首 + 各组 `组名 计数` + 未分组），当前项高亮；
   右侧搜索框。计数为 0 的组不显示按钮（「全部」始终显示）。移动端按钮组横向滚动。
2. **分组列表**：把现在的一张平铺网格改成「按组分节」——组标题行（组名 + 平台数 + 分隔线），
   组内响应式 1/2/3 列卡片网格。卡片本身沿用现有结构与样式。
   **一个组都没建时保持平铺**（骨架新装即此形态，不给空库凭空加一节「未分组」标题）。
3. **页头**：左侧标题 + 副标题（现有）；右侧补一个套餐标签（现有 `planExpireAt` 到期文案保留，
   旁边加 `plan_name` 的 `UiTag`，管理员不加）。

另外两处必须处理：

- **卡头组名当前是空的**：模板里 `{{ s.group }}` 与 `:key="s.group"` 引用的字段
  在 `/quota/dashboard` 的 `DashboardSource` 里并不存在（真实字段是 `source_code`），
  所以现在窗头条只渲染出空白、且卡片 key 重复（已记 `docs/规范/待办清单.md` P11）。
  改版顺手改：窗头条显示 `source_code`，卡片 key 用 `source_code`。
- **搜索匹配**：按「显示名 / 源码 / 组名」小写包含匹配。**不引拼音依赖**（新增依赖要过 AGPL 兼容评估，
  为一个筛选框不值当），也**不加 `search_words` 别名列**（G4 定稿：一列 + 一个输入框的成本换来的是
  「管理员得记得填」，而拼音/错别字场景由组名与显示名覆盖已够用）。

统计卡口径保持两种：普通用户 = `平台数 / 今日总额度 / 今日已用 / 今日剩余`（`buju.md` 的四张），
管理员 = 现有 `平台数 / 今日全站消耗 / 今日活跃用户 / 今日调用次数`。不合并——管理员要的是全站观感。

**已知坑必须避开**：`reveal` 默认 `opacity:0`，`revealObserve()` 只观察**调用那一刻已存在**的节点。
筛选/搜索会重排 DOM，所以「先 `loading=false`、再 `nextTick(revealObserve)`」，并且筛选变化后要再
`nextTick(revealObserve)`，否则会出现数据在、整块不可见（`Ranking.vue` 初版就是这么翻车的，
见 `docs/规范/开发约定.md`）。

## 7. 验收

1. 建组 → 改名 → 加成员 → 删组：源不丢、`group_id` 正确回落 NULL；`/datasources` 缓存立刻反映变化。
2. 按组套用限额后，`quota_limits` 是**每源一行**，`GET /quota/dashboard` 的 `effective_total` 随之变化；
   单源覆盖（`user_quota_overrides`）仍是「套餐限额 + 覆盖值」的追加语义，不受分组影响。
3. 首页：分组分节渲染、组按钮筛选、搜索命中「名/源码/组名/别名」；普通用户与管理员两套统计卡都对；
   空组、无权限源（未进套餐）不报错；移动端不破版；`reveal` 在筛选后仍然出场。
4. 黑盒用例进 `test/`：分组 CRUD 与成员整盘提交、`apply-limits` 只写源行、未分组源的可见性、
   `/quota/dashboard` 输出带组信息。集成用例禁 `t.Parallel()`。
5. `make build` 全绿并连同文档一起提交（本方案页 + AGENTS 的分组条目）。

## 8. 定稿的五个口径（2026-10-01 拍板）

- **G1 一源一组**（`data_sources.group_id`）。中途考虑过「组=标签、一源多组」（因为组既然不参与任何键控，
  多组不会污染口径），最终仍按一组收口：首页分节与批量套用都需要「这批源」有唯一归属，多组会让
  「本组今日消耗」这类读法含糊，还要多养一张关系表。真需要交叉视图时用搜索与筛选解决。
- **G2 不写覆盖日志**：`apply-limits` 只记一条服务端日志（组/套餐/值/涉及的源），可回滚靠限额页逐行看。
- **G3 首页不按组折叠**，靠筛选按钮。
- **G4 不做 `search_words` 别名列**，搜索匹配「显示名 / 源码 / 组名」。
- **G5 组参与下游 `/datasources` 输出**（`group_id`/`group`），客户端可用可不用。
