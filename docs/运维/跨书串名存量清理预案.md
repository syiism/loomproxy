# 跨书串名的存量清理（待办清单 P84 的 ② 已拍 B）——**已执行 2026-10-06（hk）**

> 状态：**已执行**（维护者本轮授权「清 912 行存量」；以当日真数 1285 行落地）。
> 本页只做四件事：口径、执行前的只读核对、备份与回滚、执行后的验收。

## 1. 要清的是哪些行（口径必须能复算）

机制侧的修法已上线（`base.chapterIdentKey(source, bookIdent, ident)` 三段键，`5281085`）。
**存量**里还留着"跨书借来的章名"，判定条件三条，缺一不可：

| 条件 | 含义 | 出处 |
|---|---|---|
| `action = 'content'` | 章名只可能由正文调用写下 | §9「书名榜与章节榜只统计 `action='content'`」 |
| `(source, chapter_ident)` 在表里**对应 ≥2 个不同 `book_ident`** | 这一组就是"章号只书内唯一"的撞键组 | P84 现网实测 123 组 |
| `chapter_title <> ''` | 只清"已经写着名字"的行——空行本来就没被骗 | P84 读数：这 912 行**全部已带 title** |

**刻意不包括**的两类，写下来是为了防止有人"顺手扩大范围"：
- `book_ident = ''` 的行：回填对它们整条不做（键少一段就没法补），清了等于永久留空；
  现网这 912 行里 `book_ident` 为空的 **0 个**，所以不需要这条豁免，但**口径里保留它**（P84 的"另一半读数"）。
- `book_name` 串名的行：书名的键本来就只有 `source|书标识` 两段、全局唯一，**不存在这一族**。

## 2. 执行前只读核对（四条，逐条把数抄进本页末尾的读数表）

```sql
-- ① 撞键组数（现网历史读数 123；今天应当持平或更少）
SELECT COUNT(*) AS groups FROM (
  SELECT source, chapter_ident FROM api_call_logs
  WHERE action='content' AND chapter_ident <> '' AND book_ident <> ''
  GROUP BY source, chapter_ident HAVING COUNT(DISTINCT book_ident) > 1
) g;

-- ② 待清行数（现网历史读数 912）
SELECT COUNT(*) AS doomed FROM api_call_logs l
JOIN (SELECT source, chapter_ident FROM api_call_logs
      WHERE action='content' AND chapter_ident <> '' AND book_ident <> ''
      GROUP BY source, chapter_ident HAVING COUNT(DISTINCT book_ident) > 1) d
  ON d.source=l.source AND d.chapter_ident=l.chapter_ident
WHERE l.action='content' AND l.chapter_title <> '' AND l.book_ident <> '';

-- ③ 这批行的时间跨度：决定"清空之后还能不能自动补回来"（见 §5）
SELECT MIN(created_at) AS oldest, MAX(created_at) AS newest FROM api_call_logs l
JOIN (SELECT source, chapter_ident FROM api_call_logs
      WHERE action='content' AND chapter_ident <> '' AND book_ident <> ''
      GROUP BY source, chapter_ident HAVING COUNT(DISTINCT book_ident) > 1) d
  ON d.source=l.source AND d.chapter_ident=l.chapter_ident
WHERE l.action='content' AND l.chapter_title <> '' AND l.book_ident <> '';

-- ④ 抽样 20 行（人工看一眼"这些确实是同一标识挂在不同书上"再动手）
SELECT l.id, l.source, l.book_ident, l.chapter_ident, l.chapter_title, l.created_at
FROM api_call_logs l
JOIN (SELECT source, chapter_ident FROM api_call_logs
      WHERE action='content' AND chapter_ident <> '' AND book_ident <> ''
      GROUP BY source, chapter_ident HAVING COUNT(DISTINCT book_ident) > 1) d
  ON d.source=l.source AND d.chapter_ident=l.chapter_ident
WHERE l.action='content' AND l.chapter_title <> '' AND l.book_ident <> ''
ORDER BY RAND() LIMIT 20;
```

**列名以 `models/api_call_log.go` 为准**：`source` / `action` / `chapter_title` / `chapter_ident` / `book_ident` / `created_at`
（GORM 的驼峰字段映射成蛇形列；**不要照着别名猜**——S60 那条体检表就是因为猜列名写坏了半张表）。
`api_call_logs` 没有软删列，所以不涉及 `deleted_at` 豁免。

**这四条 SQL 有钉子**：`test/p84_predicate_test.go` 在真实 schema 上按夹具造了六组形状
（真撞键、同书重名、单书、空章节标识、非 content 动作、空 `book_ident`），断言组数=2、待清=4，
两次变异（放宽 `chapter_title <> ''` 与去掉 `HAVING`）各红一处。
它跑在 SQLite 上（集成测试没有 MySQL），**能证明的是列名与谓词形状，不能证明方言**——
唯一方言相关的抽样那条 `ORDER BY RAND()`（SQLite 是 `RANDOM()`）不参与执行，所以留着 MySQL 写法。

## 3. 备份（写之前必须过这两道）

```bash
# 只导这批行：--where 与 §2② 的谓词同形（MySQL 的 --where 不能带 JOIN，所以退化成
# "撞键组的全部行"——比待清集合略大，宁可多备不可少备，这条差别写在这里而不是藏起来）
mysqldump --single-transaction --no-create-info --skip-add-locks \
  --where="action='content' AND chapter_title<>'' AND book_ident<>'' AND chapter_ident IN \
  (SELECT chapter_ident FROM (SELECT c.source,c.chapter_ident FROM api_call_logs c \
     JOIN api_call_logs d ON d.source=c.source AND d.chapter_ident=c.chapter_ident \
     WHERE c.action='content' GROUP BY c.source,c.chapter_ident HAVING COUNT(DISTINCT c.book_ident)>1) x)" \
  loomproxy api_call_logs | gzip > api_call_logs-p84-$(date +%Y%m%d-%H%M%S).sql.gz

gzip -t api_call_logs-p84-*.sql.gz && ls -l api_call_logs-p84-*.sql.gz   # 两道都过才继续
```

- **先验 `gzip -t`、再验字节数非空**（判据页「空备份比没备份更危险」那条）。
- 备份是**行级 INSERT 集合**，因此它只能走 §6 的回滚路径（临时表 + JOIN 回写），
  **不能直接 `mysql <` 灌回主表**——主键会撞。这一句是本页最容易踩的空子，写在备份旁边而不是回滚那节。

## 4. 执行（一条 UPDATE，等授权）

```sql
UPDATE api_call_logs l
JOIN (SELECT source, chapter_ident FROM api_call_logs
      WHERE action='content' AND chapter_ident <> '' AND book_ident <> ''
      GROUP BY source, chapter_ident HAVING COUNT(DISTINCT book_ident) > 1) d
  ON d.source=l.source AND d.chapter_ident=l.chapter_ident
SET l.chapter_title=''
WHERE l.action='content' AND l.chapter_title <> '' AND l.book_ident <> '';
```

- 期望 `RowsAffected` **等于 §2② 数出来的行数**；不等就停下来核对，别重试。
- **912 行一批做完**，不分批：单批上限是回填侧的 `BackfillScanCap=5000`，比这大批次大得多，
  而这里根本没有循环可分批（P84 的条目要求记"列宽与批次"，答案就是：列宽 `size:255` 不涉及，批次 1）。
- 清的是**展示读数**，不是判定输入：`chapter_title` 没有任何判定读它（判定读 `status`/`in_band_error`/
  `quota_usage_logs`），所以中途失败不会让某个人的额度或授权处在半敞状态——**这是这条 UPDATE 敢单发的理由**，
  也是 §10「这张表是谁的读对象」那条判据的正面用法。

## 5. 执行后的验收（三件事，缺一条就不算做完）

1. **空行数对得上**：`SELECT COUNT(*) … WHERE chapter_title='' AND <同 §2② 谓词>` = §4 的 `RowsAffected`。
2. **自动回填能不能补回来，取决于 §2③ 的时间跨度**：回填循环的窗口是
   `created_at >= utils.DayStart(BackfillDefaultDays)`，**默认 30 天**（`handlers/admin/monitor_backfill.go`）。
   - 这批行**都在 30 天内** → 一轮回填（`MONITOR_BACKFILL_SEC` 默认 900 秒）后应重新出现章名，
     而且**同一 `chapter_ident` 在不同 `book_ident` 下名字不同**——这才是"串名被治好"的证据；
   - 有行**早于 30 天** → 它们**不会自动补**，需要手动跑一轮回填入口：
     `POST /admin/monitor/backfill-subjects?days=90`（上限 `BackfillMaxDays=90`）。
     **超过 90 天的行补不回来，就让它空着**——这是 P84 的原话「面板老实说不知道」，不是故障。
     所以 §2③ 那个 `oldest` 是**决定验收口径的数**，必须在动手前抄下来。
3. **补不回也不许猜**：回填的更新条件带 `AND (chapter_title IS NULL OR chapter_title='')`，
   所以循环幂等、可反复跑，且**不会覆盖已经有的名字**。看到"大片空"不要手动去填 SQL。

## 6. 回滚

**先问一句要不要回滚**：回滚等于把**已知是错的**标题写回去。它只在一种情况下该用——
执行后发现谓词写错、误伤了 `book_ident=''` 或 `action<>'content'` 的行。

```sql
-- 把 §3 的备份灌进一张同名结构的临时表，再按主键 JOIN 回写（不碰没被清的行）
CREATE TABLE api_call_logs_p84_restore LIKE api_call_logs;
-- 导入备份（INSERT 语句，主键在这张空表上不冲突）
mysql loomproxy < api_call_logs_p84.sql          -- 解压后的那份
UPDATE api_call_logs l JOIN api_call_logs_p84_restore r ON r.id=l.id
  SET l.chapter_title=r.chapter_title;
DROP TABLE api_call_logs_p84_restore;
```

回滚后必须重跑 §5 的第 1 条核对（行数应回到 §2② 的原值），并把临时表删掉——
**留一张带用户阅读数据的表在库里，属 §11 的泄露面**，不是"占点空间"。

## 7. 与其他动作的边界

- **不与 v83 混批**：S60（`docs/数据源/待办清单.md`）写得很清楚——混在一起出事分不清是哪一步造成的。
- **不含 DDL**：这一条只 UPDATE 一列的值；`content_consent_set_at` 那处加列是 P52，走 AutoMigrate。
- **不动缓存**：清空明细列与命名缓存无关（缓存是「标识→名称」，它的键已按三段重建）。
- **不留名单在仓库**：本页与执行记录只写**行数、时间跨度、口径**；抽样 20 行的结果**不提交**（§11）。
