# 构建、部署与生命周期

> 本页由 `AGENTS.md` §3 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

```bash
make build   # 前端 pnpm build → go vet + gofmt → go test -race → 编译
             # 产出调试版 ./loomproxy-go（~51MB）与正式版 ./loomproxy-go-release（strip，~35MB，部署用）
make web     # 仅构建前端（必须先于 go build：embed.go 在 dist 缺失时 log.Fatal）
make test    # go test ./test/ -race -count=1
make vet     # go vet ./... + gofmt 检查（豁免存量文件，见 Makefile 注释）
             # + 手写 SQL 扫描：别名撞 MySQL 8.0 保留字、反引号标识符（scripts/check-sql-reserved.sh；
             #   别名表是本地 MySQL 8.0.43 逐词实测的，故意不抄文档；对照组行尾标 dialect-allow 放行）
make run     # build 后启动，默认监听 0.0.0.0:8081

# pnpm 11 需要构建脚本白名单：web/pnpm-workspace.yaml 的 allowBuilds.esbuild 勿删，否则 make web 失败
```

**部署**：

```bash
sudo scripts/deploy.sh            # systemd 模式：构建→备份→切换→冒烟→失败回滚（/opt/loomproxy）
scripts/deploy.sh --local         # 原地模式（免 systemd）；--skip-tests 紧急发版
docker build -t loomproxy-go .    # 多阶段：node 建前端 → golang CGO 编译 → bookworm-slim 运行
docker compose up -d --build      # .env 注入 + ./data 绑定挂载
```

运行所需最小部署单元：**二进制 + 同目录 `.env` + `data/` 目录**。
`DB_TYPE=sqlite` 时库文件路径是 `filepath.Join(DATA_DIR, DB_NAME+".db")`——`DB_NAME` 是**不带扩展名的文件名**，
往里写绝对路径不是「覆盖默认位置」而是拼出一个不存在的目录（曾因此启动失败）。配置加载顺序：进程环境变量 > 工作目录 `.env` > 可执行文件目录 `.env`（`.env` 不覆盖已存在的环境变量）。

**手工换装（不走 `scripts/deploy.sh` 时）三查**——脚本没跑到的路径，纪律不能一起省掉：

1. **备份先验非空再算存在**：`cp -p` 出来的二进制备份要比大小或看 md5 与换装前一致；
   数据库 dump 必须验字节数。真实教训：一次 `mysqldump --where` 因 `LOCK TABLES` 报错，
   留下一个 **861 字节的空 gz**——**一份冒充备份的文件比没有备份更危险**。
2. **scp 后先核远端 md5，一致才 `install`**：大文件（~35MB）走窄链路会被截断，
   实测见过传到一半停在 25MB、以及远端 md5 与本地不同的两轮。顺序是
   `scp → ssh md5sum → 比对 → install → restart`，不能合并成一条 `install && restart` 赌它传完了。
3. **重启后核对启动日志的关键行**，不是只看 `is-active`：单元 `Restart=always` 会把崩溃循环伪装成「运行中」。
   要按各自的启动契约点名核对（本部署：名称回填循环那行、各号池的 `init done`、`error/panic` 计数为 0，
   以及**连不上库时服务拒绝启动**——`db.Init` 失败现在是 `log.Fatalf`，第一行应是
   「数据库初始化失败，服务拒绝启动: …」而不是一串 gorm 空指针栈，见待办清单 P27），
   并区分「正常的重启」与「挂了的重启」——`NRestarts=0` + 日志里有 `Shutting down server...` 是人为/系统级重启，
   没有则是崩溃。内核升级等主机构件事会顺着把服务带下去，别把它当成本轮发布的回归。

入口与生命周期：`main.go`（监听 SIGINT/SIGTERM）→ `app.Run(ctx)`（`conf.Load()` → `db.Init()` → 构建 gin 引擎 → HTTP 服务，5 秒优雅停机 → `lifecycle.RunCleanups()`）。
