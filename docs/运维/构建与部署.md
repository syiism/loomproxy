# 构建、部署与生命周期

> 本页由 `AGENTS.md` §3 拆出（2026-10-01 文档瘦身）。AGENTS 只留条目与一句话总结，细节以本页为准；
> 代码永远是最终事实来源，与本页冲突时以代码为准并回来更新本页。

```bash
make build   # 前端 pnpm build → go vet + gofmt → go test -race → 编译
             # 产出调试版 ./loomproxy-go（~51MB）与正式版 ./loomproxy-go-release（strip，~35MB，部署用）
make web     # 仅构建前端（必须先于 go build：embed.go 在 dist 缺失时 log.Fatal）
make test    # go test ./... -race -count=1 -timeout 20m
             #   跑 **全部包**而不是只跑 ./test/：包内单测（源包的向量对拍、解析层用例）不被门禁跑到
             #   就等于没有——分支侧 S30 记的盲区是「变异验证没还原就提交，而 make build 全绿」，
             #   因为会红的那条只在 `go test ./sources/...` 里，旧门禁看不见它
make vet     # go vet ./... + gofmt 检查（豁免存量文件，见 Makefile 注释）
             # + 手写 SQL 扫描：别名撞 MySQL 8.0 保留字、反引号标识符（scripts/check-sql-reserved.sh；
             #   别名表是本地 MySQL 8.0.43 逐词实测的，故意不抄文档；对照组行尾标 dialect-allow 放行）
             # + 待办清单与归档的一致性（scripts/check-todo-status.sh；`make vet` 现有 18 个检查目标、`scripts` 下 16 个 check-*.sh；2026-10-07 加 `goroutine-guard-check`（待办清单 P103③）后现测；**这两个数会随门禁增减漂，改这一句的人要重新数，不要抄上一版的**）：
             #   同一条目不得在清单页与归档页**两处都留整条正文**；清单页引用的归档页必须存在
             #   （按链接目标查 `docs/归档/**` 全树，不按某个固定文件名查）。
             #   「状态行含待拍而正文含已处理」那半句**刻意不判**——本仓合法状态行大量长那样，那是语义活）
make run     # build 后启动，默认监听 0.0.0.0:8081

# pnpm 11 需要构建脚本白名单：web/pnpm-workspace.yaml 的 allowBuilds.esbuild 勿删，否则 make web 失败
```

**部署**：

```bash
sudo scripts/deploy.sh            # systemd 模式：构建→备份→切换→冒烟→失败回滚（/opt/loomproxy）
scripts/deploy.sh --local         # 原地模式（免 systemd）；--skip-tests 紧急发版
docker build -t loomproxy-go .    # 多阶段：node 建前端 → golang CGO 编译 → bookworm-slim 运行
docker compose up -d --build      # .env 注入 + ./data 绑定挂载
```

运行所需最小部署单元：**二进制 + 同目录 `.env` + `data/` 目录**。
`DB_TYPE=sqlite` 时库文件路径是 `filepath.Join(DATA_DIR, DB_NAME+".db")`——`DB_NAME` 是**不带扩展名的文件名**，
往里写绝对路径不是「覆盖默认位置」而是拼出一个不存在的目录（曾因此启动失败）。配置加载顺序：进程环境变量 > 工作目录 `.env` > 可执行文件目录 `.env`（`.env` 不覆盖已存在的环境变量）。

**换装三查**——脚本没跑到的路径，纪律不能一起省掉：

1. **备份先验非空再算存在**：`cp -p` 出来的二进制备份要比大小或看 md5 与换装前一致；
   数据库 dump 必须验字节数。真实教训：一次 `mysqldump --where` 因 `LOCK TABLES` 报错，
   留下一个 **861 字节的空 gz**——**一份冒充备份的文件比没有备份更危险**。
1b. **旧备份只留最近一颗**（维护者 2026-10-07 定的口径，同日清过一次：44 颗 / 1557.6 MB）。
   保留的那一颗必须是**本次换装前的线上文件**且 md5 复算过——它唯一的用途是把上一条命令回滚到"我知道能跑的那颗"。
   两条执行侧的规矩：**`.env.bak-*` 不在候选里**（配置备份是另一条时间线，跟着发布清掉会把人自己的 undo 拿走）；
   **清理动作放在新产物起来、契约行核过之后**，而不是换装之前——先把唯一的退路删了再去做一件可能失败的事，
   顺序反了就没有反悔的余地。
2a. **脚本侧已经把第 2 条做进代码了**（待办清单 P79）：`scripts/deploy.sh` 的 `place()` 是
   「同目录临时名 → `mv -f` → 对**目标**复算 md5 → 不一致就不重启」，安装与回滚两路都走它。
2b. **构建段的门禁现在与 `make build` 同口径**（待办清单 P102，维护者 2026-10-06 拍定 A）：
   `deploy.sh` 跑的是 `make vet && make test`——以前那句写的是 `go vet ./... && go test ./test/`，
   **少了 15 道扫描检查、少了 `-race`、也少了包内单测**。这一族不是假想：同一条违例（报告里写错清单页行数）
   在旧链上第一步 exit 0、直接往下走去安装，在新链上停在 `doc-numbers-check`。
   **两条路径口径不一致时，实际门禁是走的那条**，文档里写的那条只是愿望；`--skip-tests` 现在跳的是整串门禁。
   为什么必须 rename 而不是 `install`/`cp` 直写：后者是打开活路径逐字节写，写完之前那条路径上
   是一个既非旧版也非新版的文件，而 `Restart=always` 随时可能把它拿来 exec——现网 14 天里三次
   崩溃循环都是这个形状（09-28 是 `203/EXEC`、10-01 与 10-04 是 `SIGSEGV` 且**没有任何应用日志**）。
   这条已由 `make vet` 的 `deploy-atomic-check` 看着：活路径被当成交付目的地就红。
2. **核 md5 与 `install` 必须在同一条远端命令里，装完再复算目标文件**：大文件（~35MB）走窄链路会被截断，
   实测见过传到一半停在 25MB、以及远端 md5 与本地不同的两轮。顺序是
   `scp →（等传输进程真的结束）→ md5sum 源; install; md5sum 目标`，**不能拆成两次 ssh 各赌一半**：
   分开核对的读数属于「那一刻的文件」，而那一刻它可能还在被写入——`scp` 被超时移到后台时，
   它自己的输出里最后那段本地 `md5sum` 是**不需要网络**的，先写完、看起来像已完成，其实远端才传了一半
   （2026-10-04 v62 换装就装上了 60% 的文件，崩溃循环 79 秒，见踩坑判据）。
   本地 / 远端源 / 远端目标**三方一致**才算装上。
   同一条纪律适用于**下发类产物**（书源 JSON、静态托管文件）：它们从磁盘读、不随二进制走，
   要单独占一步——装到生产目录、复算目标 md5、`curl` 一次下发端点确认吐出来的就是这一份；
   而且**先装产物、后改配置**（`.env` 里的下架名单之类），反了就会有一段「配置已生效、产物还指着旧世界」的窗口。
   **新增一个数据源 = 同时下发它的 `data/<源>/*.json`**：字典是**部署产物**，而「二进制 + `.env` + `data/`」
   这个单元里没有任何一步保证新源的字典被放进去——七猫三源的 `data/qm/` 就是这么从上线起空着，
   发现页一片空列表而监控里全是 200（待办清单 P51、分支侧 S39）。
   现在启动期有一道兜底：`CheckDeclaredDataFiles()` 会按各源 `DataFiles` 声明逐条打 ERROR 点名缺哪个文件
   （挂在 `app.Run` 的 `base.RunSourceBoots()` 之后，不阻断启动）。
   **但它只看"声明过的"**——没人声明却仍被请求的路径（旧导入客户端要的已下架字典就是这一类）
   在启动那一刻不在名单里，只有人来要的时候才显形；这一半由 `handlers/catalog/misslog.go` 补：
   请求打中一个不在位的文件时，服务端自己出一条**节流过的** ERROR，并分两类数
   （`有源声明`=产物没装 / `无声明`=有人在要不存在的东西），进程级累计数走 `catalog.DataFileMissTotals()`。
   **响应一字未改**：缺文件仍然回 200 + `{"error": …, "available": […]}`（不是标准信封，没有 `code` 字段），
   因为"要不要改 404"是下游可见变更、还没拍（待办清单 P51②）。
   **`curl` 的判据是正文而不是状态码**：看状态码会把「产物没到位」读成「一切正常」——
   S39 的根因误判就出在这半句上。
3. **重启后核对启动日志的关键行**，不是只看 `is-active`：单元 `Restart=always` 会把崩溃循环伪装成「运行中」。
   要按各自的启动契约点名核对（本部署：名称回填循环那行、各号池的 `init done`、`error/panic` 计数为 0，
   以及**连不上库时服务拒绝启动**——`db.Init` 失败现在是 `log.Fatalf`，第一行应是
   「数据库初始化失败，服务拒绝启动: …」而不是一串 gorm 空指针栈，见待办清单 P27），
   并区分「正常的重启」与「挂了的重启」——`NRestarts=0` + 日志里有 `Shutting down server...` 是人为/系统级重启，
   没有则是崩溃。内核升级等主机构件事会顺着把服务带下去，别把它当成本轮发布的回归。

4. **tag 也算产物：推过要按远端复算**。今天被自己抓到一次——我给私有远端推了 `skeleton-v93`，
   随后在报告里写成"tag 已推"（依据是 AGENTS §12 那句"骨架 tag 可由维护者推送"和"上次推过"的惯例），
   实际 gitee/github 上根本没有 v93，公开侧的 tag 链从 v92 直接跳到 v94。
   判据：`git ls-remote --tags <每个远端> refs/tags/skeleton-vNN` **逐远端列一遍**，
   而不是"我推过"；三个地方（本地 / 公开 / 私有）指向同一个 tag 对象才算齐。
   这一条已固化成 **`make tag-sync-check`**（`scripts/check-tag-sync.sh`）——它**刻意不在 `make build` 里**：
   每次构建发三次网络请求，离线或远端抖动就假红，而假红的门禁第二次就被无视。
   **两个坑写进脚本头部**：一个 remote 可能配**多个 push URL**（本仓的 `origin` 同时推 gitee 与 github，
   而 `ls-remote <remote>` 问的是 fetch 那一个——只按 remote 名就漏核一个公开侧），
   以及比短码会自己骗自己（本地 `--short` 给 7 位、远端 8 位，第一次复算就差点把"一致"读成"不一致"）。
   首跑顺手把历史底子抖出来了：**v1~v53 从没推过任何远端**，v54~v85 只进过 gitee
   （github 还缺 v56/v74/v75/v76/v77），三处齐全是从 v86 才成立的——所以脚本默认只核 v86 起，
   起点与依据写在里面，而不是让它开场报 85 颗红。
   同一个形状在换装那一节已经写过一次（"后台传输没收到完成通知就不算传完"）——
   **凡是"发出去了"这类断言，复算的都是对端，不是本机。**

入口与生命周期：`main.go`（监听 SIGINT/SIGTERM）→ `app.Run(ctx)`（`conf.Load()` → `db.Init()` → 构建 gin 引擎 → HTTP 服务，5 秒优雅停机 → `lifecycle.RunCleanups()`）。

**面板引用的「站点根静态文件」是第四件部署产物**（待办清单 P107，2026-10-07 我先把它误判成仓库缺陷）：
`web/index.html` 里那行 `<link rel="icon" href="/favicon.svg">` 走的是**绝对站点根**，而面板挂在 `/panel/` 下、
`web/dist/` 里也没有这个文件——**这是刻意的设计，不是漏放**：这类文件由**前端服务器**（本机 nginx，
见 `docs/规范/开发约定.md` 的「可信代理」条）在站点根提供，**替换图标只要往根目录放一份，
不需要重新构建前端、不需要动二进制、不需要发布**。三条推论：
① 看到 `/favicon.svg` 在**本机裸实例**上报 404 **不等于缺陷**——那台实例前面没有 nginx；
② 动任何"面板里的绝对路径引用"之前先问一句**它是不是部署侧提供的**（我就是没问这一句，
才动手把 `href` 改成 `%BASE_URL%favicon.svg` 并往 `web/public/` 塞图，那会把这个约定改掉；已撤回）；
③ 反面代价是**它不随 `make build` 走**：换图之后要单独核一次
   `curl -o /dev/null -w '%{http_code}' https://<现网域名>/favicon.svg`，光看二进制与 dist 是核不到它的。
